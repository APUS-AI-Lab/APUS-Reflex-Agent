# APUS Reflex Harness Desktop branding

The display identity is APUS Reflex Harness (瞬策), with APUS / REFLEX as the compact wordmark and 瞬时执行，深度思考 · Model-as-a-Harness as the positioning text. Harness owns `apps/web/public/brand.json`, its SVG master and PNG/ICNS/ICO assets. Desktop imports those assets during runtime preparation into ignored `.build/brand`; build verification rejects missing resources or a mismatched product name. Native menus, startup/recovery, mobile pages and onboarding use the same identity. Sidebar and onboarding marks consume the shared Harness primitive rather than maintaining Desktop whale artwork.

The runtime and desktop host use the same reviewed repository commit. Prepare and package them together from the repository root. `npm ci` applies compatibility patches but no longer installs legacy brand assets into the stock dependency. Production runtime preparation applies desktop compatibility patches first, then installs the APUS favicon and web manifest identity into the deployed runtime. Runtime metadata and package names remain compatible.

Existing `ai.xdan.system3` / `ai.xdan.system3.dev` application IDs, `xdan-system3` / `xdan-system3-dev` state directories, DSH package/IPC identifiers and SYSTEM3 environment variables are retained. The application display name is independent of these identities. Product configuration disables upstream diagnostics and automatic updates without testing the display name. This preserves the existing fork policy after a rename.

Validation includes shared brand resource preparation, wrong-brand rejection, old profile identity preservation, disabled diagnostics and manual/automatic upstream updates, desktop slot ownership, localized UI, README parity and package input assertions. Native startup, actual package contents and Windows require separate acceptance evidence; source tests cannot establish those results.

The original DataElement MIT license remains unchanged. `THIRD_PARTY_NOTICES.md` thanks DSH Desktop and DeepSeek Harness and distinguishes dependency-specific licenses. Runtime preparation copies both original MIT texts, both notices, Electron’s LICENSE and Chromium’s bundled notices into `.build/licenses`; packaging includes them in `Resources/licenses` and checks byte equality. About offers a trusted local-folder action. Package license files are not excluded by the application file filter.
