# Reflex context and same-session memory

English | [中文](reflex-context-implementation.zh.md)

The `reflexContext` System3 configuration installs one bounded semantic review before each admitted model request. It uses the shared Reflex decision provider and privacy policy. Only unsubmitted, unfrozen user/tool-result text can be selected; submitted history and generated assistant text are frozen conservatively; system/developer messages, recent messages, task-frame constraints, non-text dependent messages, and recognizable structured blocks are retained. Uncertain, unavailable, over-budget and stale judgements retain current content.

Selections name the original event sequence, text-block index, exact immutable text witness, and original character offsets plus 1-based inclusive line coordinates. Long lines split at Unicode code-point boundaries. A durable `reflex/context-projection` changes only selected text, preserves message IDs and tool pairs, and records sequentially calculated token-price deltas. The pure interpreter is exported from `dsh-compaction/reflex-context-projection`; detached readers must install it. Invalid original text, ranges, protected roles, or non-current surface references reject atomically.

The host-only `reflexContext` state projection rebuilds the memory index from the log. The `reflex_memory` tool searches only its calling session and returns bounded excerpts with original references. An unfrozen active original node is restored through the durable projection; frozen content is recovered by appending attributed text without changing the old omission marker; if compaction has replaced that node, restoration returns a `reflex-memory` deferred context carrying the original reference and text. Automatic reviews also consider archived fragments and can return recovered context with the admitted input. Original events are never deleted.

When task-frame review is installed, context review first awaits the finite batch of judgements for this step’s admitted messages. Later queued messages do not extend this wait. Cancellation releases the wait and prevents context review. This prevents a concurrent task-frame update from repeatedly invalidating otherwise useful selections. The plugin fences asynchronous results against the context revision, current Goal view, and surface generation/node list. The current user input supersedes the previous topic in review input; combining both can make a legitimate topic change look like a contradiction. Restored current nodes remain protected for the current topic. Candidate rotation prevents retained early fragments from permanently starving later history.

## Validation evidence

Thirty-seven focused deterministic tests passed in `packages/experimental/system3/tests/reflex-context.spec.ts`: original-text preservation, exact request projection, detached replay, state reconstruction, restoration, structured content, stale judgement rejection, confidence and transport fallback, queued human-input fencing, invalid ranges, Unicode/CRLF handling, archive search after compaction, same-session isolation, archived restoration without repeated injection, and mixed remove/restore batches with distinct revisions and exact aggregate token deltas. They also cover deployment budgets, tool restoration limits, task-frame retention, image inputs, tool pairing, omission with no token saving, and plugin unload during pending request admission. The tests do not establish statistical model reliability.

The real-provider finance scenario in `reflex-context.e2e.ts` uses a real Reflex endpoint with a recording primary-model adapter. It asserts that a finance CSV request retains Decimal and immutable-source constraints, omits unrelated Kyoto travel details from the actual primary-model request, then reconstructs a fresh Host from a disk log and restores the hotel and breakfast facts when the user changes topics. The primary model is a recording adapter, so this is not the final Web answer-quality acceptance.

A previous live run after accepted-input, archive restoration and mixed-action changes also passed in 4.07 seconds (2.23 seconds in the test body), without retries. The first live attempt retained the irrelevant fragment; the second omitted it but failed restoration. Investigation found that the previous finance request was being concatenated with the new travel question. After fixing current-input precedence, the third attempt passed without retries: constraint removal probability 0.1067 (retained), irrelevant travel removal 0.9868, and travel restoration 0.9850. Preserve all attempt logs in final acceptance evidence rather than reporting a three-for-three success rate.

The first recorded primary request in the real-provider component scenario exposes one `reflex_memory` schema: 507 serialized UTF-16 code units, priced at 131 heuristic tokens by the repository meter (`ceil(chars / 4) + 4`), versus zero tool-schema tokens with that sole tool removed. This measures additive tool-definition overhead, not provider-tokenizer usage; the earlier SDK composition had 24 existing tools at 4,517 heuristic tokens and 25 tools with memory at 4,644, a delta of 127.

The cache-protected SDK scenario enables task-frame and context review together through the shipped Loader. Five actual tool calls produce an unsubmitted tail; the deployed four-message recent-history protection leaves only the oldest result eligible. A real memory-tool call then restores its omitted content by appending attributed context, leaving the submitted marker intact. The refreshed expected outputs must record this behavior; earlier remove/restore projection pairs describe the superseded cache-breaking behavior and are not acceptance for the new policy.

The built Python SDK scenario also enables both reviews and passes actual recording and keyless replay, with `result.json`, `model-visible.json`, and `session.v4.jsonl` generated by the existing smoke runner. Its cache-protected expectations check one removal against the persisted log and a separate appended `reflex-memory` user message; the previously submitted hotel history remains unchanged. The existing `dsh_session_log` request attachment still carries immutable original events; projection reduces inference messages and does not erase original-log delivery. These revised expectations require refreshed recordings after the cache-protection build.

The combined task-frame and context regression run passes 69 tests, including a held task-frame response that must settle before context selection begins and plugin unload during that wait. The targeted coverage run passes the strict per-file gate: statements, branches, functions and lines are all 100% across the three new modules and the task-frame module. Durable checkpoint restoration rejects a nonexistent original message reference; disposing the actual public projection registration makes the memory tool fail loudly. A same-block mixed-action regression retains a restored line while omitting another line. No threshold or exclusion was changed.

## Remaining integration verification

- Register the pure interpreter in the session format catalog and include the new source/event fields in persistence and SDK type projections.
- Verify all three token-meter projections consume per-target deltas consistently, including multiple blocks in one message.
- Run final Host/client build, lint, snapshots and combined tests after integration changes.
- Complete real primary-model Web/Electron acceptance; the recording-adapter result above is not a substitute.
- Measure tool-definition prompt cost and semantic-review latency in the final composition.

The exact original-text witness in each projection repeats that block in the durable log. This provides collision-free validation without a platform-specific hashing dependency, but increases retained-log storage; active-context reduction does not imply unbounded physical memory or storage.

Submitted-prefix protection, its effective tail scope, and the outstanding provider-cache cost/latency acceptance are defined in the [cache design](context-cache-design.md).

The cache-protected real Reflex component test passed once with retries disabled (10.00 seconds total, 4.68 seconds in the test): the fresh Host appends restored memory and does not rewrite the transmitted omission. This test uses a recording main-model adapter and does not measure provider cache hits.

Decision version 2 places each target text directly in its question and includes its original event, block and line range as an index, not a semantic file-path claim. Instructions preserve facts and amounts needed for calculation, distinguish untrusted data from useless data, and prohibit transferring another fragment’s conclusion. A session skips an identical successful, still-current empty selection only while its complete request, deployment settings, privacy route and effective provider options match. Failed, stale and positive selections are not cached; unadmitted recovery can be proposed again.
