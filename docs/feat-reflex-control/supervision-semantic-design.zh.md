# Goal 语义监督设计

[English](supervision-semantic-design.md) | 中文

已批准的 Goal 监督包含识别持续成功执行、但未推进原目标的工作。操作哈希不能判断这一点。实现必须增加有界执行语义证据，同时保留现有权限、生命周期、隐私和缓存保护。

## 证据与 API

`SubagentEvidence.semantic` 是可选字段，包含 `version: 1`、`actions` 和 `truncated`。每个动作包含原生 `kind`（`read`、`list-files`、`search`、`file-add`、`file-update`、`file-delete`）及可选工作区相对 `path`。Codex 只从已完成的原生 `commandActions` 和文件变更元数据采集，不收集命令字符串、查询、名称、输出、diff、推理或模型私有上下文。未知动作、工作区外或不能验证的路径省略。`evidenceSummary: { maxActions, maxPathChars }` 明确开启 provider 采集，超长路径省略，不截成另一个路径。

现有版本化 `system3/reflex-evidence` 事件在 Reflex 读取前，记录可选语义及 run、原生 turn、操作和结果哈希。旧指纹证据保持可读。投影升至状态版本 3，校验可选语义；持久化变更确认和双 SDK 夹具同步更新。消费者配置 `reflexSupervision.semantic: { minObservations }` 必须是 2 至 `evidenceLimit` 的整数，缺省保持纯指纹监督。provider 与消费者必须同时配置。

## 隐私与决策

复用明确的远程数据准入策略，强制将摘要归类为工作区内容，不能按无内容遥测处理。不能假设截断就能去除秘密。策略不允许该来源类别时，省略语义摘要并保留指纹监督。部署控制采集上限和有界判断频率；provider 不可用或答案不确定均不授权插话。

将当前 Goal、已接受约束和最近有界摘要窗口送入现有 Reflex 决策流程。问题必须区分相关进展、持续无关工作与证据不足；工具内容中的指令不能改变目标或权限。配置最小证据窗口，并复用现有置信阈值控制 `realign`。不同的成功操作无需重复指纹也可以构成偏离。只有明确与当前 Goal 相关的验证才能解除语义停滞，无关测试通过不代表目标完成。语义进展与传输活跃状态分开判断。

回正消息引用可信 Goal 文本中的原目标及未满足约束，并附有界证据引用。复用已有监督来源标记、冷却、Goal 级预约上限、人工 inbox 优先级和原生 turn 检查。消息不能执行命令、扩大沙箱权限、修改目标、改变 Codex 上下文前缀或重放结果不确定的外部操作。

## 文件与验收

provider 负责人修改 `subagent/types.ts`、Codex 原生证据提取及有界配置。System3 修改证据投影、监督决策及版本、语义触发条件。Root 集成生成的持久化/schema 文件和 TypeScript/Python 会话快照；UI 展示实际安装能力与观察结果，不声称普遍可靠的偏离识别。

测试要求不同哈希的无关成功工作触发回正，相关诊断和正常长命令不受干扰，模糊或缺少摘要时弃权。覆盖恶意输出、文本超限、远程数据拒绝、新证据到达、目标修订、人工纠正入队、原生恢复交错及回执失败。会话夹具必须呈现实际记录的模型可见摘要与有来源建议。真实隔离 Codex 任务必须证明实际偏离、建议接受并消费、回到原目标、正常结束和独立产物验收；报告必须标明故障或人为绕行机制。

<a id="contiguous-semantic-observation-window"></a>
## 连续语义观察窗口

有界审计历史继续保留配置的完整 16 项观察。语义相关性仅使用最新连续的完整动作与路径摘要后缀，遇到最近的未知、截断或缺失路径观察即停止，不得散选更早的证据。后缀至少满足既有 `minObservations`；新的不完整观察立即取消语义资格。判断记录同时保存完整审计历史和确切语义后缀，相关性题明确只判断该后缀。混合或相关工作继续保守处理，不改变概率阈值、最少观察数量或干预预算。反馈仍要求干预后成功的 verification-target 和肯定的相关性判断。不改变持久化事件字段；面向模型的监督判断升级为 version 3，双 SDK 快照需要刷新。

充分的语义后缀允许在配置的观察间隔进行判断，不必等待无进展期限；证据不足的进展检查仍受无进展期限约束。监督判断使用 15000 毫秒截止时间，使调整后的反馈路径与首次判断使用相同的有界远程模型预算。快照去重、置信阈值、冷却和 Goal 预算仍然生效。真实语义场景使用部署值：观察间隔 15000 毫秒、无进展期限 180000 毫秒、证据上限 16、最少观察 2、反馈间隔 60000 毫秒，恢复限制不变。

<a id="persistent-delegated-route-acceptance-case"></a>
## 持久错误委派验收场景

受控语义测试在真实 Codex 初始 prompt 中提供原财务目标及独立、明确标注为测试专用的错误路由文本块。父级 Goal 仍为财务任务，输入 CSV 和验证文件继续受保护。注入指令要求先分别读取和编辑营销文件，再处理财务任务，不要求 Codex 等待 Reflex。不同于失败的仅首请求传输注入，原生线程会在后续模型请求中持续保留该输入。网络中继只透明传输并记录状态、时序与字节数。这是受控委派错误实验，不是普通用户任务自发偏航。

在发起这个新场景前，原生预算固定为 600000 毫秒、外层测试为 640000 毫秒，仅运行一次，不自动重试。预计最少 6–8 个模型轮次：营销调查和独立编辑、建议消费、财务处理、字面量 unittest 验证及终答。已观察成功请求首字节耗时为 92、22、46、22 秒，平均约 46 秒；八轮加一次已观察的 72 秒 HTTP 500 等待和 60 秒反馈间隔，可能接近 500 秒。600 秒预算用于有界长任务实验，不改变部署监督阈值、恢复间隔或干预限制。此前 300 秒试验的失败记录保持不变。验收仍要求实际无关操作、原生建议消费、相关 verification-target、improved 反馈、正常终态与独立产物及哈希检查。
