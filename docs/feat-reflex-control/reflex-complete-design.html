Reflex 模型配置、Goal 监督与动态上下文

设计提案，尚未实现。供用户确认实现范围；本页不构成新的 E2E 通过声明。产品统一称 Reflex，底层既有 Jev 协议、模型 ID、包名保持兼容。

1. 目标与完成定义

用户从专用页面配置 Reflex；长时 Goal 的 Codex 子任务异常或持续无进展时，Reflex 根据执行证据判断并自动发送调整消息，再观察调整效果；Harness 每次模型请求按当前任务需要保留或移出上下文的行/片段，并可找回旧信息。三个能力均以运行行为而不是配置开关验收。

入口选路保留已有回归。原始会话日志不删除，“删除上下文”指后续模型请求不再携带选中的无用内容。持久记忆首期为同一会话、跨进程重启可恢复；跨会话共享记忆不默认为启用。外部 Codex 内部上下文目前没有按行编辑接口，不把 Harness 投影能力冒充 Codex 内存编辑。

3. 专用配置页面

沿用Reflex 模型配置设计：地址、受保护 API Key、模型、high/low、超时、真实判断测试和保存。复用 ConfigForms 与 Credentials，不增加浏览器明文密钥存储。展示部署锁定/配置来源；保存后的新请求生效，若设施需重启则明确提示。连接测试不能自动覆盖此前有效配置。

三项能力分别显示 implemented、enabled、最近判定与执行结果；配置成功不等于能力完成。监督频率、无进展阈值、冷却时间、每 Goal 干预上限、上下文预算与单批判断大小均是验证后的部署配置，提供解释清楚的高级设置，不散落硬编码。

4. Goal 长时监督闭环

范围包括活跃 Goal 下正在执行的 Codex 子任务，以及该 Goal 多轮继续执行时反复失败的任务。监督基于同一个 goalId/revision 关联 runId、turnId、证据序号，不能只看最后一条活动时间。等待真实进程/审批、持续产生新结果等状态不得仅因耗时长判为打转。

现有 subagent/activity 是受限活动摘要，不允许悄悄塞入完整命令和工具输出。新增独立监督证据事件：操作类别、归一化操作指纹、失败类别、结果变化指纹、验证结果及有限脱敏摘要；来源和缺失字段明确。命令输出按不可信数据处理，不能成为监督指令。不能仅凭文件改变判定目标已取得进展。

观察 → 候选异常 → Reflex 判定
                   ├ 正常/证据不足：继续观察
                   └ 需要调整：复核 Goal / run / turn / evidence revision
                               → 记录干预意图 → steer → 记录回执
                               → 冷却与新证据观察 → 有效 / 无效 / 无法确认
无效且预算尚存：换策略再次判断；预算耗尽：停止自动插话并显示需处理原因

Reflex 接口本身是结构化判断，不假设可自由生成纠偏长文。首期选择有证据支持的策略：停止重复操作并检查根因、先做最小验证、缩小单步范围但保留原目标、重新核对目标约束。Host 根据策略和证据构造有界消息；不得擅自换目标、宣称完成、扩大权限或执行破坏操作。需要额外生成模型时另作显式配置，不隐藏调用。

每个运行实例只允许一个待处理判断；冷却以成功回执为准。人工插话优先，使旧自动判断失效。Goal 暂停/完成/修订、子任务退出、turn 改变、进展更新都使旧结果失效。steer 失败记录失败，不冒充成功；超时回执不确定时不得盲目重发。重启后从持久化意图/结果恢复，无法确认是否已发送的干预标记为未知，等待新证据重新评估。

观察 Codex 运行异常与超时

观察信号证据与判断动作
运行较久但有进展进程仍活跃，产生新的验证结果或相关成果；操作不只是重复继续观察，不因总时长插话
无进展超时距最近可验证进展超过配置阈值，对比前后证据窗；仅心跳/commentary不重置有效进展时间Reflex判断继续等待或调整策略
重复失败/打转相同操作指纹、相同错误类别/结果跨多次或多轮重复，没有新的诊断证据Reflex选择根因诊断/最小验证等策略并发送有来源的调整消息
进程退出/连接失效真实run结束、异常退出或传输不可用；观察失败不等于任务进程死亡记录故障并通知父任务；已结束run不能接收steer，不自动重启冒充纠偏
偏离目标操作/结果与当前Goal约束和验收项持续不相关引用未满足约束，引导回到原目标

输入给 Reflex 的监督包包含 Goal objective/revision、验收约束、run/turn、观察窗口起止、运行状态、距最近有效进展时长、有限操作/错误摘要与证据引用、历史干预及后续变化。采用既有 decision-kernel 的隐私准入，服务不可用/低置信度则继续观察并显示诊断。不能将完整工作区或任意终端日志默认发送到外部服务。

复用 goal/changed、goal/activation-changed、subagent/start/activity/end 和既有告警作为触发。自动消息必须明确标记 reflex-supervision 来源，与 human 输入区分；扩展既有 steer 持久化类型或提供内部监督接口，底层复用 turn/steer。判断成功、消息已接收和行为改善为三种独立状态。生命周期销毁时取消计时器和待处理判断，重启不对陈旧 run 投递。

5. 按行上下文与恢复记忆

片段引用为 sessionId、原事件序号、文本块序号、内容摘要及 1-based 闭区间行号；行号相对于原始文本，不相对于此前裁剪后的文本。范围、内容摘要、当前投影版本全部匹配才可应用。中文、空行、CRLF、无末尾换行和超长单行需一致处理；超长单行进一步分片并保留原行映射。

Reflex 根据当前 Goal、最新有效用户要求、候选片段和已有关键记忆，判断 keep/remove/uncertain。uncertain 保留。先按语义单元组织候选，再允许精确行范围；代码、JSON、表格等相互依赖结构按组保护，不能删除一行导致剩余信息失真。系统/开发者指令、当前目标、未解决约束、正在执行的工具调用与配对、最近必要输入受保护；新版本用户约束取代旧版本需可追溯。

以有限批次调用决策 API，符合服务单问题 token 和每请求问题数上限；单轮时间/调用预算用尽即保留未判断片段。判断失败不做删除。上下文插件将替代消息写入持久化投影，保留原始消息、工具调用配对和来源引用；计量同步更新。不重用“固定头尾裁剪成功”作为语义裁剪证明。

恢复使用受会话权限约束的记忆索引：原事件/片段定位、关键词或引用查询、Reflex 相关性复核，将原文恢复到后续请求并记录事件。用户或主模型可请求恢复；任务目标/主题改变时自动重新评估相关的已移出内容。索引可从日志重建，重启后不丢失恢复路径。不得将另一个会话内容混入本会话。

现有 Codex wire 仅见 thread/start、turn/start/steer 等生命周期操作，没有按行投影接口。对子任务可发送新证据或恢复片段，但不能宣称删除其内部历史。若后续要求直接编辑 Codex 上下文，需要协议支持或单独批准的运行实例重建方案，不能偷偷中断重启任务来伪装。

真实 E2E 使用可控隔离项目与有界失败场景，但 Reflex 判断与 Codex 执行必须是真实调用；记录注入故障与模拟设施，不能用 stub steer 冒充真实闭环。确定性测试覆盖全部生命周期，模型测试按预先定义场景报告每次结果，不挑选成功重跑。记录监督误报、纠偏有效率、关键约束保留、恢复成功、token节省、额外耗时与调用数；阈值与样本表在实现前固定，不能用一个样本宣称普遍可靠。

9. 实施顺序与审阅

  1. 配置页面与真实连通/持久化；同时补齐状态接口。
  2. 监督证据、Reflex判定、steer及反馈；真实Goal异常和正常对照验收。
  3. 行片段投影、恢复与重启；真实模型请求验收。
  4. 两仓组合验收、构建/lint/回归/快照、review、交接与授权范围内合并。

四步属于同一完整Goal，任一步通过不代表整体完成。依据用户提供的 AGENTS.md Human Gate：“Do NOT start implementation until explicit approval”。请确认本设计后开始产品代码实现。
