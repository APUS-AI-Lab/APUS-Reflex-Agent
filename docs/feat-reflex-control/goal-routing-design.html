Goal 首轮委派入口

真实 Web 验收发现 /goal 直接进入 Goal round-driver，绕过只接收空闲真人 API 输入的入口路由。目标明确要求 Codex 时，主模型仍先修改文件。新增 System3 pre-step 插件路径，在主模型产生工具调用前完成已授权委派。

Goal continuation → 校验 active/armed + goalId/revision → 候选权限/可用性 → Reflex 语义确认 → 持久化 reservation → subagents.start → 原生执行与现有 Reflex 监督 → 带 Goal 来源的结果 → 主模型复核

复用 entryRouting 中的委派候选、隐私分类、请求大小及决策预算。该路径只选择委派或保留主模型，不在正在准备的 step 中切换模型。人类新消息、Goal 变更和取消会取消在途工作并使建议失效。每个 Goal revision 只作一次委派尝试，恢复后 reservation 仍阻止重复启动；自动消息不冒充用户，也不制造 API request id。

所有目标包括点名 Codex 的目标均经 Reflex 语义确认，否定和引用中的名称不构成授权；不确定时弃权。卸载先取消，再等待完整 pre-step 和 child.dispose 结束，内层 next 迟返时不得启动任务。

新增 goal-entry-routing.ts、goal-entry-state.ts 及测试；System3 index.ts 在既有 entryRouting 配置下安装插件。新增 system3/goal-entry 记录 goalId/revision、候选、阶段、精确输入及JSON编码输出；新增 kind-only system3-goal-delegation 消息来源，结果内容完整留在日志。SDK schema、持久化分类及双语 README 同步；独立 keyless SDK 场景复用真实 pipeline，只替换外部 provider。

验收

单测覆盖明确选择、Reflex 选择、无候选、隐私拒绝、超预算、人工/Goal/取消竞态、恢复防重复与异常清理。keyless snapshot 验证首个主模型请求前委派已经执行、结果归属及持久化。真实浏览器 /goal 验收由主代理执行，不以正文要求模型等待代替真实入口。

定向验证：30 项测试通过，包含真实 AgentLoop 在 pre-step 等待子任务时接收人工消息，阻塞旧 Goal 后保留原消息并在后续明确 followup 时送入模型。两个新增模块覆盖率均为 100%（138 语句、93 分支、31 函数、97 行）。记录完成但模型尚未接收的输出可以从回执恢复，不重放外部副作用。
