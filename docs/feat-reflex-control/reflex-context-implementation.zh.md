# Reflex 上下文与同会话记忆

[English](reflex-context-implementation.md) | 中文

System3 的 `reflexContext` 配置在每次获准执行的模型请求前进行一次有界语义审查，使用共享的 Reflex 决策提供方与隐私策略。只有尚未提交且未冻结的用户或工具结果文本可被选择；已提交历史与模型生成的助手文本保守冻结；系统与开发者消息、最近的消息、任务框架约束、依赖非文本块的消息以及可识别的结构化块会保留。不确定、不可用、超预算或已失效的判断保留当前内容。

选择记录原始事件序号、文本块索引、完整且不可变的原文校验依据，以及原始字符偏移和从 1 开始、两端包含的行号。长行按 Unicode 码点边界分段。持久化的 `reflex/context-projection` 只修改选中文本，保留消息 ID 和工具配对，并记录依次计算的 token 估算差值。纯解释器由 `dsh-compaction/reflex-context-projection` 导出；脱离运行中会话的读取方必须安装它。无效原文、范围、受保护角色或不在当前上下文中的引用会使整批操作被拒绝。

仅在 Host 中使用的 `reflexContext` 状态投影从日志重建记忆索引。`reflex_memory` 工具只搜索调用它的会话，返回带原始引用的有界摘录。尚未冻结且仍在当前上下文中的原始节点通过持久化投影恢复；冻结内容通过追加有来源原文恢复，不改变旧省略标记；若压缩已替换该节点，则返回携带原始引用和文本的 `reflex-memory` 延后上下文。自动审查也考虑已归档片段，并可随获准输入返回恢复的上下文。原始事件永不删除。

安装任务卡审查时，上下文审查先等待本步骤已取走消息的有限判断批次。后续排队消息不延长等待。取消会结束等待并阻止上下文审查。这避免任务卡并发更新反复使本来可用的选择失效。插件以异步请求发出时的上下文修订、当前 Goal 视图、上下文生成序号和节点列表为依据，拒绝过期结果。审查输入中的当前用户消息替代旧话题；合并两者可能将合法的话题切换误判为矛盾。当前节点中已恢复的文本在当前话题下受保护。候选轮转避免早期保留的片段永久挤占后续历史的审查机会。

## 验证证据

`packages/experimental/system3/tests/reflex-context.spec.ts` 中 37 个定向确定性测试通过，覆盖原文保留、精确请求投影、脱离运行会话的重放、状态重建、恢复、结构化内容、过期判断拒绝、置信度和传输失败回退、排队用户输入使判断失效、无效范围、Unicode/CRLF 处理、压缩后的归档检索、同会话隔离、归档恢复不重复注入，以及混合删除和恢复批次各自的修订和精确总 token 差值。测试还覆盖部署预算、工具恢复上限、任务框架保留、图片输入、工具配对，没有 token 收益的省略，以及等待请求准入期间的插件卸载。这些测试不能证明模型的统计可靠性。

`reflex-context.e2e.ts` 中的真实提供方财务场景使用实际 Reflex 端点和记录请求的主模型适配器。它断言财务 CSV 请求保留 Decimal 和不可修改源文件的约束，从实际主模型请求中移除无关的京都旅行细节，随后从磁盘日志重建全新 Host，并在用户切换话题后恢复酒店与早餐事实。主模型只是记录适配器，因此这不等于最终 Web 回答质量验收。

此前获准输入、归档恢复与混合动作调整后的真实运行也已通过，总耗时 4.07 秒，测试主体 2.23 秒，未重试。第一次真实尝试保留了无关片段；第二次移除了片段，但恢复失败。排查发现旧财务请求被拼接到了新的旅行问题前。修复当前输入优先级后，第三次尝试无重试通过：约束删除概率为 0.1067（保留），无关旅行片段删除概率为 0.9868，旅行恢复概率为 0.9850。最终验收证据应保留所有尝试的日志，不能报告为三次全部成功。

真实提供方组件场景中首次记录的主模型请求包含一个 `reflex_memory` 工具定义：序列化后为 507 个 UTF-16 代码单元，仓库计量器按 `ceil(chars / 4) + 4` 估算为 131 tokens；移除这个唯一工具后，工具定义估算为零。这衡量新增工具定义的开销，不代表提供方分词器用量；此前录制的 SDK 组合原有 24 个工具，估算为 4,517 tokens；加入记忆工具后为 25 个工具、4,644 tokens，差值为 127。

保护缓存的 SDK 场景通过已发布 Loader 同时启用任务卡和上下文审查。五次真实工具调用生成尚未提交的尾部，部署的最近四条消息保护只让最早结果成为候选。真实记忆工具调用随后追加有来源原文，恢复省略内容且保持已提交标记不变。更新后的预期输出必须记录这一行为；此前删除与恢复投影成对出现的记录描述的是已替换的破坏缓存行为，不能验收新策略。

已构建 Python SDK 场景也同时启用两种审查，并通过实际录制和免密钥重放，由现有 smoke 运行器生成 `result.json`、`model-visible.json` 和 `session.v4.jsonl`。其保护缓存的预期输出对照持久化日志验证一次删除及单独追加的 `reflex-memory` 用户消息；此前已提交的酒店历史保持不变。既有 `dsh_session_log` 请求附件仍携带不可变原始事件；投影缩减推理消息，不会擦除原始日志传输。这些修订预期需要在缓存保护构建后重新录制。

任务卡和上下文组合回归的 69 个测试通过，包括任务卡响应被挂起时上下文审查必须等待，以及等待中的插件卸载。定向覆盖率运行通过逐文件严格门禁：三个新增模块和任务卡模块的语句、分支、函数和行覆盖率均为 100%。持久化检查点恢复会拒绝不存在的原始消息引用；调用真实的公开投影注销函数后，记忆工具明确报错。同一文本块的混合动作回归验证恢复一行时仍省略另一行。没有修改阈值或排除项。

## 待完成的集成验证

- 在会话格式目录中注册纯解释器，并将新增来源和事件字段纳入持久化与 SDK 类型投影。
- 验证三个 token 计量投影一致应用每个目标的差值，包括同一消息中的多个文本块。
- 集成修改后执行最终 Host/客户端构建、lint、快照与组合测试。
- 完成真实主模型 Web/Electron 验收；上述记录适配器结果不能替代此验收。
- 测量最终组合中的工具定义提示开销和语义审查延迟。

每次投影中的完整原文校验依据会在持久化日志中重复该文本块。它提供无碰撞校验且无需平台相关的哈希依赖，但会增加保留日志的存储量；缩减当前上下文不意味着无限物理内存或存储。

已提交前缀保护、有效尾部范围及待完成的提供方缓存成本和延迟验收，见[缓存设计](context-cache-design.zh.md)。

保护缓存的真实 Reflex 组件测试在禁止重试时通过一次（总计 10.00 秒，测试主体 4.68 秒）：新 Host 追加恢复记忆，不改写已发送省略。该测试使用记录请求的主模型适配器，不测量提供方缓存命中。

决策版本 2 将每个目标原文直接放入对应问题，并附原事件、文本块和行范围作为索引，不将索引解释为文件路径语义。指令要求保留计算所需事实和金额，区分不可信数据与无用数据，禁止套用其他片段的结论。只有成功、仍有效的空选择才会在完整请求、部署设置、隐私路由及有效提供方选项完全相同时跳过重复请求；失败、过期和正向选择不缓存，尚未接纳的恢复仍可再次提出。
