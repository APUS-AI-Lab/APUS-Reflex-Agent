Reflex 用户体验验收

场景预先固定，状态均为待执行；采用虚构业务数据，不使用用户真实财务资料。真实模型与真实Codex执行，测试替身及故障注入单列。不能挑选成功结果掩盖失败。

用户操作/自然问题验收证据
设置→Reflex模型配置，填写服务并测试、保存，重启后发起任务页面真实可用、无凭据回显；新会话请求命中指定服务；错误key不覆盖已保存有效配置。
“这个账单工具导入CSV时金额汇总不对，请修复，金额要精确到分，不要修改原始CSV或测试，运行测试通过后说明修改。”实际文件修改、独立测试通过、原CSV和测试hash不变；观察正常任务不误插话。若自然出现重复失败，记录真实监督；没有异常不能伪造自动纠偏成功。
同一任务遇到可控外部执行故障，用户仍只描述修复目标记录注入位置及范围；真实Reflex诊断、真实Codex调整、后续行为与外部验证；不提示Codex固定重复次数或预写答案。
执行中追加“输出CSV列名用中文，已有命令参数保持兼容”新要求被采纳；旧监督判断作废；最终功能、列名与兼容性独立检查。
先讨论样例周末行程，再处理CSV工具；后续问“刚才行程中的集合时间是什么？”Reflex移出无关旧行、保留财务约束；重启后旧信息检索恢复并答对；实际请求和原日志对照，不只看节省数字。

每次记录用户输入、UI截图、session/run/decision对应关系、结果文件、测试输出、延迟、失败及限制。Web与最终Electron装配各做适用流程；未运行的平台不报告通过。
