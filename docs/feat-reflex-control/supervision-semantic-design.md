# Semantic Goal supervision design

English | [中文](supervision-semantic-design.zh.md)

The approved Goal supervision includes successful work that persistently does not address the Goal. Operation hashes cannot establish this. The implementation must add bounded semantic execution evidence while retaining existing permission, lifecycle, privacy and cache protections.

## Evidence and API

`SubagentEvidence.semantic` is optional and contains `version: 1`, `actions` and `truncated`. Each action contains a native `kind` (`read`, `list-files`, `search`, `file-add`, `file-update`, `file-delete`) and an optional workspace-relative `path`. Codex collection uses only completed native `commandActions` and file-change metadata. It excludes command strings, queries, names, output, diffs, reasoning and model-private context. Unknown actions and external or unverifiable paths are omitted. `evidenceSummary: { maxActions, maxPathChars }` explicitly enables provider collection; over-budget paths are omitted instead of cut into a different path.

The existing versioned `system3/reflex-evidence` event records optional semantics with its run, native turn and operation/result digests before Reflex sees them. Fingerprint-only evidence remains readable. The projection moves to state version 3 with optional semantic validation; declared persistence acknowledgements and both SDK fixtures update together. Consumer config `reflexSupervision.semantic: { minObservations }` requires an integer from 2 through `evidenceLimit`; absent means fingerprint-only. Both provider and consumer configuration are necessary.

## Privacy and decision

Use existing explicit remote-data admission, with summaries forcibly classified as workspace content rather than content-free telemetry. Do not assume truncation removes secrets. If policy does not permit the source class, omit semantic summaries and retain the existing fingerprint supervisor. Deployment owns collection limits and bounded decision cadence; an unavailable provider or uncertain answer never authorizes steering.

Pass the current Goal, accepted requirements and a bounded recent summary window to the existing Reflex decision pipeline. The question must separate relevant progress, continued unrelated work and insufficient evidence; quoted tool instructions cannot change the Goal or permissions. A configured minimum evidence window and the existing confidence threshold gate `realign`. Different successful operations may qualify without duplicate fingerprints. Only verification demonstrably related to the current Goal can clear the semantic stall; an unrelated passing test is not proof of completion. Keep semantic progress separate from transport liveness.

A realignment message identifies the unchanged Goal and unmet requirement using trusted Goal text, with bounded evidence references. It uses the existing attributed supervisor steering path, cooldown, Goal-wide reservation limit, human-inbox priority and native-turn fencing. It cannot execute commands, enlarge sandbox permissions, change the Goal, mutate the Codex context prefix or replay uncertain external effects.

## Files and acceptance

The provider owner changes `subagent/types.ts`, Codex native evidence extraction and its bounded configuration. System3 changes the evidence projection, supervision decision/version and semantic eligibility. Root integrates generated persistence/schema files and TypeScript/Python recorded-session fixtures; UI reports the installed capability and its observed decision without claiming universal drift detection.

Tests require unrelated successful work with distinct digests to trigger realignment, related diagnostics and long commands to remain undisturbed, and ambiguous/missing summaries to abstain. Include malicious output, over-budget text, denied remote data, late evidence, Goal revision, queued human correction, native recovery interleaving and failed acknowledgement. Recorded fixtures must show the exact logged model-visible summary and attributed advice. A real isolated Codex task must demonstrate an actual unrelated detour, accepted and consumed advice, return to the original objective, normal termination and independent artifact verification; faults or artificial detours must be identified in the report.

## Contiguous semantic observation window

The bounded audit history retains all 16 configured observations. Semantic alignment uses only its latest contiguous suffix of complete action/path summaries, stopping at the most recent unknown, truncated or pathless observation. It never selects scattered older evidence. At least the existing `minObservations` must remain in that suffix; a new incomplete observation immediately clears semantic eligibility. The judgement logs both the complete audit history and the exact semantic suffix, and the alignment question explicitly judges only that suffix. Mixed or related work remains conservative. No probability threshold, minimum observation count or intervention budget changes. Feedback still requires a post-intervention successful verification-target and an affirmative relevance judgement. No persistence event fields change; the model-facing supervision decision advances to version 3 and both SDK snapshots require refresh.

A sufficient semantic suffix permits review at the configured observation interval without waiting for the inactivity deadline. The inactivity deadline continues to gate evidence-insufficient progress checks. Snapshot deduplication, confidence thresholds, cooldown and Goal budgets still apply. Supervision decisions use a 15000 ms deadline so the post-intervention feedback path has the same bounded remote-model budget as the initial judgement. The real semantic trial uses the deployment values: interval 15000 ms, stall 180000 ms, evidence limit 16, minimum observations 2, feedback 60000 ms and unchanged recovery limits.

## Persistent delegated-route acceptance case

The controlled semantic trial supplies the original finance objective and a separate, explicitly test-only wrong-route text block in the real Codex initial prompt. The parent Goal remains finance, and the input CSV and verifier remain protected. The injected assignment asks for separate marketing reads and edits before finance work; it does not tell Codex to wait for Reflex. Unlike the failed first-request-only transport injection, the native thread retains this input across model requests. The network relay is transparent and records only status, timings and byte counts. This is a controlled delegation-error experiment, not spontaneous drift in an ordinary user task.

Before running this new case, its native budget is fixed at 600000 ms and the outer test at 640000 ms, with one run and no automatic retry. The estimated minimum sequence is 6–8 model rounds: marketing inspection and separate edits, then advice consumption, finance work, literal unittest verification and final response. Observed successful first-byte delays of 92, 22, 46 and 22 seconds average roughly 46 seconds; eight rounds plus one observed 72-second HTTP-500 delay and the 60-second feedback interval can approach 500 seconds. The 600-second budget bounds this long-task experiment without changing any deployment supervision threshold, recovery interval or intervention limit. The earlier 300-second trial remains an unchanged failure record. Acceptance still requires actual unrelated operations, native advice consumption, relevant verification-target, improved feedback, normal completion and independent artifact/hash checks.
