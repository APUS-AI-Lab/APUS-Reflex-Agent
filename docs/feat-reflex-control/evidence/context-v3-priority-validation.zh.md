# 上下文判断 v3 优先级验证

[English](context-v3-priority-validation.md) | 中文

浏览器 v2 请求把“旅行与本次财务无关”的旧任务框架，与稍后询问归档旅馆、早餐和集合细节的请求拼在一起，没有明确旧旅行排除条件的时间角色。v3 分开记录有序 `currentUserRequests` 数组、仅在 phase 为 active 时提供的 `activeGoal`，以及 `priorTaskFrameConstraints`。提示区分任务相关性与持续有效的安全、权限、精度和原文件约束，没有调整阈值或缓存保护。

固定五次请求对照使用已有合成浏览器证据、模型 APUS-OpenJev-v1-9B-5949、high effort 和不变的 0.9/0.1 阈值，无重试。包含 v2 失败在内的全部请求和响应保存在[对照记录](context-v3-priority-comparison.json)。

| 探针 | 观察结果 |
| --- | --- |
| 原始恢复 v2 | 必需旅行片段 f1 得分 0.033086，未恢复。 |
| 相同片段、v3 任务角色 | 必需旅行片段 f1 得分 0.998499，选择恢复。 |
| 财务删减 v2 | 必要金额片段保留。 |
| 财务删减 v3 | 必要金额片段保留，仅选择旧旅行正文。 |
| 先约束后开始的有序请求，v3 | 必要金额片段保留，较早约束仍可用。 |

无密钥回归覆盖同批有序要求、话题回退、活跃与暂停 Goal、继承原文件保护与 Decimal 约束、请求预算，以及从持久事件重新创建全新 Host 上下文后的恢复。既有缓存前缀测试保持不变，上下文实现定向覆盖率四项均为 100%。

这些证据限于语义探针和确定性 Host 回归。后续 [Host16 浏览器验收](browser-context-v3.json)已通过恰好六次读取的财务任务，以及 Host 完整重启后首个主模型请求前的自动恢复，没有工具调用或旧持久化前缀变化。上下文 v3 的 TypeScript 刷新回放与 Python 录制回放也已在 Host16 通过；[汇总报告](context-semantic-validation.zh.md)记录了验证范围及保留的失败证据。v3 同时选择恢复了仅包含路径的归档片段；选择表示受限恢复，不代表每个返回片段都必需。
