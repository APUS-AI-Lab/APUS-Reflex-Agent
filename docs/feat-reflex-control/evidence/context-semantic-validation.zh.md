[v3 优先级对照](context-v3-priority-validation.zh.md)保留该失败，并对固定五次真实 API 请求进行无重试比较。分开当前用户请求与旧任务框架后，必要片段恢复得分升至 0.998499，同时保留必要财务金额，也覆盖先约束后开始的有序输入。这些是受限决策探针，不能替代浏览器验收。[首次 v3 浏览器验收](browser-context-v3-attempt1.json)使用 Host15，保留全部必要金额、移出旧旅行，并返回独立核验的合计 1137.41。原始文字与已提交缓存前缀保护通过。但主模型对已排除的旅行进行了两次无关记忆检索，效率检查失败。重启与自动恢复后半段尚未执行，不能将本轮算作完整通过。记忆工具说明调整后，已在 Host16 上用相同提示词、新 Session 复验。

[最终 Host16 浏览器报告](browser-context-v3.json)的前后两部分均通过。财务轮次恰好执行六次文件读取，没有记忆检索，保留全部必要金额、移出旧旅行行，并返回 1137.41。Host 完整退出并重启后，同一 Session 在首个模型请求前自动追加来源为 `reflex-memory` 的归档旅行文字，没有任何工具调用，正确回答四项事实：樱花小舍、抹茶松饼、09:20、京都站中央口。之前的 44 条持久事件和全部输入文件哈希保持不变。详见[财务截图](reflex-context-v3-finance.png)与[记忆恢复截图](reflex-context-v3-restored.png)。上文 v2 自动恢复失败与首次 v3 效率失败仍保留为验收证据。
