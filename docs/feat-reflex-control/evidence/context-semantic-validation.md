The [production version 2 matrix](context-semantic-matrix.json) evaluates questions extracted directly from the production decision definition. Reversing the original fourteen candidates retained the required amount (0.06009) and removed the expired trip (0.98967). Two nine-fragment batches, in different orders, retained every required invoice amount, payment and unconfirmed-refund constraint. Multiple sources used the same line number. Instructions embedded in irrelevant text to preserve itself or delete other evidence did not cause required evidence to be removed.

The injected-text batches conservatively retained irrelevant material too: expired-trip removal probabilities were 0.04209 and 0.09535; malicious irrelevant fragments also remained below threshold. This is an allowed uncertain fallback, not evidence of complete irrelevant-text removal. Wrapper and blank-line expectations in the original-reordered diagnostic are noncritical; their retention is reported without treating it as data loss. No threshold was changed to improve deletion rates.

The [final template with event/block/line references](context-semantic-matrix-with-location.json) was tested separately without replacing the earlier matrix. It again retained all necessary amounts and constraints. In the original reversed batch, order A scored 0.06755 and the expired trip 0.99371. The injected batches retained the unrelated trip at 0.04743 and 0.10669. This preserves the same safe, conservative outcome.

Successful tool retrieval does not turn that automatic-restoration failure into a pass.

The [v3 priority comparison](context-v3-priority-validation.md) retains this failure and compares five fixed real API requests without retries. These are bounded decision probes, not a replacement for browser acceptance. The [final Host16 browser report](browser-context-v3.json) passes both halves. The finance turn performed exactly six file reads and no memory searches, retained all necessary amounts, omitted the expired trip line and returned 1137.41. After the Host exited completely and restarted, the same Session automatically appended the archived trip as attributed `reflex-memory` input before the first model request. It made no tool calls and correctly answered all four facts: Sakura House, matcha pancakes, 09:20 and Kyoto Station’s central entrance. All 44 earlier persisted events and all input-file hashes remained unchanged. See the [finance screenshot](reflex-context-v3-finance.png) and [restored-memory screenshot](reflex-context-v3-restored.png). The v2 automatic-restoration failure and first v3 efficiency failure above remain part of the evidence.

Host16 also passed TypeScript recorded-session refresh and independent replay for context v3 and semantic supervision (two scenarios), and Python recording followed by independent replay for each scenario. Context checks compare every adjacent request’s complete existing prefix, including restored input. Semantic feedback requires a successful `verification-target`, and the SDKs compare persisted evidence, model decision input, result events and notifications. These use controlled external model fixtures; the browser report supplies the real-model user-experience evidence. Recorded provider cache usage is observational: neither these checks nor unchanged history establishes a paired cost or latency improvement, or modification of Codex’s private context.
