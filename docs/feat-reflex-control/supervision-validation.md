# Reflex supervision validation

The live tests use an isolated workspace and Codex home, a real Codex app-server process, the configured Responses relay, and the real Reflex model. Credentials are loaded from the local runtime environment and are not written to reports. Completion requires the native Codex `completed` result plus independent Python verification; a changed file alone does not pass.

The successful alternative-model run is an environment comparison; it does not establish reliability of the deployed default `gpt-5.6-sol-relay`. Its corresponding report is `/private/tmp/reflex-supervision-gpt6-diagnostic.natural.json`. Failed default-model reports remain at `/private/tmp/reflex-supervision-attempt2.fault.json`, `/private/tmp/reflex-supervision-attempt2.natural.json`, and `/private/tmp/reflex-supervision-attempt3.natural.json`.

The second fault report is `/private/tmp/reflex-supervision-gpt6-fault.fault.json`. The fixture now classifies actual `python3 verify.py` execution rather than any mention of its filename. Feedback also requires successful verification evidence before an overconfident Reflex response can become `improved`. Improvement remains distinct from independently verified task completion.

The natural-task runs exposed an overly broad intervention condition: elapsed time plus fresh read/file-change evidence could cause an unnecessary realign suggestion. Interventions now require repeated failures or repeated matching operation/result evidence. Elapsed time without that evidence still invokes Reflex and records inconclusive observation. This protects normal long model requests without making the observer blind.

Focused regression: the subagent service, Codex adapter, and supervision suites passed 130 tests. An additional session-restoration regression then brought the supervision suite to 41 passing tests. It checks that bounded evidence and Goal-wide intervention reservations replay identically after restoration. The final focused coverage gate measured both new supervision modules at 100% statements (255/255), branches (197/197), functions (48/48), and lines (204/204), without exclusions or threshold changes. Targeted oxlint and earlier System3 Host TypeScript checks passed. These checks do not establish exhaustive repository coverage.

A subsequent 150-second low-effort diagnostic observed the native app-server emit `userMessage` start/completion events containing the Reflex supervision marker at 98.7 seconds. Advice was therefore delivered into native Codex input, but the task still timed out before repair. The original fixture spent 60–85 seconds on its three deliberately separate failing tool calls; this budget is not a user-facing latency promise. A separately declared 300-second fault-scenario budget uses `REFLEX_SUPERVISION_LONG_TASK=1`, `gpt-6-sol-relay`, `model_reasoning_effort="low"`, and no artificial sleep. Natural-task tests retain their original budget.

The timing investigation found a product defect: an inconclusive assessment at the first feedback deadline discarded the intervention before later verification could arrive. The corrected implementation retains that intervention, assesses only after new evidence, and clears it at termination without another model request when the evidence has not changed. New successful verification can now produce a later improvement assessment. Real reports from this implementation carry `acceptanceRevision: feedback-reassessment-v2`; older reports are retained separately.

The first 300-second trial still aborted. Native Codex consumed the supervision message around 80 seconds and repaired the file at 181.8 seconds. A separate Python verification returned exit code 0, the verifier hash was unchanged, and the result exactly matched the expected file; these facts do not substitute for normal native completion. That trial ran the older feedback implementation. Its independent verification is preserved in the bounded [trial evidence](supervision-trial-evidence.json).

The final 300-second trial used the feedback fix and confirmed native reasoning effort `low`. Three failed commands finished at 81.8, 87.8, and 93.3 seconds. Automatic advice was acknowledged, but no native supervision `userMessage` appeared before cancellation, no repair occurred, and the run ended `aborted`. The absence of native activity after the third failure is consistent with a pending native model request; the report does not establish its internal cause. An accepted `turn/steer` request does not establish immediate consumption while a native model request remains pending. No further retries were performed.

Real repeated-failure acceptance through steer alone has not passed. The evidence distinguishes observer decisions, delivery acknowledgement, native input consumption, independently verified output, and normal completion. The natural alternative-model task passed; the steer-only fault scenarios above failed whole-test acceptance. The final report is `/private/tmp/reflex-supervision-gpt6-final300.fault.json`; the preceding long-task report is `/private/tmp/reflex-supervision-gpt6-long300.fault.json`.

The keyless `reflex-supervision` recorded-session scenario passes through the shipped SDK profile using real Goal, supervision, subagent lifecycle, session persistence, and SDK notification paths. Only external Codex execution and Reflex HTTP answers are fixtures. TypeScript refresh and replay, and Python built-runtime recording and replay, passed. Their generated snapshots preserve three failed verifications, attributed advice consumed by the provider, one successful verification, and `intent → accepted → improved`, while excluding automatic advice from human steer records. This deterministic coverage does not change the failed real-provider acceptance results.

The separate native-inactivity recovery scenario passed with the real Reflex API, package-local Codex app-server, and real remote generation. A loopback proxy deliberately holds the first model request. Reflex then authorizes interruption; the adapter waits for the interrupted terminal event and starts another turn in the same live thread. Codex writes the expected file, runs the verifier, and completes normally. Independent Python verification passes, and the expected-file and verifier hashes are unchanged. This tests a controlled transport stall, not an uncontrolled production outage or the steer-only repeated-failure scenario.

The final [v4 report](evidence/native-recovery-real-v4.json) and [test log](evidence/native-recovery-real-v4.log) record 127.41 seconds for the test, one recovery judgement, four ordinary evidence judgements, and `intent → continued` recovery receipts. V4 includes queued-action checks that reject stale native activity and stale human/Goal revisions. Earlier v2 and v3 reports remain as intermediate evidence. The reports retain their original metadata: their inherited `budgetMs: 150000` field was incorrect for this scenario; the executed abort budget was 180000 ms and the test timeout was 210000 ms. The report writer now records the scenario-specific budget; existing evidence has not been rewritten.

Deterministic tests separately cover unknown interrupt receipts, normal completion winning a race, cancellation, side-effect and approval waits, bounded retries, and suppression of unchanged observations. Successful native continuation does not itself set the parent Goal complete. Browser acceptance and each SDK projection have separate result records.
