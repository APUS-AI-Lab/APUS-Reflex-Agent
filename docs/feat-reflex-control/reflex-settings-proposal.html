命名约定

用户可见页面、菜单、按钮、状态和帮助统一使用 Reflex；专用页面名称为“Reflex 模型配置”。底层 Jev 协议、provider 包名、环境变量和服务返回的模型 ID 保持真实值，不进行破坏性改名。

已有基础与架构

当前 Jev provider 已有 endpoint、model、effort、timeoutMs、apiKeyEnv 配置和 credentials.resolve；已有 Web/Electron 共享专用设置页。复用现有 configForms、credentials 和 locale，不新增第二套明文密钥保存。

配置与接口约定（拟定）

操作输入与返回
读取有效配置返回endpoint/model/effort/timeout及credentialConfigured；不返回密钥。显示配置来源并明示部署锁定字段。
更新配置通过现有Host配置命名空间校验持久化；密钥只走现有credentials写入。当前请求保持已解析配置，新请求使用保存后配置；完整重启后的真实请求继续使用保存值。
连接测试无破坏地检查健康、鉴权/模型目录，再发一个无用户内容的简单noul判断；返回分阶段状态、latency、模型及effort。失败不静默修改有效配置。
能力状态分别返回implemented、enabled、verifiedAt、lastOutcome；配置成功不把未实现能力标为已启用。

拟修改文件范围

  • packages/experimental/apus-dsh-jev-plugin：现有provider配置桥、脱敏状态与有限测试接口。
  • packages/experimental/client-ui-system3 或单独的 ui-settings-jev companion：共享设置页、typed locale和现有设置slot注册，按责任确定最小归属。
  • packages/experimental/system3：只投影实际能力配置和状态，不增加纠偏/记忆实现。
  • apps/cli/config 与 Frontend runtime装配：注册页面与Host namespace，明确部署值和用户设置优先级。
  • 对应README/API说明、类型与测试；Frontend更新固定Harness版本后重新装配验收。

E2E验收

  1. 从前端填写配置 → 一次真实判断成功 → 保存 → 新会话实际使用指定的 Reflex 决策模型。
  2. 错误key、错误模型、超时分别显示准确错误，不能显示连接成功；此前有效配置保持可用。
  3. 退出并重启后设置仍生效，密钥不出现在前端配置回包、localStorage、URL或日志中。
  4. Web与最终Electron包均有相同入口，显示服务连接状态与真实能力状态。
  5. 自动监督和按行上下文管理分别显示真实启用状态；连接测试成功不能替代对应能力的 E2E 验收。

本页保留初始设计约定；当前实现与证据以 验收清单 和 专家级验收报告 为准。
