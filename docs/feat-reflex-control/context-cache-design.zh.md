# 兼顾缓存的 Reflex 上下文设计

[English](context-cache-design.md) | 中文

本设计针对模型提供方的提示缓存，不是浏览器缓存。已提交前缀保护已实现；提供方成本与缓存基准仍待验收，此前浏览器验收不能证明这些指标。按行投影可能减少估算 tokens，却因为修改已发送历史而使请求更慢或更贵。历史删除和原位恢复都可能从第一个改动位置开始损失可复用前缀。

## 本地请求证据

[Agent-loop 架构](../architecture.zh.md) 描述了按尝试冻结请求、在支持的路由追加运行时上下文和明确的新请求序列。[DeepSeek 序列化](../../packages/llm/llm-deepseek/src/serialize.ts) 与[用量转换](../../packages/llm/llm-deepseek/src/translate.ts) 管理原生请求及 Anthropic 风格的缓存用量字段；序列化器没有暴露已确认的逐消息缓存边界。[pi-ai 适配器](../../packages/llm/llm-pi-ai/src/adapter.ts) 将配置中的 `cacheRetention` 和会话身份交给提供方实现，[目录兼容设置](../../packages/llm/llm-pi-ai/src/catalog.ts) 决定可用缓存控制。

已检查安装的 `@earendil-works/pi-ai` 0.85.1 中 `dist/api/anthropic-messages.js`、`openai-completions.js`、`openai-responses.js` 和 `openai-responses-shared.js`。Anthropic 序列化向系统内容和最后一个符合条件的用户块添加 `cache_control`，工具缓存受兼容设置控制。OpenAI Responses 从会话身份生成 `prompt_cache_key`，保留策略由兼容能力决定；OpenAI Completions 只在指定路由条件下添加该键，也可能为兼容路由设置 Anthropic 风格标记。Responses 用量读取 `input_tokens_details.cached_tokens`。这些是本地实现事实，不承诺服务器保留或驱逐行为。相同缓存键不能让修改后的内容继续复用。

[TokenUsage](../../packages/llm/llm/src/types.ts) 将 `inputTokens`、`cacheReadTokens`、`cacheWriteTokens` 定义为互不重叠的数量。[pi-ai 用量转换](../../packages/llm/llm-pi-ai/src/stream.ts) 省略零值缓存字段，因此字段缺失不能统一解释为不支持缓存或实测未命中。[计量器](../../packages/llm/token-meter/src/estimate.ts) 使用字符密度估算，不是提供方分词器。汇总缓存数量不能反推出具体行、消息、工具定义或服务器缓存断点。

## 默认行为与配置

默认强制保护已提交前缀，不提供允许编辑冻结历史的普通上下文配置。凡可能已通过生成请求传输的内容全部冻结。超时或响应丢失不能证明服务器没有收到请求。发送时冻结，不等成功完成。已有语义阈值和请求预算仍由部署配置控制。

可编辑尾部只包括当前路由时期内从未发送的投影文本块；这是本地已知的提交边界，不是服务器缓存边界。对模型生成的助手文本也保守处理，因为提供方可能在内部保留它。首版尾部候选因此限于尚未发送的工具结果和不存在模型生成歧义的旧非约束用户文本。最新用户意图、Goal、当前约束、结构与工具配对始终保留。没有有效尾部候选时跳过 Reflex 请求，不为必然无操作的判断付费。第一次发送前完成语义选择，之后冻结结果内容。

不要向稳定前缀插入变化的时间戳、省略计数、动态说明或新工具定义。记忆工具定义应稳定加载，不能第一次删减时才切换启用。保留消息顺序、角色、已序列化的 ID、工具顺序和参数、系统文本、推理签名、缓存标记位置及适配器序列化身份；最后一组由适配器管理，不由 System3 管理。路由、模型、工具或系统变化使缓存连续性不明确，不授权任意重写旧历史。

恢复冻结的已省略内容时，向新尾部追加已记录且有来源的 `reflex-memory` 原文，不替换已发送的省略标记。尚未发送的省略仍可原位恢复。对已可见事实、同次决策的重复片段，以及等待上下文接纳的工具恢复去重。待接纳记录在取消、上下文替换或投影、步骤或轮次结束时失效；接纳后根据可见记录去重。在当前任务中保护恢复的事实，保留原事件、文本块及行引用。必要信息即使增加 tokens 也必须恢复。

上下文压力不授权静默改写历史。历史压缩必须走既有明确的新请求序列或 compaction 机制，记录前缀重建，并如实表述为缓存重建，而非保持缓存的删除。必要改写统一成一批，不在多次请求中连续进行细小历史编辑。未知路由容量不能作为自动改写依据。本次不新增自动压力批处理配置。

## 拟议 API 与持久化状态

最小实现不猜测缓存边界，也不改适配器：通过 `llm/stream` 观察普通 loop 请求，在进入传输前同步记录 `reflex/context-cache-anchor`，字段为 `version: 1` 与 `throughSeq`。状态投影冻结该序号及以前的全部原始消息，不区分路由。生成的助手文本也保守冻结。辅助调用不会解冻或改写历史。锚点不含用户内容，不改变模型可见历史，必须在调用中断后保留，并支持脱离运行会话的重放。

恢复会话时根据锚点重建保护。没有锚点但存在请求或助手记录的旧日志，保守冻结现有历史。进程重启或路由变化不代表缓存已冷。最后冻结位置之后的新工具结果可在下一 pre-step 审查。部署的 `protectRecentMessages: 4` 仍生效：单个最新工具结果受到保护；一批五个结果节点可使第一个结果成为候选，且不改变工具调用与结果的配对。流开始后，任何异步判断都不得修改请求；继续保留 Goal、输入和当前上下文的失效检查，以及任务卡准备等待机制。冻结内容恢复通过已有日志输入机制追加有来源文本。

以后可增加由提供方管理的精确请求指纹及断点观测，但实施这一保守禁令不需要它。不得导出猜测的 `cachedThroughSeq`。工具或系统变化仍由原有机制管理；本能力保证 Reflex 不改变已提交内容，不保证独立的序列化或部署变化永远不损失缓存。新增锚点同步更新持久化声明和两种 SDK 预期输出。

## 成本与延迟验收

逐路由、逐请求记录真实的互斥用量、首个生成输出延迟、总延迟、Reflex 判断延迟及用量，以及重试或压缩开销。使用可信路由价格时，输入成本为 `uncached × uncachedRate + cacheRead × readRate + cacheWrite × writeRate`；分别报告输出和 Reflex 费用，再报告完整任务总额。未知价格或缺失用量保持未知，不算零。仅在数量完整时报告命中比例 `cacheRead / (uncached + cacheRead + cacheWrite)`，同时保留缓存 token 绝对量，避免缩短提示掩盖复用损失。

使用相同提供方、模型、effort 和工具定义，对比无投影、旧逐行改写和前缀保护三组匹配多轮任务。覆盖冷启动与重复前缀预热、稳定长上下文、追加大型工具输出、必要历史恢复、压力批次、路由切换和重启。用独立会话或提供方支持的隔离防止策略间互相预热；随机顺序，多次配对运行，保留所有失败。批次首个请求和后续复用分开统计，要求完整任务成本与延迟证据，不能只展示一个更短请求。测量前不声称普遍改善。

确定性验收核对 DeepSeek、Anthropic、OpenAI 路径序列化前缀完全相同，工具定义和缓存标记稳定，只删除尾部，冻结恢复只追加，未知缓存状态保守，以及有失效保护的单次压力改写。补免密钥会话与两种 SDK 快照、区分字段缺失和明确零值的提供方用量测试，以及有付费凭据时的真实缓存基准。现有 `-33/+33` 估算快照只证明投影计量，不能满足此验收。

## 文件职责

最小保护修改 System3 状态和选择，以及会话持久化声明与目录，不改写适配器或核心循环。详细的提供方缓存分析和压缩基准属于独立后续工作。补适配器序列化测试，并在当前 worktree 文档和证据目录保存专用缓存基准。同步包双语文档和 schema。不得为了得到好看的测量而修改提供方缓存保留默认值或重写第三方源码。
