# Cache-aware Reflex context design

English | [中文](context-cache-design.zh.md)

This design addresses provider prompt caching, not browser caches. The submitted-prefix protection is implemented; provider cost/cache benchmarks remain pending and earlier browser acceptance does not establish them. Current line projections can reduce heuristic tokens while making requests slower or more expensive by changing previously submitted history. Both historical removal and in-place restoration can invalidate a reusable prefix from the first changed position onward.

## Local request evidence

[Agent-loop architecture](../architecture.md) describes frozen per-attempt requests, appended runtime context on capable routes, and explicit new request series. [DeepSeek serialization](../../packages/llm/llm-deepseek/src/serialize.ts) and [usage translation](../../packages/llm/llm-deepseek/src/translate.ts) own the native request and Anthropic-style cache usage fields; the serializer does not expose a confirmed per-message cache boundary. [pi-ai adapter](../../packages/llm/llm-pi-ai/src/adapter.ts) passes profile `cacheRetention` and session identity into the provider implementation, and [catalog compatibility](../../packages/llm/llm-pi-ai/src/catalog.ts) determines available cache controls.

The installed `@earendil-works/pi-ai` 0.85.1 implementation was inspected at `dist/api/anthropic-messages.js`, `openai-completions.js`, `openai-responses.js` and `openai-responses-shared.js`. Anthropic serialization adds `cache_control` to system content and the last eligible user block, with tool caching controlled by compatibility. OpenAI Responses derives `prompt_cache_key` from session identity and supports retention through compatibility; OpenAI Completions adds that key only under its route conditions and may apply Anthropic-style markers for compatible routes. Responses usage reads `input_tokens_details.cached_tokens`. These are local implementation facts, not promises about server retention or cache eviction. Identical cache keys do not make changed content reusable.

[TokenUsage](../../packages/llm/llm/src/types.ts) treats `inputTokens`, `cacheReadTokens`, and `cacheWriteTokens` as disjoint quantities. [pi-ai usage translation](../../packages/llm/llm-pi-ai/src/stream.ts) omits zero cache fields; absence therefore cannot universally mean either unsupported caching or a measured miss. [The meter](../../packages/llm/token-meter/src/estimate.ts) uses character-density estimates, not a provider tokenizer. Aggregate cache counts cannot be mapped back to exact lines, messages, tool definitions or server cache breakpoints.

## Default behavior and configuration

The default is mandatory submitted-prefix protection. There is no ordinary context setting that permits editing frozen history. Freeze all content in any possibly transmitted generation request. A timeout or lost response does not prove the server never received it. Freeze on dispatch, not on successful completion. Existing semantic thresholds and request budgets remain deployment settings.

The editable tail consists only of current projected blocks never transmitted in that route epoch; this is a locally known submission boundary, not a known server-cache boundary. Treat generated assistant text conservatively because providers may internally retain it. Initial tail eligibility is therefore unsubmitted tool-result text and older admitted non-constraint text with no provider-generation ambiguity. Always preserve the newest user intent, Goal, current constraints and structural/tool pairing. If no useful eligible tail exists, skip the Reflex call rather than pay for an unavoidable no-op. Apply semantic selection before first transmission and freeze its resulting bytes afterward.

Do not insert moving timestamps, omission counters, dynamic notes or new schema descriptions into a stable prefix. Load the memory tool schema consistently rather than switching it on when omissions first appear. Preserve message order, roles, IDs where serialized, tool order and parameters, system text, reasoning signatures, cache-marker placement and adapter serialization identity. The adapter, not System3, owns this last group. A route/model/tool/system change marks continuity uncertain; it does not authorize arbitrary rewriting of all old history.

Restoring frozen omitted content appends a logged, attributed `reflex-memory` excerpt to the new tail. Do not replace a previously transmitted omission marker. Before transmission, an unfrozen omission can still be restored in place. Deduplicate already visible recovered facts, repeated fragments within one decision, and tool recoveries awaiting context admission. Pending tool recovery expires on cancellation, surface replacement/projection, or step/turn settlement; admission transfers deduplication to the visible transcript. Protect recovered facts for the current task; retain original event/block/line references. Restore necessary information even when adding it costs tokens.

Context pressure does not authorize silent historical rewriting. Historical compression must use the existing explicit new-request-series/compaction mechanism, record that the prefix is rebuilt, and present it as cache reconstruction rather than cache-preserving deletion. Coordinate a necessary rewrite as one batch; do not make repeated small historical edits across requests. Unknown route capacity cannot justify an automatic rewrite. No automatic pressure-batch config is added by this change.

## Proposed API and durable state

The minimal implementation needs no guessed cache boundary or adapter rewrite: an ordinary loop request observed through `llm/stream` synchronously records a `reflex/context-cache-anchor` with `version: 1` and `throughSeq`, before reaching transport. The state projection freezes every original message at or before that sequence, irrespective of route. Generated assistant text is also frozen conservatively. Auxiliary calls do not unfreeze or rewrite history. The anchor contains no user content and does not change model-visible history. It must survive interrupted calls and detached replay.

On resume, anchors rebuild protection. Legacy logs without anchors but with request/assistant evidence conservatively freeze existing history. Do not infer a cold cache from process restart or changed routing. New tool-result text after the last frozen position can be reviewed at the next pre-step. The deployed `protectRecentMessages: 4` still applies: a single latest tool result is protected; a batch with five result nodes can expose the first result for review without changing any call/result pairing. No awaited decision may mutate a request after streaming begins; retain Goal/input/surface fencing and the task-frame preparation barrier. Frozen restoration appends attributed text through the existing logged input mechanism.

Future provider-owned serialization observations may measure exact request fingerprints and breakpoint metadata, but are not necessary to enforce this conservative prohibition. Do not export a guessed `cachedThroughSeq`. Tool/system changes remain owned by their existing mechanisms; this feature promises that Reflex does not alter already-submitted content, not that independent provider serialization or deployment changes can never lose cache reuse. Update persistence declarations and both SDK expectations for the new anchor.

## Cost and latency acceptance

For each route and request, record actual disjoint usage, time to first generated output, total latency, Reflex decision latency and usage, and any retry or compaction cost. With trustworthy route prices, input cost is `uncached × uncachedRate + cacheRead × readRate + cacheWrite × writeRate`; report output and Reflex charges separately, then the complete task total. Unknown prices or absent usage remain unknown, not zero. Cache-hit share is reported only when counts are complete: `cacheRead / (uncached + cacheRead + cacheWrite)`. Also retain absolute cached tokens so shorter prompts cannot disguise lost reuse.

Compare matched multi-turn tasks under no projection, legacy per-line rewrite, and preserve-prefix policy, using the same provider/model/effort/tool schemas. Include cold-start and warmed repeated-prefix runs, stable long context, appended large tool output, required history recovery, pressure batch, route switch and restart. Separate sessions or provider-owned isolation prevent cross-policy warming; randomize order and repeat paired runs. Preserve every failure. Measure first batch request and subsequent reuse separately; require whole-task cost and latency evidence rather than a single shorter request. No claim of universal improvement is made before those measurements.

Deterministic acceptance checks exact serialized prefix identity on DeepSeek, Anthropic and OpenAI paths; stable tool/schema/marker placement; tail-only deletion; append-only frozen restoration; unknown-cache conservatism; and a single pressure rewrite with revision fencing. Add keyless session and both SDK snapshots, fake-provider usage tests that distinguish absent from explicit zero, and real-provider cache benchmarks with paid credentials when available. Existing `-33/+33` heuristic snapshot deltas establish projection accounting only and cannot satisfy this acceptance.

## File ownership

The minimal protection changes System3 state/selection and session persistence declarations/catalog, with no adapter or core-loop rewrite. Detailed provider-cache analytics and compaction benchmarking are separate follow-up work. Add adapter serialization tests and a dedicated context-cache benchmark under the worktree documentation/evidence directory. Update bilingual package documentation and schemas. Do not modify provider cache retention defaults or rewrite vendor code merely to force favorable measurements.
