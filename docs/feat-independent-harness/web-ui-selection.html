界面负责呈现，DSH 负责执行

工作台输入用户问题、自动或固定意图
→
DSH 原生准入会话、取消、队列与权限
→
Jev 有界判断合法候选、选择或弃权
→
原生模型执行System2 经 Fidoo 生成

会话日志向工作台返回三类事实：system3/entry-decision 是建议，model/automatic-selection 是采用记录，request/header 是准备调用的模型配置。header 在模型流开始前记录，执行结果还需结合模型输出、错误或取消状态，不能把“Jev 选了 Pro”直接显示成“Pro 已执行”。

关联需从决策 requestId，经 user/message.source.rpcId 定位输入，再按 turn/step 找到对应 header；header 本身没有 API requestId。缺失的记录需要等待补档或显示未知。

目前自动入口仅覆盖空闲、无待处理输入、无人工固定选型的 Web/API 文本请求。路由期间的取消与失败由宿主处理。UI 读取持久事实，刷新、重连和回放不得再次调用 Jev。

当前入口验收 · 原生准入实现

任务看板不等于 System3 调度

核查路径对 Jev 的影响接入要求
普通看板任务调用 session/prompt源码路径可到达现有入口；仍需满足空闲、文本、无固定选择等条件。实测建议、采用、请求配置及模型响应一致。
任务指定模型，先调用 session/selectModel被视为人工固定选择，自动入口跳过 Jev。保留用户固定意图，另设明确的自动策略。
Team 成员、Goal 自动续轮不经过同一文本准入路径，首片没有覆盖。分别设计适配与回放，不能宣称安装即覆盖。
看板标记 succeeded包含回合结果与 Goal 状态判断，但不是独立任务验收。区分回合完成、目标暂停、结果未知和验收通过。

核查的 dev 实现会在 Goal 暂停、缺失或投影读取失败时回退到回合结果；因此卡片完成状态不能直接成为我们的长程 Goal 完成证据。

源码依据：任务准入与结果判定、Team 调用。此处为源码审计，非跨版本运行验证。

建议的交付顺序

  1. 先做可读的决策卡。在原生会话显示建议模型、是否采用、请求模型、执行状态、弃权或失败状态及耗时。展开查看候选与分数；分数不得标成成功率。
  2. 补自动／固定模式操作。当前人工选模后需要新建会话才能恢复自动。应先补宿主状态操作、持久记录与恢复语义，再提供 UI 开关。
  3. 隔离试装社区布局。先验证 DSH Codex UI；需要 dsh-web 的具体模块时再选择匹配版本。每项验证通过后纳入可选组合。
  4. 再接任务与长程目标。看板、记忆和主动沟通复用同一任务身份、执行事实与授权，不产生另一套竞争路由。

Open WebUI 支持 OpenAI 兼容 API 与本地模型，适合独立多模型聊天。但直接连接 Fidoo 只连接生成模型；要呈现 DSH 的会话、审批、工具和 Jev 采用记录，还需适配层。本项目现阶段优先复用已有原生工作台。Open WebUI 项目说明。

首个 UI 切片：文件、接口与验收设计

目标：用户能在原生会话中确认本次请求由谁判断、谁执行，以及是否发生降级。此切片只读展示，不改变现有选模策略。

建议文件：packages/experimental/system3-ui/ 放可选的客户端事件解释器、卡片、双语文案及行为测试；docs/feat-independent-harness/ 放组合配置与使用说明。具体包结构以实现前的 Host/Client 类型审查为准，实验包不进入默认 CLI 生产依赖。

接口：消费现有 Session 事件与投影，通过原生 Conversation definition 和 conversation.chat.node slot 呈现。记录缺失显示未知或等待确认；只有完整已结算区间的证据才能判断未采用。不得推断不存在的解释、费用或执行成功。自动模式 API 属于下一切片。

验证：关联不同请求、建议未采用、provider 失败、弃权、采用后取消、实际请求、重连与冷回放；打开页面不能发送新决策请求。补无密钥会话快照和浏览器交互，检查 390px 布局、键盘操作、双语、审批与工具卡不回归。社区插件另测版本匹配及卸载后恢复。
