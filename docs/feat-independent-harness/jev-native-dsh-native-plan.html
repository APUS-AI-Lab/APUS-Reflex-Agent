第一目标：入口选对处理路径。第二目标：执行环节更智能、更顺畅。

System3 = System1（Jev-like 决策模型）+ System2（高性能推理与生成模型）。核心方向是让 Jev 智能决策融入整个 DSH：用户输入后先判断处理策略，将工作交给适合的模型或专业 Agent；执行中再根据真实结果调整能力、记忆、策略和跟进。两个目标共享原生状态与决策机制，按入口优先、过程增强的顺序实施。

Jev 判断策略，DSH 管理并执行调度，System2 完成推理与生成。入口决定如何接手，过程判断如何继续；记忆、路由、任务归属和结果反馈贯穿两者。本仓库已有 Jev 类型接口与显式影子记录，自动入口调度和过程协同尚待实现。本地 9B／27B Lead Agent 是未来部署演进。

1. 两个目标，一条 Jev Native + DSH Native 主线

第一目标是入口决策与调度：用户提出问题后，依据任务语义、当前目标和允许能力，选择本地处理、高性能模型、专业 Agent、先规划或先澄清，让第一次有效执行进入合适路径。

第二目标是过程智能与顺畅协作：在执行中选择必要记忆和能力，识别停滞、恢复失败、调整分工和跟踪目标，减少重复解释、无效切换和反复试错。两者都使用 DSH 的原生事实、受约束动作与结果反馈。

Jev 承担“规则覆盖不了、完整生成又太贵”的有界语义判断。明确用户选型、唯一可行路径和精确预算继续由规则处理；复杂规划和参数生成由 System2 承担。入口优先决定交付顺序，过程协同决定架构的扩展方式。

架构特点具体机制如何证实
原生事实供给从 DSH 当前目标、会话、工具结果和任务状态形成有界输入，附版本及可恢复证据；不靠模型猜测执行状态。一次判断能重建当时看见的事实，不能只保留摘要标签或哈希。
分配判断成本规则处理确定情况；Jev 选择、评分或判断有限命题；System2 处理开放规划、复杂推理与生成。与同输入、同候选的规则和大模型决策对照，包含候选生成、失败及回退成本。
原生动作采纳由能力所属服务检查并应用决定，例如选择后续证据、调整策略或委派；保持单一动作拥有者。记录建议、实际采用与拒绝原因，确认判断真正改变后续执行。
结果反馈可评测把决定关联到实际产物、后续工具结果及独立验收，用于下一步判断和离线评估。观察任务成功、错误完成、返工、总费用和端到端延迟；记录结果不等于已经实现自动学习。

Jev Native 指保留原生结构化判断能力和明确弃权路径；DSH Native 指沿用其会话、生命周期、服务装配与执行机制。Cordis 插件是 DSH 内部的模块组织方式；新的决策消费者直接参与原生流程，不迁入 Pilot 的宿主钩子、代码或另一套状态机。

2. 第一目标：用户输入后的策略决策与调度

入口先判断“采用什么处理方式”，再落实模型、推理投入或专业 Agent。Jev 从 DSH 提供的有限候选中选择；候选包含已测能力、输入模态、上下文容量、权限范围、可用性和成本信息。Jev 自身处理输入也必须满足该数据的使用范围，不能先外发给路由模型再判断隐私。

用户输入进入 DSH 原生接收端
→ 标识请求，关联当前目标、任务负责人和必要上下文
→ 规则保留用户显式选择，过滤不允许或不具备能力的路径
→ 有语义取舍时，Jev 选择处理策略；确定情况直接采用
→ 校验请求与目标版本、候选可用性、输入模态、容量和预算
→ DSH 记录采用结果，按所选路径组装请求或创建委派
→ 执行结果回到同一任务；第二目标在有新证据时调整后续策略
处理策略适用情况DSH 如何执行
沿用当前／本地处理当前能力足够，或用户只是继续已有任务。保留上下文与任务归属；未来可由通过验证的 9B／27B 承担。
高性能模型处理需要更强推理或生成，原有任务执行方式仍适用。为该任务采用允许的 provider、model 与推理投入；上下文、工具与容量保持一致。
专业 Agent 委派需要专业工具、工作流或领域能力。使用原生子代理能力交付任务、必要上下文及验收要求；保留父任务、取消关联与结果回收。
先规划，再分配任务过于开放，现有候选不足以直接执行。由合适的 System2 形成计划和候选，再进行有界分配；Jev 不生成完整执行计划。
先澄清或补证据缺少用户才能决定的条件，或需要低成本检查才能判断。由生成模型或交互机制组织具体问题／检查；保留任务，得到答案后重新判断。

入口使用轻量记忆，确定路径后补充工作上下文

Jev 不只看最新一句话。“继续”“按刚才的做”需要当前目标、已选策略、负责人和必要事实。入口先取有界、允许访问的相关片段，不以大模型完整理解一遍任务作为常规前置步骤；选定路径后，再为执行模型组装足够的专业上下文。缺少信息时允许一次有预算的补证据，避免无限路由重试。

任务连续性与路由稳定性

入口和过程消费者共用任务身份、输入身份、目标版本、已采用策略及候选版本。默认延续当前负责人；新任务、明显能力不足、用户调整目标或重要新证据才触发重选。进入模型请求后固定该次选择；后到建议留待合法的后续步骤，不能改变已经发出的请求。设置可配置的重评频率、切换条件和回退上限，避免模型间来回跳转。

自动任务选型与用户默认设置分开。模型切换保留当前任务；专业委派产生有父子关系的子任务。两者都记录实际动作，不能仅记录“建议调用某专家”就声称完成交接。用户显式固定的模型优先；该模型不能处理时说明限制，不静默改为另一条路径。

首片的有效期：自动选型绑定本次输入触发的一个回合，该回合内工具续步可以沿用；回合结束或取消后，不能凭旧请求头自动续期。下一次输入重新准入，规则可选择延续合适路径，先前自动选择不等于用户固定选型。用户显式约束单独记录；跨回合任务级策略在后续阶段通过任务身份、目标版本与到期条件扩展。

原生接入：可复用机制、首批范围与真实缺口

首批建议：共享 System3 决策服务加 Web/API 的服务端入口适配，先验证空闲、无在途或待处理输入的文本任务，在消息入队前完成决策。先接两个输入／工具能力兼容且经过验证的模型；专业委派、澄清和其他运行入口在同一第一目标内分批完成。不是在前端或外部代理中另建一套调度。

现有 session-controller.prompt() 负责请求去重、附件准入，再调用 followup() 或 steer()。内部 selectForNextRequest() 可记录会话的 model/selection，installModelSelection() 在提示词组装时捕获选择，并让模型请求使用相同选择。复用这些机制时，需要共享决策服务和入口适配，不能跨包直接依赖 API 私有 controller。

现有 selectModel() 命令还保存用户默认模型，不能直接拿来执行自动任务路由。选定路径之后要按实际模型检查附件模态和最终上下文容量；先按旧模型准入图片、再切到不支持图片的模型，会造成错误。

空闲不是事务：等待 Jev 时可能出现新输入、目标续轮或定时跟进。需要请求级准入保护、取消处理和采用前的身份／状态复核；选择记录与该请求交付必须有关联，交付失败或首个匹配请求尚未提交就取消时，应记录失效并恢复尚未消费的选择；一旦开始执行，不回写或撤销既有历史。执行缓存被消费与自动策略有效期是两件事，按采用记录分别处理。已有维护或串行机制不自动保证 inbox 没有新工作。

活跃任务的 followup 属于下一回合；steer 属于后续步骤，并可能与其他输入合成一批。直接写入会话级 selection.current 可能影响当前任务下一步，或被后来的请求覆盖。首片对这类输入沿用原生队列／引导行为，不自动改模；后续补“输入身份 → 最终认领批次 → 该批次选择”的关联与测试。

Web/API、headless、SDK 和 ACP 不是同一输入路径。每个适配都要接共享服务并验收，不能把 Web 入口支持声明为全 DSH 覆盖。纯模型选型可先复用现有机制；若需要同时改变 preset、工具或任务归属，单独定义消费者，不把 provider/model 字符串当作完整能力配置。

可进一步验证现有插件组合：同步收集 agent/inbox/claimed 的输入身份，在随后可等待的 system-prompt/assemble 中完成决策，使组装与请求一致。需检查监听顺序、无新消息的工具续步、非循环主动组装、多输入批次、取消、恢复和映射清理；只有这些试验暴露明确接口缺口，才评估最小核心扩展。

源码依据：Web/API 输入命令、会话内选模、组装与请求一致性、输入批次、headless、SDK、ACP 选模。

入口效果看最终任务能否由合适能力完成，同时看错误分流、重复交接、首次有效响应延迟和总费用。Jev 的判断质量与实际部署延迟都需要实测；输出短并不能证明入口等待值得。

3. 入口与过程共享的原生决策机制

每个决策点遵循同一分工：会话记录事实，状态投影提供当前视图，工具和子代理承担动作，模型选择服务持有实际路由，目标服务管理续轮。新增记忆与任务账本应使用这些原生机制，不导入 Pilot 的代码、宿主钩子或外部状态库。

原生执行节点产生决策机会
→ 所属能力提供当前事实、任务版本和可执行候选
→ 规则排除不合法路径；确定情况直接处理
→ Jev 对剩余语义问题返回选择／评分／命题判断，或弃权
→ DSH 校验输出、目标版本、权限、容量、预算及取消状态
→ 所属服务采用动作；生成与工具执行仍走原生流程
→ 记录实际结果与独立验收，供后续决策和评测使用

候选来自注册能力、检索结果、确定规则或 System2 的开放规划。Jev 不凭空生成复杂行动参数；候选不足时，补证据或请求规划，不能用高分掩盖没有可行解。超时、无效输出、状态过期或弃权走有界回退；回退仍遵守本地范围、权限和原预算。

执行时序与扩展限制：为什么不能随意加一个钩子 
认领当前输入 → 组装提示词与工具 → 步骤准入（agent/pre-step）
→ 选择并准备模型请求（agent/request）→ 提交已接受输入 → 冻结请求历史
→ 生成模型输出 → 工具执行与结果提交 → 当前步骤结束
→ 下一步，或回合结束前检查（agent/turn-stopping）
原生机制设计约束
会话日志与状态投影进入 Jev、主代理或专家的模型可见信息必须有可重建记录。原始证据、记忆召回和实际采纳动作分别留痕；摘要或哈希不能替代全部事实。
步骤准入与请求选择现有准入发生在提示词／工具组装之后，请求选择也没有本批尚未提交的全部输入。入口首片先在入队前决策；过程集成需验证组装时序，不把该接口当成任意联合改写工具与路由的入口。
工具结果提交逐工具同步调用 Jev 会阻塞有序提交并可能只看到半批结果。轻量收集事实，在完整批次后的受控时机再做语义判断。
模型选择与上下文压缩保持单一选择拥有者，用户显式选择优先。换小窗口模型前需校验最终输入容量，处理压缩、重试和有界回退，不能只替换模型名称。
专业委派与工作流用原生子代理和工作流接口，保存任务身份与输出；现有运行事件不是完整的跨会话持久任务账本。
目标与提醒已有同会话续轮和提醒，不代表离线任务宿主。未来后台续行必须有明确的授权与恢复规则。

入口与过程都复用相同的候选、版本检查、预算及采用记录。消费者只拥有自己负责的动作，模型选择由单一拥有者提交；规则、入口 Jev 与过程 Jev 不各自维护一份竞争的路由。先验证现有入口及插件组合，只有具体用例无法可靠表达时才评估核心扩展。

实现人员参考：决策输入、返回与采用记录

Jev 保留原生 /v1/systemone：输入状态与问题，输出 Choice（选择）、Score（有序评分）、Noul（命题判断）。参数和响应需类型校验；概率使用前需校准。DSH 负责候选准入和实际动作，不把聊天回答临时解析成执行授权。

决策输入：决策身份、会话／任务身份、触发环节、目标与候选版本、证据、允许候选、权限与资源限制
判断记录：实际请求内容与可恢复证据、候选标识、模型版本、选择／评分／命题判断或弃权、用量与耗时
采用记录：规则／Jev／System2 判断 → 输出及状态校验 → 已采用／拒绝／过期／有界回退
结果关联：任务产物、后续会话事件、独立验收与实际沟通投递状态

通过 dsh 运行配置与 Cordis 组合原生服务：Jev 接口、主代理配置、任务与记忆服务、决策消费者、专业代理提供者。插件是 DSH 内部组织方式，不是外挂另一套主循环。初期不因图示拆出大量空包；记录类型变更需同步相关 SDK 和会话快照。

源码依据：原生架构、代理执行循环、模型选择、目标服务、目标续轮、提醒、工作流、持久存储、历史查询。

4. 第二目标：执行环节更智能、更顺畅

入口选定处理路径后，以下六类过程判断帮助持续推进。仅在完整结果、重要阻塞、目标变化或阶段交付时触发需要的判断，避免每个工具都同步等待 Jev。下表尚未自动运行。每类都需要独立验证，不能因为模型支持同一种输出格式，就默认所有场景同样可靠。前两列定义问题，后两列决定能否形成真实产品能力。

环节与判断依据Jev 原生判断DSH 原生消费者收益条件与限制
能力与场景策略
子目标、已准入工具／技能／工作流候选、适用前提和代价。		Choice 选下一能力或阶段；Score 评估适用性。能力配置、技能与工作流所属机制；记录下一步策略，原有工具执行器落地。候选需要语义取舍才调用。开放规划和参数生成交给 System2；当前 pre-step 晚于工具组装，不能声称可在此任意裁剪工具。
记忆与上下文
当前任务、候选片段、来源、时间、范围及剩余上下文容量。		Score 相关性；Choice 选应补读的材料；Noul 提示待核实冲突。上下文组装和未来记忆服务，按记录注入已选片段；原文可恢复。召回结果确有歧义时才有价值。不得覆写持久历史、把推断写成事实或绕过可见范围。
执行中的升级与重新分配
入口已选策略、新增证据、能力不足、候选成本／容量及用户约束。		Choice 选允许模型、推理投入或委派路径；不确定则弃权。现有 model-selection 或 subagent／workflow 所属消费者，按操作种类分别处理。必须检查请求容量、压缩、重试和授权；专业代理接入并不等同于替换聊天模型名称。
执行恢复与证据选择
完整结果批次、错误语义、既有尝试、增量证据和合法检查候选。		Choice 选补读、检查或重规划；Noul 判断是否出现支持改换策略的新证据。下一次原生步骤的策略消费者记录并应用建议，由现有执行机制完成检查。在入口目标完成后，适合验证避免昂贵错误方向的价值。不得对半批结果决策，或每个工具同步等待网络判断。
长程目标与跟踪
目标版本、阶段验收、产物、实际进展和阻塞。		Score 有证据支持的进展等级；Choice 继续、补证据或调整策略。goal 与续轮消费者，更新允许的策略或提出待复核建议。完成依赖独立验收；暂停、轮次预算及恢复授权始终有效。不能用语义分数直接完成目标。
主动沟通
待解歧义、用户可回答的问题、继续执行代价、近期通知与偏好。		Choice 询问、继续或阶段汇报；Score 信息价值。interaction、模型上下文与未来通知消费者；System2 生成沟通内容，宿主按授权投递。只用于是否值得打扰的模糊情况；明确约定、必要授权和固定提醒由规则处理，不为每次中文回复调用 Jev。

唯一有效候选、精确预算、固定测试要求、明确权限拒绝和传输重试协议继续由规则处理。只有当判断可能改变动作、具备足够事实且潜在收益大于判断开销时，才进入 Jev 路径。深度融合由实际作用点和反馈来体现，不能按调用次数衡量。

“顺畅”的验收：减少用户重复解释、重复委派、无效换模、无增量重试和不必要打扰；切换后仍能恢复目标、上下文和验收要求。同步判断次数、附加等待和最终完成质量共同衡量，不能只看路由分数。

5. 记忆：连接入口理解与执行中的判断

记忆是主架构的一部分：为 Jev 与 System2 提供一致、可追溯的事实，避免重复探索和陈旧判断。先建立可撤销的基本语义，再按需要增加 Jev 判断。存储、会话历史、当前任务状态和长期记忆分别拥有职责。

信息层保存内容管理方式
会话事实真实输入、工具结果、模型回复与决策记录。复用 DSH 会话日志和状态投影；作为执行证据，不直接等同用户事实。
任务与目标状态负责人、子任务、里程碑、阻塞、交付物、验收与预算归属。在 DSH 中建立明确任务账本；与会话关联，不靠主代理反复复述维持。
长期记忆已确认偏好、项目约定、可靠知识及已验证经验。记录来源、适用范围、时间、版本、有效性与撤销方式；区分事实和模型推断。
本次工作上下文从上述信息选出的必要片段与恢复引用。有长度和权限限制，进入模型时留有可回放记录。

Jev 的可选位置：候选记忆相关性排序、重复或冲突提示、值得进一步确认的写入候选。规则可以确定的去重、权限、有效期与显式用户偏好不重复请求模型。对跨时间的事实冲突，Jev 只能提示，不能凭当前一段文字决定哪个历史事实应被永久覆盖。

最小实现：先支持少量有来源的偏好与项目事实、明确的检索和撤销接口；复用现有历史检索与存储。语义检索、自动归并和广泛经验提取按任务需要逐项加入。专业代理只收到完成子任务所需的记忆片段，结果不会未经筛选全部写成长期事实。

已有基础是会话日志、session-query 历史检索和类型化 storage；目前尚未实现上述完整记忆生命周期。主架构纳入记忆不等于宣布它已经完成。

6. 长程目标：明确“在推进什么”和“何时继续”

主代理长期维护目标、里程碑与阻塞；Jev 可辅助判断进展是否真实、策略是否停滞、下一阶段应选什么；DSH 拥有状态、续轮授权和执行机制。目标变更由用户意图驱动，不能为了适应模型能力悄悄缩小目标。

DSH 已有原生 /goal 相关服务与命令：目标状态持久化，修改通过版本比较拒绝旧更新；续轮驱动在活跃代理空闲且已授权继续时推进同一会话。可以在这个底座上增加语义进展判断，而不是另建一套竞争的目标状态机。

当前边界：每个会话只有一个当前目标；预算主要是续轮次数；重启、恢复或派生会话后，自动继续默认解除武装，需要明确恢复授权。提醒服务不自动唤醒关闭会话，工作流也没有跨重启的断点恢复。跨天后台自治需要持久任务、唤醒宿主、执行租约、去重、资源预算和恢复机制，必须单独实现。

长程目标管理采用事件驱动：完成一个阶段、出现新证据、遇到重要阻塞或达到约定复核时间，再判断下一步。避免每个工具结果都调用一次全局目标评估。继续、等待、请求信息、调整执行策略和完成是不同状态；主代理、专业代理和 Jev 均不能绕过暂停或预算限制。

7. 主动沟通：成为可靠的跟进者

主动沟通进入主代理职责，包括阶段进度、重要阻塞、需要用户选择的事项、约定时间的复核，以及结果交付。内容由主代理组织；在信息价值不明确时，Jev 可辅助判断是否值得打扰。明确的用户约定、关键错误和期限提醒优先走规则。

沟通层次可利用的基础需要补齐
当前会话内跟进会话事件、目标续轮与定时跟进。进展摘要、重要性规则、去重与可见展示；排入跟进不等于用户已经收到。
专业任务执行期间的进度任务或子代理运行事件。明确谁在主代理等待时汇总状态。现有工作流调用会阻塞父回合，不能默认主代理可同时继续生成沟通内容。
外部渠道主动通知本方案尚不依赖具体邮件或即时通信产品。用户授权的渠道、收件人、允许内容、频率、安静时段、投递回执、失败重试与撤销。
关闭应用后的主动跟进当前会话内提醒不足以完成。后台唤醒和持久通知执行机制；不借定时器重新授权已暂停的目标。

主动并不意味着频繁播报。系统应在状态实质变化时沟通，合并低价值进度，保留用户设置的暂停与频率选择。外部发送由 DSH 的授权与通知执行器决定；Jev 的“值得提醒”不能直接成为发送权限。本次只定义设计，不实际接入或发送外部消息。

8. 未来演进：本地 9B／27B 与 Lead Agent

本地模型是原生决策架构中的可替换部署角色，不是先建设完整 Lead 平台才能接入 Jev。System1／System2 描述计算分工，主代理／专业代理描述工作角色，两者不是同一分类。本地主代理使用通用生成模型，承担可胜任的推理与生成；更难的工作由高性能模型或专业代理承接。Jev 的决策角色与本地主代理分开，不因为它们都可能本地运行就视为同一个模型。

角色主要职责不能默认具备的能力
Jev 决策模型对有限候选做选择、评分、命题判断；辅助相关性、路由、停滞、下一策略与沟通时机判断。任意任务规划、长文本生成、工具执行授权、独立证明任务完成。接口支持不等于场景准确率已达标。
本地主代理
未来 9B／27B		理解用户意图，处理普通本地事务，整理任务与上下文，委派、追踪、汇总和沟通。仅凭参数量可靠拆解和验收所有难题。规划和验收本身困难时，也需升级到专业能力。
专业 Agent / 高性能模型复杂编码、调研、分析或领域任务；必要时协助主代理规划与复核；提交产物、证据和未解决问题。继承用户的全部记忆、权限与无限预算；改变总目标或凭自述直接关闭主目标。
DSH 原生宿主持久化状态，执行工具和委派，维护权限、取消、资源上限、生命周期与恢复；应用已通过校验的决定。目前已经拥有完整语义记忆、跨会话任务总账、离线唤醒或外部主动通知。

专业 Agent 不限定云端，也可以本地部署。初始主代理可使用已经验证过的生成模型；未来本地 9B／27B 达到相应门槛后逐项接管。模型部署与编排角色应可替换，避免将整个产品绑在某个未经验证的型号上。

未来任务流程可以是：本地 Lead 接到目标并整理必要记忆；DSH 形成合法路径，Jev 在存在歧义时判断本地执行、专业委派或规划升级；专业结果回到原生状态，Lead 跟踪进展、组织汇报。验收困难时也请求专业复核，不能只把执行外包、把规划与验收风险留给较弱模型。

9. 客观可行性与评审结论

能力工程判定不能跳过的验证
第一目标：入口策略与调度Jev 类型接口和原生选模基础可复用；共享入口服务、准入关联及各入口适配待实现。实际路径采用、任务成功、错误分流、首个有效响应延迟；活跃／排队请求不能串用策略。
第二目标：过程智能与顺畅协作已有生命周期、工具、子代理与目标机制；具体语义消费者与稳定切换待实现。减小无效重试、重复交接和用户重复解释；新增判断开销与失败代价要计入。
本地主代理处理限定事务模型提供者与工具机制可承载；9B／27B 实际表现未验证。工具调用正确率、指令遵循、隐私、完成证据及设备资源。
专业委派与结果汇总已有子代理和工作流基础，自动分配策略待实现。委派内容质量、取消与失败传播、实际结果采用、独立验收。
基本记忆与任务跟踪原生底座可复用；记忆语义与任务账本需要明确接口。来源、隔离、撤销、重复事件、陈旧状态、跨会话恢复。
活跃会话内长程目标已有持久目标和续轮，可分阶段增强。目标变更、暂停、预算、真实进展和验收。
跨进程自治与外部主动通知目前基础设施不完整，独立实施。唤醒授权、任务租约、恢复、去重、投递状态与用户可控性。

入口目标不依赖先验证某个本地型号。使用已知能力的模型建立路由，再分别测 Jev 的选择质量与本地模型能力。不能把“更多任务分给低成本模型”直接算作收益，必须以实际完成质量和总开销核算。

本地主代理的瓶颈可能是“规划和验收”，而不仅是任务实现。因此路由同时覆盖执行、规划、复核三类升级。若本地模型需要频繁向专家重新解释任务、修正计划或补读材料，本地优先可能增加总成本；这种结果应促使调整分配策略，而不是强行保留本地路径。

Jev 只在规则无法处理、证据足够且存在有效候选时介入。规则已经足够、只有一个候选、没有正确候选、信息不可观测、实际采用率低、质量下降或额外成本更高时，应跳过该决策调用。用户希望纳入记忆和路由，不等于每次读记忆和选工具都要请求 Jev。

Pilot 的实验教训与此前两轮评审

Pilot 仅为参考，不引入其插件能力和代码。其既有报告包含 18 次校准：Jev 辅助臂严格成功 4/6，另两臂各 5/6；仅两个完整可比样本，一例总 token 下降 16.21%，另一例增加 34.03%，耗时均增加。实际费用不完整；这些数字不能证明新架构收益。

该路径四次成功判断耗时约 4.9–5.5 秒，两次传输失败约 10 秒；这是部署路径观测，不是模型裸推理时延。新部署需实测，不能因为输出短就假设适合每步同步调用。

此前评审保留了原生分工，撤回了“首期必须改核心循环”的断言，并指出路由、压缩和重试的一致性问题。记忆与路由服务于原生决策主线；本地主代理扩展未来部署方式，不改变这些实现条件，也不要求所有能力同时上线。

10. 实施顺序与验收：入口第一，过程第二

先让入口能可靠选择并采用处理路径，再让执行过程逐步更智能、更顺畅。以下分片控制工程风险，不改变第一目标覆盖模型选择、专业委派及必要澄清的产品范围；固定路由的失败恢复试验安排在第二目标。

优先级／阶段交付重点验收条件
M1a：入口模型调度首片共享决策服务与首个 Web/API 服务端适配；空闲且无待处理工作、文本输入、两个兼容能力模型。Jev 在合法候选中选策略，原生选模负责采用；保留用户显式选择和规则回退。当前输入与实际请求路由对应；不改用户默认；超时、取消、重复输入、状态变化和过期建议可控。实测分流对任务成功、首个有效响应和总成本的影响。
M1b：入口策略完整与覆盖扩展补专业 Agent 委派、先规划与澄清路径；增加附件、活跃／排队输入的批次关联，并为 headless、SDK、ACP 逐项适配。任务归属、必要上下文、取消和回收完整；按实际模型校验模态／容量；各入口分别通过回放，不因首片可用就宣称全入口完成。
M2：过程智能与顺畅协作沿同一状态和决策机制，逐类接入记忆相关性、能力选择、执行恢复、路由升级、目标跟踪和沟通价值判断。质量不退化，重复解释、无效重试、重复交接及路由震荡减少；有界调用不拖慢整体。错误完成仍由独立验收防止。
M3：本地模型与持续自治9B／27B 按能力接管本地事务、编排、跟踪和沟通；完善跨会话记忆、任务恢复。离线唤醒与外部通知独立交付。设备资源、工具调用和规划／验收升级达标；授权、去重、恢复、投递及暂停均有实际证据。

入口与过程分别评测

  1. 入口对照保留固定基线模型、确定规则、规则加 Jev、规则加 System2 判断；后几组使用相同候选能力、任务证据和资源限制，记录实际采用的模型或专业路径。复杂度标签和路由分数只作诊断，不替代最终任务结果。
  2. 入口指标包括独立成功率、错误分流、纠正一次错误路由的代价、首次有效响应与端到端延迟、每成功任务总成本。统计 P50／P95、超时、弃权、补证据、委派及回退，缺失费用保持未知。
  3. 过程评测冻结已验收的入口策略，仅切换某个过程消费者；先验证一次判断是否改变动作，再看无效操作、重试、换模、交接和用户重复解释。失败诊断后的证据选择可作为首个过程试验，不挤占入口第一目标。
  4. 长程目标继续要求真实进展和独立完成证据；记忆与沟通分别增加误用、撤销、重要性和投递指标。冻结架构后才比较本地 9B／27B，避免同时改变多个变量。
拟议接口、文件范围与验证计划（本次仅改文档） 
入口输入：requestId、session/taskId、输入引用、目标/任务版本、当前负责人及策略、必要上下文、候选版本、用户选型约束
策略候选：固定候选标识、处理方式、模型/专家配置引用、输入能力、容量、费用与权限条件
判断结果：候选标识或弃权、实际模型返回、使用量与耗时；规则结果和 Jev 判断来源分开
采用结果：已采用/拒绝/过期/回退、实际目标、对应输入批次、失败原因与任务关联
过程输入：在同一任务和策略上增加新事件、完整结果批次、增量证据；不得复用过期入口结果

这些是设计字段，不是已有 API。实际请求内容及 Jev 可见信息必须可从日志重建；仅保存输入引用而无法恢复原文不合格。任务策略选择不授权执行；动作在适用的原生服务中完成准入。

预计涉及范围职责
packages/experimental/system3*共享入口／过程决策、候选与证据、版本校验、实际采用记录；复用现有 Jev provider，预算归属明确。

行为验证覆盖：显式模型优先、无可用候选、Jev 超时／无效输出／弃权、取消、重复请求、目标变化、决策等待中到达新工作、排队串用、附件模态、容量回退、委派取消与结果归属。通过真实 profile 的无密钥回放验证实际采用；真实模型任务对照验证策略质量，二者分别报告。

具体模型候选、任务集、费用上限和第一批入口在代码实施前确认；本设计默认先验证 Web/API 的空闲文本任务。代码实施不以更改 AgentLoop 为前提，只有现有原生组合的验证暴露明确缺口，才提出最小扩展。本次更新方案、图示和 README，不启用自动路由或外部消息发送。

产品方向与顺序：第一目标用 Jev 在入口选择处理策略并由 DSH 调度；第二目标让执行环节更智能、更顺畅。两者共享事实、受约束动作和结果反馈，将 Jev 智能决策融入整个 DSH 架构。
