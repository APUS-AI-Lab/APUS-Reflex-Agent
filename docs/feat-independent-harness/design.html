Jev × DeepSeek Harness

独立仓库：xDAN-System3-Harness。用户已于 2026-09-29 批准创建，核心方向是将 Jev 理念与模型能力嵌入 DSH。产品定位是独立、通用的 Agent 决策与执行框架。

目标与边界

让 Jev 在有证据、有预算、可回放的决策点提供模型判断，由 DSH 执行任务，由确定性代码守住权限、隐私、取消和验收。Jev 不替代生成模型，概率不等于校准置信度，candidate_done 不等于完成。本次先完成独立底座与已有能力迁移；后续自动控制按独立切片实施。

接口约定

AG-UI HTTP 接口保持通用，客户端可传人格，不需要 App URL/token。ctx.jev 继续接受 typed question 并返回已验证答案或 unknown；ctx.system3.shadowDecision 继续持久化记录且不自动改路由。默认启动不连接旧 App 或运行 SSH 凭据脚本。JEV_ENDPOINT、JEV_MODEL 来自显式部署配置；模型所在宿主不能由 localhost URL 推断。

验收计划

  1. 保留 MIT、历史与原仓库；新 Git 仓库无共享 object alternates、无旧远端 push 目标。
  2. 聚焦 Jev/System3/AG-UI 测试通过，涵盖 provider 拒绝、隐私、取消、HTTP 集成与记录回放。
  3. 构建源码及自带客户端，使用隔离 home 检查独立 overlay、真实启动及 SDK snapshot。
  4. 主模型看到的通用人格与 Session 记录一致；无特定消费 App 的业务承诺。
  5. 类型、lint、文档与必要生成目录检查；每次 push 前 Ruff 两门通过。
  6. 推送后回读 origin/main 与私有状态，记录 CI；不把排队或未运行写成通过。

后续实施顺序

先完善 supervisor 的证据完整性和空检查规则，再做有界语义输入及自动 shadow；有足够任务对照证据后，才启用有界继续、重试、升级、模型路由和专家委派。实际预算与目标完成权必须接到 DSH 的权威状态，不能仅依赖调用者传入的数字或模型自评。

不在本次初始化中承诺的能力

自动语义完成判断、全流量 Jev 路由、专家调度、本地 9B 通用任务质量、训练收益和部署成本改善均未在本轮实现或证明。保留这些方向，不用仓库创建成功替代功能验收。
