# System3 委派门槛校准 · 2026-10-03

[English](delegation-calibration.md) | 中文

来源：任务与脚本在 `packages/experimental/system3/tests/fixtures/delegation-calibration/`，入口决策来自 `packages/experimental/system3/tests/delegation-calibration-decisions.e2e.ts`。原始输出：[delegation-calibration-report.json](delegation-calibration-report.json)。

## 设置

- 10 道按规模分级的 Python 任务（2 道极小、2 道小、3 道中、3 道大；最大的一道改动一个小包里的 4 个文件），每道都有 agent 看不到的隐藏验收测试；`verify.py` 证明每组隐藏测试在初始工作区失败、在参考答案上通过。
- 3 道只测决策的仓库级探针（40 个包的构建迁移、不稳定测试排查、12 个端点的 API 新版本）。
- 对照组，每道任务在全新工作区里通过 `dsh headless` 各跑两次：自己做（DeepSeek V4 Flash，low，使用原生工具）、委派（同一主模型，提供 `subagent_codex`，提示词要求使用它）、Jev。产品里的委派是注入一条指令，而不是改写提示词。
- 输入固定时 Jev 的决策是确定的：四档评测连跑两次，决策完全相同。因此 Jev 组对每道任务取其已记录决策所对应那一组的运行结果；Jev 判给 Pro 或 GPT-5.6 Sol 的任务各自单独运行。
- Codex 0.153.4 在开发 Mac 上经 ChatGPT 登录使用 gpt-5.5；Codex 的 token 用量没有上报，不按零计。

## 结果

| 组 | 隐藏测试通过 | 耗时中位数 | 20 次总耗时 |
| --- | --- | --- | --- |
| 自己做（Flash） | 20 / 20 | 36 秒 | 865 秒 |
| 总是委派 | 20 / 20 | 203 秒 | 4515 秒 |
| Jev，原 Codex 描述 | 20 / 20 | 176 秒 | 3819 秒 |
| Jev，采用的 Codex 描述 | 20 / 20 | 41 秒 | 2430 秒 |

- 10 次因并行构建替换了 CLI 而没有启动的运行已重跑并剔除，共计入 52 次运行。
- 各种规模上委派都没有多做对任何一道：自己做在极小、小、中、大四档的耗时中位数分别是 8、26、37、68 秒，委派分别是 102、130、342、263 秒。
- 原描述下 Jev 以 0.92 到 0.98 的置信度委派了 10 道中的 8 道，包括一道单行的差一错误修复；只有两道因低于 0.8 的阈值回到 baseline。
- 采用的描述下 Jev 一道都没有委派，仍委派了 3 道仓库级探针中的 2 道（0.87、0.97）；API 探针以 0.69 回到 baseline。
- 采用描述后剩余的耗时来自模型档位：Jev 把两道大任务交给 GPT-5.6 Sol，用时 321 到 581 秒，Flash 只要 68 到 117 秒；把四道小、中任务交给 Pro，用时 12 到 81 秒，Flash 是 7 到 33 秒。

## 采用的改动

部署的 Codex 候选描述改为：超出一次对话能完成的大型工程任务：在大型代码库里长时间探索、跨十个以上文件改造、反复构建和测试直到通过，通常要十分钟以上。几分钟内能直接改完的修复、函数实现或单个功能都不属于此类，交给模型直接完成。四档入口评测不包含这个候选，仍为 29 / 30。

两种排除动手改代码的 expert 档改写把四档评测降到 26 / 30 和 28 / 30，而且仍把一道大任务交给 GPT-5.6 Sol，因此 expert 描述保持不变。

## 局限

- 任务集很小，而且采用的描述是对照它调出来的，所以采用描述的结果是乐观上界；仓库级探针只检查决策，没有执行结果。
- 这里没有一道任务需要委派，委派真正划算的门槛仍未测得，需要 Flash 做不出来的任务。
- 编码任务的档位路由（Pro、GPT-5.6 Sol）在这些任务上增加耗时却没有测得质量收益，需要单独校准。
