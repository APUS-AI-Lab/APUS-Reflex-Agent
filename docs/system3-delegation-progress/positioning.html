System3：决策原生的混合 Harness

一个 0.4 秒的专用决策模型先判断这件事该交给谁，再由合适的模型或专业 Agent 去做，全程可见、可纠偏、可追溯。

本质

我们是什么

System3 把“谁来做、怎么盯、做得怎样”从执行模型里剥离出来，交给一个快速、可审计、可训练的决策层。

今天的 Agent 架构，通常由正在干活的大模型自己决定要不要换模型、要不要派子 Agent：决策和执行挤在同一个昂贵的循环里，既慢又难以复盘。System3 的做法相反：在执行开始之前和执行过程中的有限几个节点，由专用的 9B 决策模型 Jev 给出结构化选择。确定性规则先划定合法范围，Jev 只在其中挑选或弃权。每一次建议、采用、执行和结果都写成会话事实。

它不是又一个编程 Agent。Codex 和 Claude Code 在 System3 里是候选执行者，和多家厂商的模型档位放在同一个候选空间里，由同一个入口统一调度和监督。

融合了什么

三个系统，一个 Harness

名字来自双过程理论：System 1 快速直觉，System 2 深度推理。System3 是两者之上的元认知层，负责分派、监督和记账。

定义点

六个架构创新

  1. 决策与执行分离

    路由、Skill 选择、委派这类“谁来做”的问题，交给独立的小型决策模型，而不是让执行中的大模型在自己的循环里花 token 去想。决策在执行开始前约 0.3–0.4 秒完成，用户在模型开口前就能看到这一轮由谁处理。

    对照：Agents SDK 的 handoff、Claude Code 的子 Agent，都由正在运行的主模型自己决定。

  2. 规则先行，弃权即回退

    硬条件（读图能力、上下文容量、权限、数据能否出网）由确定性规则判定，Jev 只在剩下的合法候选里选，可以弃权。置信度不足就回到默认模型，同一输入得到同一决策，可审计、可复现。

    对照：完全依赖大模型自由判断的路由，难以保证一致性和安全底线。

  3. 异构执行者，统一候选空间

    多家厂商的模型档位和第三方专业 Agent 放在同一个候选列表里，由一个入口统一选择。模型和 Agent 都是可替换的插件，新增一个执行者不需要改主循环。

    对照：Codex 与 Claude Code 各自主要服务自家模型，Agents SDK 让开发者为每个 Agent 手工指定模型。

  4. 监督第三方 Agent 的过程层

    把 Codex 和 Claude Code 的执行步骤归一成不含内容的类别，持久写入父会话：进度卡片每 2 秒更新，启动过慢、停滞、超时会提醒，可以在运行中补充说明或停止。System3 是管理多个 Harness 的 Harness。

    对照：单个 Agent 能看到自己的过程；System3 统一看见、统一干预它委派出去的外部 Agent。

  5. 事实底座：建议、采用、执行、核验分开记

    “Jev 建议了什么、系统采用了什么、实际由哪个模型回答、结果是否核验通过”是四条独立的会话事实，进入模型的内容都能从日志重建。界面、评测和后续的 Jev 训练都从同一份事实推导。

    对照：常见的 tracing 记录调用链，不区分“建议”和“实际执行”。

  6. 用证据决定路由策略

    每条路由规则都要经过三组对照（固定基线、确定性规则、Jev），并用 Agent 看不到的隐藏测试独立验收。第一次对照就发现过度委派：小任务交给 Codex 正确率没有提高、耗时却长 4–13 倍，产品配置随即改正。

    对照：多数 Agent 产品的路由与委派策略没有公开的对照评测。

能说什么，暂时不说什么

可以说（有实测数据）
  • 专用决策模型在执行前完成路由，服务器 p95 约 0.4 秒
  • 四档模型与 Codex 委派统一由一个入口调度

  • 决策可复现，建议与实际执行分开记录
暂不宣称（尚未完成或未验证）
  • 本机模型与隐私数据路由：在路线图上，尚未实现
  • 自动纠偏、自动换执行者：目前由用户在提醒中决定
  • 委派比单模型更强：对照中尚未出现需要委派的任务
  • Claude Code 运行中补充说明：目前只支持 Codex
  • 任何“超越或替代 Codex、Claude Code”的说法
