## Small existing test batches

The first three commands listed below were executed together as one six-file batch, followed by the filtered file-read command. They use no online model credentials. Batch 1 exercises input/Skill behavior; batch 2 exercises memory components and budgets; batch 3 exercises local filesystem tools. Temporary fixture writes stay within their test-owned directories. The Jev composition suite additionally starts and closes a loopback HTTP fixture, so it remains separate from the initial no-new-service batch.

```sh
pnpm exec vitest run packages/experimental/system3/tests/skill-selection.spec.ts packages/experimental/system3/tests/desktop-profile.spec.ts
pnpm exec vitest run packages/context/continuum/tests/retrieval.spec.ts packages/context/continuum/tests/context.spec.ts packages/context/continuum/tests/persistence.spec.ts
pnpm exec vitest run packages/fs/tool-fs-search/tests/integration.spec.ts
pnpm exec vitest run packages/fs/tool-fs/tests/integration.spec.ts -t 'returns line-numbered content|paginates a multi-line file|read works'
```

On 2026-10-13 at 22:12:45 +08:00, the six-file batch passed 113/113 tests in 2.48 s. At 22:12:55, the filtered file-read batch passed 3/3 selected tests in 851 ms, with 30 tests explicitly skipped. Both processes exited with code 0. These are Vitest run durations, not user task latency. The first batch emitted a `MaxListenersExceededWarning` for 11 process exit listeners; it was retained rather than suppressed and does not establish a production leak. Logs: `/tmp/apus-reflex-stage-acceptance-keyless.log` and `/tmp/apus-reflex-stage-file-read.log`.

The optional existing composition command is `pnpm exec vitest run packages/experimental/continuum-jev/tests/composition.spec.ts`. It validates local HTTP protocol and persistence composition, not live Jev relevance quality. The existing SDK scenario already has a passing result in this phase; no rebuild or replay is proposed merely to repeat that result.

## Evidence required for the user-facing claim

For each stage, record input, data scope, candidate count, selected source IDs or paths, decision/load/adoption outcome, elapsed time and failure reason. Keep selection, body readiness and actual main-model consumption distinct. Record `not-run`, `disabled`, `fallback`, `timeout` and `no-source` without translating them into success. Every claim about cross-session memory needs real authorized source history; synthetic fixtures must remain labeled.

Module tests passing does not establish a complete product path or an end-to-end speedup. A 3× claim is not established. It requires a fixed task set, matching main-model settings and quality, a Reflex-disabled baseline, an equivalent local-selection control, all failures retained, and paired timing of the same observable milestone. Faster intent classification cannot substitute for faster useful output or task completion.
