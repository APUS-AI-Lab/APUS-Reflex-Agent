Reflex 接入与即时判断体验

目标：每次普通文本输入后尽快显示真实 Reflex 判断，随后由主模型继续。约一秒是待验收的体验目标，不是已证实的服务保证。用户已明确要求两种接入方式及直接展示判断结果。

接入界面

仅保留「APUS Reflex 限时免费端点」「自定义参数」两个选项，服务协议显示 Reflex。免费模式隐藏地址、模型与密钥字段；自定义模式可编辑自己的参数。后端协议标识保持兼容。默认 endpoint 与 model 是公开配置，凭据仅存本机 managed credentials，安装包不包含共享 Key。

预置凭据引用 APUS_REFLEX_TRIAL_API_KEY，与自定义引用隔离；切换模式不向其他地址携带预置密钥。未获凭据的新安装不能宣称免费服务已激活。公开服务的有效期、配额及凭据发放尚需服务端实现。

请求与显示链路

用户提交 → 立即显示已接收 → Reflex 有限类别判断（候选较小时同时选 Skill） → 显示真实判断及耗时 → 主模型执行与正文回复

Jev 返回分类和概率，不生成自由文本正文。界面由语言字典将分类映射成中性描述，选 Skill 和注入 Skill 依据不同事件显示。没有命中 Skill、大目录等情况不静默丢弃候选；可仅做输入类别判断，Skill 发现交给原生主模型。

约一秒为目标，当前真实服务在一秒强制期限下多次超时；改用可配置三秒总准备上限，超时后原生聊天继续；超时不显示伪造判断。所有分类失败、网络失败、超时保留。输入超过预算时保留完整原文，不截断后冒充已理解全部输入。

显示规则

回答上方使用紧凑状态条，含 Reflex、真实判断类别或 Skill 名称、本次实测耗时。判断中原位更新；详细依据折叠。示例「Reflex · 日常交流 · 480 毫秒」仅为版式示例。「建议检索历史记忆」不等于已完成检索，「已选择 Skill」不等于已执行任务。新一轮输入不复用上一轮结果，读屏只播报真实状态变化。

文件与接口

  • client-ui-system3：接入控制器、双语字典、设置界面、即时判断显示及对应 UI/controller 测试。
  • system3：输入判断与 Skill 选择、运行状态投影、Session 事件兼容及真实 Loader 测试。
  • apus-dsh-jev-plugin：独立 Skill 能力状态；不改变 systemone 网络协议。
  • frontend/scripts/generate-system3-patch.mjs：正常桌面加载执行插件；安全模式保持独立。

保存和测试使用现有 settings / credentials / reflex Remote；不将密钥放进浏览器存储或 Session 日志。公开分类为有限枚举，未知值拒绝显示为成功判断。现有 Session 数据必须可继续读取。

指标起止点

OFF/ON 同题、同主模型和 thinking 设置，配对交错；保留 Flash 关闭 thinking 对照。报告 P50、P95、1 秒内有效反馈比例、判断正确率及超时率。成功样本的快响应不能代替所有输入的成功覆盖率，3× 尚需足够独立案例支持。

  • 双模式切换、保存重开、丢弃、缺凭据、密钥隔离、已有自定义值保留。
  • 普通对话、记忆请求、资料查找、生成内容、工具操作、不确定输入、无 Skill、大目录、长输入、超时与错误。

0.1.3 安装验收接口

Web 验收通过 Reflex configuration 导航进入配置页；接入方式仅 trial/custom，服务协议文本为 Reflex。免费模式不出现地址或密钥输入，自定义模式保存测试地址和模型，重启后验证原值。macOS 验收进入 Reflex 配置后读取、修改并验证 Continuum 开关持久化。Loader 的联合问题 fixture 同时回答 intent 与 skill，保留严格响应验证和原生 Skill 注入断言。

改动文件：scripts/product-web-smoke.mjs、scripts/product-macos-smoke.mjs 和 system3 的 Loader 组合测试。沿用现有 settings/credentials API，不修改产品协议或延长测试超时。验证包括本地脚本与 Loader 测试、真实预览页面，以及绑定提交的原生平台安装验收。

原生发布检查还覆盖 Linux shell 对缺失 Node 的状态、测试 fixture 显式声明 Full/Lite，以及 macOS 打包 shell 的文件句柄上限。签名保留，文件限制在实际打包进程的父 shell 中设置并记录；设置失败则停止打包。平台最终结论仍依赖真实安装与重启验收。

发布复验：签名资源与 Web 执行装配

macOS 签名依赖递归同时打开过多文件，32768 的文件上限仍触发 EMFILE；对锁定的 @electron/osx-sign 1.3.3 加可重放补丁，约束遍历并发，保持二进制候选集合、嵌套应用顺序、临时文件清理和错误传播。不得跳过签名、减少扫描文件或删除严格完整性验证。改动位于 frontend/patches、对应签名行为测试及补丁说明；不改变应用 API。

Web 专用 profile 必须与 Desktop 一样实例化 System3 执行插件；仅加载设置 UI 不构成功能可用。两个 profile 共享必要的输入判断与 Skill 选择配置，保留三秒总预算、完整候选和已有权限规则；不引入桌面专用插件到 Web。改动位于 profile 生成、Web 打包与安装验收脚本和真实 Loader 测试。

Desktop / Web profile → Jev provider + System3 执行插件 → 输入判断与 Skill 选择 → Session 决策记录 → UI
应用资源 → 有界签名遍历 → 原生签名 → 严格完整性校验 → 安装包 → 安装、启动、重启验收

验证：低文件上限下的大目录扫描、未修补版本负对照、签名后资源篡改拒绝、干净安装补丁重放；Web Loader 的真实联合决策与 Skill 注入、缺配置仍继续主模型、安装包启动后 skillSelection implemented/enabled 均为 true。修复后的各目标从同一提交重建；旧 Web 启动验收不得冒充执行能力通过。

Windows 验收使用平台路径比较；进程观察失败时区分退出与输出管道关闭，终止仍存活子进程并等待结束，保留已退出进程的真实错误码。受控管道持有场景验证 exit/close 竞态，不能用 sleep 或丢弃退出证据通过。
