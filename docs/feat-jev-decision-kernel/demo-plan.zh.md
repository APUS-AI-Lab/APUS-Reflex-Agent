## 演示准备与路线

材料只含合成数据。解压到新的演示目录，并在App中选择apus-reflex-demo作为工作区；每次彩排用新副本和新会话，保留失败记录。不要覆盖当前用户文件或打断正在使用的会话。英文版保留相同中文提示，便于逐字复现。

sales.csv有6行：流水5000、折扣370、退款210、净收入4420；App1620、Partner1450、Web1350。acceptance.txt为approved加换行。demo-ledger初始1条测试通过；demo-log初始3条测试中1条失败，修复副本后3条通过。

| 讲解路线 | 内容 |
|---|---|
| 3分钟 | 场景2主秀，打开成果，再解释大小脑分工。 |
| 10分钟 | 1选路 → 2改要求 → 3核验 → 6刷新证据。 |
| 20分钟 | 加演4专业委派、5长日志，最后审阅能力缺口。 |

时间仅为讲解安排，真实模型和工具等待另计。未通过时转用明确标注日期、构建与范围的历史记录；不把回放说成现场运行。

## 六个演示场景

### 1. 一句话，交给合适的大脑

在自动模式的两个新会话分别发送两题。查看执行依据里的选路、实际模型和耗时，再看真实回答；第二题不保证换模型。新提示待彩排；本次观察为入口1659ms、本轮8757ms，后者不含入口。

初始提示或操作对象：

```text
把“Please confirm the delivery date.”译成自然中文。
```

追加提示（场景1发到另一新会话；场景3/6为操作说明，不发给模型）：

```text
一个零售业务只能追加一项投入：获客、履约或留存。已知新增订单增长20%，履约失败率8%，复购率下降5个百分点。请给出你的优先选择、最关键的不确定信息和判断理由。
```

### 2. 老板中途改要求，交付跟着变

材料包解压后选择apus-reflex-demo作为工作区。create_goal之后、任务仍在运行时发追加要求；结束后的修订不能算运行中插话。任务卡要出现原文，board-report.md要真实存在：净收入4420，渠道按App1620、Partner1450、Web1350排列。初始附加要求仍可能被模型目标简化，不能宣称全部要求受保护。

初始提示或操作对象：

```text
请创建目标：读取 sales.csv，按净收入=gross-discount-refund计算2026年9月样本经营结果，生成 report.md 并读取文件核对。报告写明总流水、折扣、退款、净收入，给出一句经营判断；只依据这6行合成数据，不编造环比、增长率或因果。
```

追加提示（场景1发到另一新会话；场景3/6为操作说明，不发给模型）：

```text
新增要求：成果文件改名为 board-report.md；补充各渠道净收入，并从高到低排列；说明仅为合成样本，不代表公司真实经营。
```

### 3. 没做完先申请完成，系统会怎么处理

明确说明这是受控故障注入。taskFrame和completionReview须为active；acceptance.txt内容为approved加换行。观察首次update_goal被拒、目标仍active，随后真实read/write/read、最终完成。核对副本与源文件hash一致。只覆盖原生目标完成调用；不确定、请求失败和拒绝额度存在放行，专用核验依据界面未完成。

初始提示或操作对象：

```text
这是完成核验系统的受控验收。请先 create_goal，objective原文为“读取 acceptance.txt，确认它的内容为 approved，并把 acceptance-copy.txt 写成完全相同的内容，再读取副本核验”。在读写前，先尝试一次 update_goal(action=complete)，使用返回的goal_id和revision。如果工具拒绝，就执行目标中的真实读取、写入与核验，再次update_goal(action=complete)。最后简短报告。
```

追加提示（场景1发到另一新会话；场景3/6为操作说明，不发给模型）：

```text
无需追加；若缺少提前update_goal或拒绝记录，本轮不能算负例通过，不强迫额外调用制造已通过结论。
```

### 4. 专业事交给Codex，补充要求还能送达

材料包demo-ledger初始1条测试通过。确认Codex授权与前台委派可用，在真实running期间补充文件名。实际Codex调用、追加要求送达、check_ledger.py文件和非零测试全部通过须分别留证。当前Mac未彩排此场景；后台、停止与断线恢复不在本场景通过范围内。

初始提示或操作对象：

```text
请把工程修改交给Codex：在demo-ledger目录中，为ledger.py增加按月份汇总金额的函数，并补充unittest测试。运行python3 -m unittest，读取结果后交付改动与测试摘要。使用合成数据。
```

追加提示（场景1发到另一新会话；场景3/6为操作说明，不发给模型）：

```text
新增要求：测试文件名使用check_ledger.py；运行python3 -m unittest check_ledger -v，确认实际发现并执行测试，失败则继续修复。
```

### 5. 日志再长，也要找到影响交付的错误

材料包demo-log包含真实退款符号错误。python3 run_tests.py --unittest运行3条真实测试，初始失败1条且exit=1；中间有错误，前后各180行是标注的合成进度。材料本身已验算：修复副本后3条通过。产品仍需证明实际System3折叠、同轮原文hash可核对及修复通过；普通终端缩略不算语义折叠。

初始提示或操作对象：

```text
在demo-log目录运行 python3 run_tests.py --unittest。请从实际输出定位失败原因，修复后用同一命令重跑，确认3条测试全部通过。最终写明改动文件和错误原因；前后进度行是合成噪声，测试结果必须以实际执行为准。
```

追加提示（场景1发到另一新会话；场景3/6为操作说明，不发给模型）：

```text
请指出导致失败的具体错误行，并说明你如何读取或核对原始输出；不要仅用最终摘要猜测。
```

### 6. 刷新以后，拒绝和交付记录仍在

复用已通过完成核验的Web会话，不发新消息。记录会话标识、事件和判断数，刷新后展开同一拒绝卡，确认记录和成果保留、没有新增判断。当前证据是Web刷新，不是服务器重启、跨设备连续工作或跨会话记忆；不要为演示干扰正在使用的Mac会话。

初始提示或操作对象：

```text
复用已完成的受控完成核验会话，不发新任务。
```

追加提示（场景1发到另一新会话；场景3/6为操作说明，不发给模型）：

```text
无需向模型发消息；操作浏览器刷新，再展开第一次update_goal拒绝卡与最终交付记录。
```

## 两层计时与能力覆盖

上层“入口决策·1659ms”，下面放任务判断与实际模型；下层“本轮执行·8.8秒”，下面放过程和回答。入口耗时包括检查与网络，不是纯Jev推理；本轮含技能选择、主模型和可能的工具，不是纯大脑耗时。当前“8秒”由8757ms向下取整，未包含入口。两层布局仍为提案，运行中的App未修改。

缺失记录不显示0ms，也不用其他轮判断补齐。取消、超时、沿用和固定选择须区分；没有点击到渲染数据时不宣称端到端总时延。

DSH的8组底座能力也属产品：执行循环/会话、工具/沙箱/终端、子agent/后台任务、目标/计划/待办、上下文/压缩、技能/MCP/hooks、工作流/定时/webhook、Web/桌面/SDK。六故事只涉及部分；权限负例、后台、MCP、定时、跨端恢复须专项验收。

原版Web与当前System3的Dock、卡片、动效归属对照见[HTML的UIUX审查](demo-plan.html#uiux)。两层计时、预计耗时和专用核验面板仍为待交付；原生动画不算新增成果。

## 成功标准与复盘

每次记录构建与配置、会话标识、实际模型调用、追加要求送达时点、工具退出码、非零测试数、实际成果及核验结果。禁止以界面标签、模型自述或文件最终正确推断整个执行过程正确。

历史生产v0.1有5场景；当前完成核验有真实源码2条和本地Web1条；Mac新证据为启动、选路与基础文件工具冒烟。这些范围不同，不能相加当能力准确率，也不代表所有招牌完成。

收尾可以说：“我们已有自己的即时决策模型和可运行的Harness。今天看的是它们如何在任务里协作。下一步先在一个公司产品任务中，用成果、成本和独立对照决定扩展。”Rivon Browse和Bibble仍为接入候选；执行记录回流不等于训练循环已完成。
