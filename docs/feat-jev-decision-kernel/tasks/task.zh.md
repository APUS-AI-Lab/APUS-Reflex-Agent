# feat-jev-decision-kernel — 让 System3 成为 agent 的管家

[English](task.md) | 中文

2026-10-07 批准：分七批实现 mu 的全部 38 个判定点，所有判断围绕同一张任务卡组织。方案与场景：[../steward-plan.html](../steward-plan.html)；大白话对照：[../mu-product-view.html](../mu-product-view.html)；去重后的 Top 10：[../top10.html](../top10.html)。

## 原则

- 一张任务卡：所有判断都读同一份目标、用户原话要求和验收项，不各自猜测。
- 判断归 Jev，动作要直接：Jev 只回答封闭问题；之后的动作是确定的（换模型、请求确认、插入当前步骤、亮出或收起工具）。进入模型或界面的文字只用用户原话，或由现有模型生成。
- 看得见、能撤回：每个动作都在侧边面板用一句话说明原因，并且可以撤回。
- 坏情况回归集就是验收标准：真实发生过的坏情况做成可重跑的会话，每项修改前后各跑一遍。
- 先有证据再开启：每个判定先以 `shadow` 上线，阈值来自真实 Jev 上跑的标注集，prd 数据达标后才转为 `active`。实现不等于开启；没有测出收益的项保持关闭，并记录原因。
- 指标不达标时改问法，不改阈值。
- 判定失败（超时、出错、隐私拒绝）一律回退，绝不阻塞主流程。
- 不新增等待：每条用户消息只发一次 Jev 请求（最多 16 题），包含入口路由、任务卡、澄清提示和工具披露；其他判定与主模型并行，或只在规则触发后才调用。每项都报告 P50 / P95 延迟增量。
- 进入模型的一切都能从 Session 日志重建。
- 每项都交付单元与组合测试（新代码 100% 覆盖）、修改前后对照和 prd 实测。
- e2e 验收通过后，每项还要在公网 prd 上用真实浏览器从用户角度验证：像用户一样输入场景，记录用户实际看到的内容（侧边面板文字、确认卡片、消息位置、等待时间）并截图。
