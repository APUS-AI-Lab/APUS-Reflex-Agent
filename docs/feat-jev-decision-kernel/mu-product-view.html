一句话结论

用 System3，用户今天能感到的是：简单问题答得快、难题自动换强模型、大活交给 Codex 时有进度可看、能补充、能叫停。还感受不到的是：它不会拦住违背你原话的操作，做没做完靠它自己说，下次会话不记得你的要求。mu 恰好在后三件事上做得细，这也是 Top 10 前四项要补的。

值得学的是 mu 的产品方法，不只是功能

mu 做得好的

  • 一句话能讲清楚：每个点都对应一个用户见过的坏情况（删了不该删的、说做完其实没做完、插话没生效），而不是技术名词。
  • 开关粒度细：每个点都能单独关闭、只记录、或生效，出问题可以只关一个。
  • 坦白自己的失败：作者公开了“tool.admission 零裁剪、成本 54%”的回测。

mu 的局限（我们不要照搬）

  • 大多数效果数字是作者一次性实测，没有可重跑的脚本，也没有与 Claude Code / Codex 的端到端对比。
  • 有 4 个点默认关闭（7、9、30，看板按项目默认关闭），另有不少只在特定模式下运行，“38 个”不等于 38 个都在起作用。
  • 只给提示多、真正改变行为少；System3 的路由与委派是直接动作。
