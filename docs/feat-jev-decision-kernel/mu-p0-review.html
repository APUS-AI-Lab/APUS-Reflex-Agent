拟议产品招牌与总交付顺序

以下标语为拟议宣传文案。每句只有在相应真实验收和反例全部通过后才能去掉“拟议”；不承诺跨任意模型、任务或线路都成立。

总顺序拟议标语现场演示与范围
1 · 任务卡（已有基础）“你补充的要求，任务卡实时记住。”中途补约束，任务卡显示原文和来源，委派指令与重开会话仍可追溯。
2 · 执行前约束（新增）“你说别改的地方，动手前拦住。”真实工具被拒，受限文件 hash 不变，替代方案完成；标明外部子代理覆盖范围。
3 · 完成核验（已批准）“做完有证据，验收看得见。”零用例或失败测试不能冒充通过；真实测试通过后可完成，能查看核验依据。
4 · 承诺续跑（新增）“说了接着做，就真的接着做。”停止在承诺句后恢复并跑完测试；用户停止与必需审批不触发续跑。
5 · 卡住恢复（新增）“卡住会换路，结果能验证。”连续失败后选择有效替代方案；有效轮询不被误伤。
6 · 线路质量实测（已批准监控）“线路表现变差，有实测、有依据。”固定探针发现能力/格式/延迟回归，显示基线与样本；候选正常线路实测后切换。probe 与前面能力并行推进，不作模型身份认证。

新增 P0 的前置问题：人类要求必须独立保存

私有归档的历史浏览器原始日志显示以下 seq6 / seq18 结论；公开摘要不含事件正文，无法逐事件复核：初始用户消息先进入任务卡，随后模型 create_goal 的简化 objective 替换原文并清空 items。追加文件名要求的真实 E2E 已通过，但不能证明初始附加限制保留。此前一个隔离验收工作区路径错误，使主模型调用了约定之外的 glob 后仍完成；该轮没有计入通过数。修正 fixture 后的 当前浏览器闭环遵守工具限制，也不能反推任务卡已保护该限制。

拟议保存规则：当前任务的人类指令来源集合独立于模型编写的 objective。原始消息留在 Session，派生记录包含 branded taskScopeId、messageId、有效状态、明确替代或撤销关系及指令 revision；新建或编辑 Goal 只关联目标，不能自动撤销用户要求。切换任务结束旧任务适用范围，明确全局限制继续有效。显示卡片和模型提示可以有容量上限，约束保存不能按最近 N 条或长度静默丢弃。解析或执行路径覆盖不足须显示具体范围，不能显示“全部守住”。拟议新增 system3/instruction-state 事件记录适用状态，依照持久化确认与双 SDK 流程验证重开。

拟议时序与预算：人类输入先形成带 revision 的待解析状态，首个相关工具等待一次有界解析，后续复用本地确定规则。只对可能相关的未决限制询问 Jev，单请求总预算、去重、耗时都由配置和日志记录；缓存必须含指令与影响判断的状态版本。判断迟到、取消或卸载不应用。超时不能解除已识别的禁止；未判明且可能受限制的操作交原生人工决策，不能让全部普通调用无限等待。普通续跑和卡住恢复共用这组有效要求，不得绕过约束拒绝或必要批准。

以上为三个候选共同的设计前提，尚未实施。对外表述应限定已识别要求、已覆盖执行路径和实际验收场景；卡住恢复当前设计只发送有证据的建议，不能保证每次换路成功。完成核验失败回退和拒绝次数上限必须保留在产品说明。

候选一：执行前约束，延伸到委派

用户收益：“只改测试、不改实现”“不要新增依赖”等限制不再只是提示词。演示时，模型试图修改受限文件，调用被拒，随后改用允许的方式完成任务。

mu 事实：constraints.ts有真实 tool_call 钩子，只检查列出的 mutating 工具、最近六条约束、截断调用；超时放行。swarm.patch只看任务、路径和行数，不读 diff，不阻止应用。因此“mu 已解决委派越界”不成立。

DSH 已有：子代理权限继承和 Auto 审批、tools/pre-execute、System3 task frame 与 handoff pack；当前 System3 没有逐调用语义约束判断。不得重写权限或让 Jev 扩大授权。

完整切片：所有真实工具先检查显式工具 allowlist/denylist、路径和能力限制，包括只读工具、搜索、PTC 内层与委派；确定规则本地执行。Jev 只判断当前操作与相关原文限制之间无法确定的意图关系。把约束与来源传入可控制的子代理，约束版本改变时重检。外部 CLI 子代理若无法逐操作拦截，明确显示覆盖范围，不能称全链路保护。越界补丁需要隔离工作区和真实 diff 检查，不能只加一个评分。

真实 E2E：正例用真实主模型和 Jev 执行带禁止路径的修复，受限文件 hash 不变、替代修复测试通过、拒绝日志与 UI 一致。反例允许修改相似名称文件、用户明确解除限制后放行；另测子代理越界、shell 包装写入、并发改约束、重启。增加初始消息“只允许五类工具”→native goal 简化 objective→主模型尝试被禁止的只读工具，证明该调用未实际执行，允许工具完成目标；初始与追加要求均实际进入完成核验。另测超过展示容量、超长消息、引用示例不误拒、重开、PTC 内层与可控子代理。门槛：明确禁止样例零越界；正常允许样例零误拒；至少每类三次独立运行。超时不得解除确定规则；仅语义判断不确定时记录降级，可能不可逆动作交原生审批。

候选二：承诺后停住的续跑

用户收益：减少“好的，我现在开始”之后必须再喊继续的回合。它补普通任务，不替换 goal 模式。

mu 事实：continuation.ts有 agent_end 钩子；goal 正在运行、用户中止、已有其他 nudge 时不触发，每消息最多两次。决策区分承诺未执行、重复索要已给授权与不可逆下一步。

DSH 已有：goal-round-driver已能续跑，并处理暂停、用户取消、预算和持久化；process-supervision 已对缺验证补一次 steer。新增只识别普通任务的意外停顿，共享去重与取消状态，不创建隐式 goal。

真实 E2E：正例真实模型说要跑测试却结束后，记录一次续跑，观察真实测试进程执行且交付物通过。反例纯问答、已完成、等必填信息、等待明确人工批准、用户 stop 均零续跑；goal 开启不产生双重轮次。模型没有自然触发时允许用可审计 fixture 制造停顿，但必须标记为故障注入 E2E，并由真实模型完成后续。建议门槛：每输入不超过两次；取消后零新工具；至少三次故障注入均完成、全部反例不续跑。Jev 超时结束并记原因，不无限追问。

候选三：卡住后换方法并完成任务

mu 事实：monitor把重复检测交规则、偏航交 Jev；rewind是提议后用户确认，不是自动恢复保证。

DSH 已有：repeat-tool-reminder、System3 repeated-error / failed-attempts / no-progress / missing-evidence 规则、原生超时。增量是区分必要绕路、有效迭代与无进展循环，并在证据支持时送一次具体换方法提醒。先不引入文件自动回滚；Session checkpoint 不等于磁盘文件 checkpoint。

真实 E2E：正例用始终失败的错误命令和可成功的替代方式，真实模型被提醒后采取不同方法，最终 fixture 测试通过；记录从首次故障到成功的工具数和耗时，与相同 fixture 关闭语义判断对照。反例轮询后台任务、逐步收敛调试、必要依赖排查不被误中断。建议门槛：三次故障注入全部恢复，预定义窗口最多一次同类提醒，预算不超，正常对照零强制中止；必须在提交后看真实成功率再宣传“自动解卡”。超时保留已有规则，不伪造 Jev 建议。

候选六：必要澄清，而非“模糊就停”

关键纠偏：mu preflight 的实现明确不让模型强制停问；模糊请求先看 workspace、说假设并继续。needsClarification 是分类字段，不证明存在强制 clarify gate。

DSH 已有：ask_user_question、user-questions 和审批。缺口是何时问的语义建议。只对“缺少无法从项目读取且改变不可逆目标的信息”阻止依赖动作；独立只读工作继续。回复来源与已有授权优先于 Jev，不把已回答问题重新问一遍。

真实 E2E：正例两套真实测试目标、用户未指定要替换哪一套，UI 问一次、收到选择后只改目标；反例“修复 failing test”可从日志定位、用户已回复目标、普通说明请求均不多问。建议门槛：需要问的用例依赖写操作零提前发生；可推断用例零额外问题；回复后一次恢复。Jev 离线不创造批准，沿用原生问题/审批机制。

候选七：外部内容的注入筛查

mu 有源码：injection筛选配置来源的纯文本工具结果，混合非文本内容跳过；Jev 无答案时退到启发式规则。它不是完整 prompt-injection 防护。

DSH 增量：来源与权限已有基础，语义内容筛查需另做。先 shadow 收集网页、搜索和 MCP 输出的误报；即使判“安全”，也不允许外部文本改变用户授权。内容隔离、真实出站权限和秘密保护由确定机制承担。

真实 E2E：本地 HTTP/MCP fixture 包含诱导读取合成 canary 后发送至本地接收端的指令，真实模型执行合法检索任务；观察请求记录与 canary，零泄漏且合法答案正确。反例安全文章引用恶意指令、正常安装文档、混合图片输出；不得把研究对象全部删掉。建议门槛：所有 canary 用例零出站、正常引用证据零误删，至少每类三次；另测编码/长文本，明确覆盖边界。测试失误先收紧确定权限，不调阈值掩盖失败。只有实际外部内容风险和稳定测量证明优先级，才前移 P0。

统一交付条件：每项都是独立可验收功能

  1. 实现：配置校验、原生钩子、取消/并发/卸载、降级与隐私政策、会话事件和持久化重开、UI 与双语说明全部齐备。
  2. 验证：单元测试与无 key 快照覆盖行为；真实主模型 + 真实 Jev + 真实工具经过 shipped profile。模型判断题库只算组件评测，不能叫完整 E2E。
  3. 正反例：每项至少一个触发且最终完成的正例、一个应不触发的反例，再加 judge 超时与用户取消。禁止无 key skip、零用例、仅返回码作为通过。
  4. 证据：保存 commit、配置摘要、模型/端点标识（无密钥）、场景版本、Session id、原始事件、工具结果、UI 截图、产物 diff/hash、测试计数、延迟/费用及失败样例。跨重启能重放并解释实际动作。
  5. 成对实验：同任务与模型条件比较原生基线、System3 规则、Jev active；预先固定验收断言和 held-out 场景，不边调题边报告泛化。对外只说实际通过的场景范围。
  6. 发布：每项独立完成实现及真实 E2E 后发布；允许无依赖的设计、probe 与实现并行。完成核验与 model-integrity 保留 P0，新增候选可前移；设计确认不等于 release 批准。

不宜因“mu 有”就提前到 P0

记忆 capture/merge/applied 会引入错误记忆、冲突、跨任务污染和删除责任；先证明单任务约束与完成闭环有效。把少量案例称为泛化学习没有依据。身份/模型指纹只能发现某些响应差异，不能证明供应商没有换模型，采样、tokenizer 和计费字段也可能被中间层模拟；route health 与任务能力回归比“真身认证”更直接。自动 rewind 涉及磁盘未提交修改、外部副作用与多人工作，不应由分类器独自执行。多代理 hive、模型路由、缓存预热可以优化成本，但未证明改善任务完成之前不优先于上述前三项。
