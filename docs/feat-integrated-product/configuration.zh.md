# 配置模型并完成首个任务

[English](configuration.md) | 中文

桌面客户端默认以普通模型模式启动。先配置你可以访问的服务商，选择工作区并验证一次响应，再运行较大的任务。普通模式不需要 Jev 凭证。

## 配置服务商

1. 打开**设置 → 模型**，按你的服务添加目录中的服务商或自定义服务商。
2. 填写服务商 API Key 并选择模型。自定义服务商还需要 Provider ID、显示名称、API 协议、Base URL 和准确的 Model ID。请使用服务商的 API 地址，不要填写网站首页。
3. 保存配置，开始对话时选择已配置的模型。

使用你自己的服务商账户凭证。APUS 不附带模型订阅或共享 API Key。保存配置不代表凭证可用，下一步的首次响应用于检查真实模型访问。

## 验证任务

选择一个临时文件夹作为工作区，然后新建对话，让所选模型回复一个短句，确认响应出现且没有认证或连接错误。再要求它在该文件夹创建一个小文本文件，并检查结果。审阅请求的访问范围后再批准工具操作。

退出并重新打开应用，确认模型配置仍可使用、对话可以打开。测试任务可能产生模型服务费用。工作区访问与远程模型推理是两回事：模型请求可能向配置的服务发送任务和文件内容。

## 排查配置错误

| 现象 | 检查项 |
| --- | --- |
| 认证失败 | 服务商是否正确、API Key 是否有效、账户权限与额度 |
| 模型不存在 | Model ID 是否准确，以及账户是否有权使用 |
| 连接失败或超时 | Base URL、服务商状态、代理与网络访问 |
| 没有选择模型 | 为对话选择已保存的服务商与模型 |

保留原始错误用于排查，分享之前先去除密钥。凭证使用现有本地凭证存储，位于 `$DSH_HOME/.credentials.yaml`；请保护该目录，不要提交到仓库或作为 Issue 附件。

## 可选的 Reflex 决策服务

打开**设置 → Reflex 模型配置**，接入你自己的 Reflex/Jev 决策服务。普通模型任务不需要此服务；生成模型仍在**设置 → 模型**配置。 首次打开时可能显示决策服务尚未配置，仍可填写地址和模型；草稿测试不会保存配置。

| 字段 | 填写内容 |
| --- | --- |
| 服务地址与决策模型 | 决策服务的直接 API 地址与真实模型 ID；地址不可包含密钥、用户信息、查询参数或 fragment |
| 决策强度 | 服务支持的 `high` 或 `low` |
| 请求超时（毫秒） | 连接测试和决策请求的等待上限 |
| 密钥引用与 API Key | 使用独立引用名，如 `REFLEX_API_KEY`，并填写自己的服务密钥；无认证服务无需密钥 |

API Key 留空会保留已存密钥。新增或轮换密钥须使用新的专用引用名，不能覆盖已配置的引用。部署环境中的凭据为只读；密钥通过后端凭据服务保存，不进入普通设置或源码。

点击**测试连接与真实判断**。测试使用当前草稿，不会保存配置；更改字段后需重新测试。页面分别报告认证失败、超时、模型不存在或真实判断结果。“真实判断通过”只验证此次决策服务测试，不能证明路由、监督、记忆或任务执行已经启用或验收。

检查结果后点击**保存**。保存后对新请求生效，正在执行的请求保留原配置。若页面提示保存失败或部分生效，请重新打开配置页，检查设置与密钥状态后再重试。

## 检查能力是否启用

Reflex 页面单独显示用户入口路由、Codex 长时 Goal 自动纠偏、动态上下文与可恢复记忆的能力状态。点击**刷新能力状态**读取当前运行状态，并区分未加载、未启用、已启用和执行验收记录。

连接成功或保存服务地址不会自动开启这些能力。高级路由候选、数据分类与远程授权需单独配置 profile；Continuum 还需要对应的记忆准入与 scope 设置。参见[公共 provider 指南](../dev-continuum-reflex-integration/public-provider-configuration.zh.md)、[System3 配置参考](../../packages/experimental/system3/README.zh.md)与 [Continuum 指南](../../packages/context/continuum/README.zh.md)。这些配置可能允许向决策服务及生成模型发送任务内容，启用前请检查服务地址和授权范围。

启用具体能力后，请用小任务检查对应的运行记录和实际结果。建议被显示不代表已被采纳，能力已启用不代表该任务已经验收。Model-as-a-Harness 表达产品定位，各项能力以实际配置和执行证据为准。
