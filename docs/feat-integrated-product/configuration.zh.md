# 配置模型并完成首个任务

[English](configuration.md) | 中文

桌面客户端默认以普通模型模式启动。先配置你可以访问的服务商，选择工作区并验证一次响应，再运行较大的任务。普通模式不需要 Jev 凭证。

## 配置服务商

1. 打开**设置 → 模型**，按你的服务添加目录中的服务商或自定义服务商。
2. 填写服务商 API Key 并选择模型。自定义服务商还需要 Provider ID、显示名称、API 协议、Base URL 和准确的 Model ID。请使用服务商的 API 地址，不要填写网站首页。
3. 保存配置，开始对话时选择已配置的模型。

使用你自己的服务商账户凭证。APUS 不附带模型订阅或共享 API Key。保存配置不代表凭证可用，下一步的首次响应用于检查真实模型访问。

## 验证任务

选择一个临时文件夹作为工作区，然后新建对话，让所选模型回复一个短句，确认响应出现且没有认证或连接错误。再要求它在该文件夹创建一个小文本文件，并检查结果。审阅请求的访问范围后再批准工具操作。

退出并重新打开应用，确认模型配置仍可使用、对话可以打开。测试任务可能产生模型服务费用。工作区访问与远程模型推理是两回事：模型请求可能向配置的服务发送任务和文件内容。

## 排查配置错误

| 现象 | 检查项 |
| --- | --- |
| 认证失败 | 服务商是否正确、API Key 是否有效、账户权限与额度 |
| 模型不存在 | Model ID 是否准确，以及账户是否有权使用 |
| 连接失败或超时 | Base URL、服务商状态、代理与网络访问 |
| 没有选择模型 | 为对话选择已保存的服务商与模型 |

保留原始错误用于排查，分享之前先去除密钥。凭证使用现有本地凭证存储，位于 `$DSH_HOME/.credentials.yaml`；请保护该目录，不要提交到仓库或作为 Issue 附件。

## System3 协同

打开**设置 → System3**，配置可选的 Jev 选路。该功能默认关闭，普通模型任务不需要它。先在**模型**页配置推理服务商和模型，再填写以下内容：

| 字段 | 填写内容 |
| --- | --- |
| Jev 服务地址、协议、模型 ID | 你自己的决策服务地址、对应的 `openjev` 或 `typesafe` 协议和决策模型 ID |
| 凭证引用名与 API Key | 为服务设置独立引用名，如 `APUS_JEV_API_KEY`，并填写服务密钥；仅无认证服务可将引用名留空 |
| 路由候选 | 添加候选模型，填写候选 ID、Provider ID、模型 ID 与何时选择此模型；引用模型页已配置的服务商和模型 |
| 数据类别与远程授权 | 明确选择允许的 `public`、`workspace`、`sensitive` 或 `secret` 输入类别，并批准远程传输 |
| 超时、最低置信度、输入上限 | 决策请求的限制，仅按服务需求调整 |

使用直接 API 地址，不含用户信息、查询参数或 fragment。添加 1–254 个候选模型，ID 必须小写且唯一；`baseline`、`jev`、`abstain` 和 `unknown` 为保留 ID。即使地址为 loopback，所有路由也按网络路由处理，请谨慎选择数据权限。授权覆盖 Jev、候选模型提供商以及对话当前的模型提供商。

勾选**启用协同**并点击**保存配置**。设置表单会在启用前验证必要字段与凭证是否可用。密钥通过现有凭证服务保存，与普通设置分开。新增或轮换密钥须使用新的专用凭证引用名，页面拒绝覆盖已有引用；密钥字段留空可保留原值。若密钥保存成功但设置保存失败，新密钥仍留在凭证存储中，设置草稿会保留供修正。若其他客户端修改了配置，请明确点击“丢弃草稿并载入已保存配置”，再重新操作。

修改后无需重启 Electron。页面显示本地协同服务已关闭、启动中、就绪或失败状态，可点击**刷新状态**重新检查。“就绪”只代表本地插件已挂载，不代表远端模型已响应。启动失败时，请修正配置或关闭协同后保存。

保存不会调用 Jev 或推理模型，也不证明连接可用。请新建对话，发送一个小任务，检查 System3 选路记录和实际模型响应。界面显示建议本身不能证明建议已被采用。部署细节及能力限制见 [System3 配置参考](../../packages/experimental/system3/README.zh.md)。

要恢复普通模式，取消**启用协同**并保存。不能仅凭 Model-as-a-Harness 品牌认定所有协同能力都已启用。
