可直接采用的 README 首屏草案

APUS Reflex Harness

瞬策 · 瞬时执行，深度思考。

让大小脑模型协同管理 Agent 的工作过程。 APUS Reflex Harness 中，Jev 负责有界的即时判断，推理模型负责复杂规划、生成和工具调用，APUS 运行时执行动作、落实权限并记录事实。

我们的目标是 Model-as-a-Harness：让模型逐步管理工具、技能、记忆、上下文和子 Agent。当前已接入入口选路、Skill 选择、任务要求与运行中补充、工程委派管理，并提供可配置的完成证据核验；各项能力需要显式配置。

按任务分工

为符合条件的任务建议模型或工程委派，在执行步骤前选择相关 Skill。允许的候选、隐私策略和实际采纳由运行时检查。

执行中接收变化

把识别出的目标与追加要求保留原文，作为任务上下文；支持把当前任务的补充送入运行中的回合，并转给支持接收输入的子 Agent。

过程有据可查

区分模型建议、实际采纳、模型响应与委派进度。会话保存决策和执行事实，用户可以查看任务交给了谁、补充是否送达及后续活动。

一个已经验证过的协作场景

工程任务交给 Codex 后，用户补充“测试文件改名为 check_ledger.py”。历史验收记录显示，补充送达运行中的 Codex，并体现在后续交付中。这个场景展示运行期间仍能调整任务；它不承诺每句话都能被正确识别，也不承诺固定响应时间。

历史场景与验证范围 · 浏览器验收说明 · 配置与能力限制

开发者预览。 System3 功能属于实验能力，挂载服务不会默认开启上述功能。完成核验已有本地真实验证，仓库部署模板仍为 shadow；长期记忆与 Jev 驱动的上下文管理等能力仍需接入和验证。

对应的英文定位草案

Reflex decisions. Deep reasoning. APUS Reflex Harness brings bounded Jev decisions and reasoning models into one agent runtime. Jev handles focused judgments; reasoning models plan, generate, and invoke tools; The APUS runtime executes actions, enforces permissions, and records what happened.

Our goal is Model-as-a-Harness: models progressively manage tools, skills, memory, context, and subagents. Current integrations cover intake routing, Skill selection, task requirements, input during execution, engineering delegation, and configurable completion review. These experimental capabilities require explicit configuration.

审慎挑战：让读者看见能力，也能核对它

战略不能缩成路由器

入口选模只是已经接入的一段。完整方向仍是模型管理五类 Harness 事务；首页用工作过程组织价值，不以 provider 或模块清单组织价值。

收益需要任务对照

快速判断也会增加一次调用和等待。价值评估应比较完整任务的成功率、人工介入、成功交付时间和成本，并与关闭 System3 的原生路径对照。

可回放是评测基础

会话事实有助于追查策略是否被采用以及后续结果。持续学习仍需数据授权、标注、独立评测和模型更新流程，不能从已有日志推出训练闭环已成立。
