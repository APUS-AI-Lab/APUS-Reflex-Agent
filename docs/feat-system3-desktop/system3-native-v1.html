完整后端 Goal

System1：Jev

判断少量已描述的候选。它不生成完整工作计划，不执行工具，不分配权限，不读取全量日志，也不独立认定 Goal 已完成。规则无法区分候选、且大模型判断的成本明显高时才调用。

System2 与 DSH

System2 完成复杂推理、生成、工具调用和专业工作；DSH 维护任务状态、执行准入、持久化、取消、权限和预算。未来本地 Lead 是生成与编排角色，不能与 Jev 有界判断混为一谈。

一套决策服务、一个官方 SDK，两种 Jev 供给

自有 Jev 9B

自有模型经官方 TypeSafe SDK 的自定义 baseURL 连接 System One 兼容服务；可部署在设备、内网或自有远程 GPU。providerId、模型/checkpoint、实际执行域与接口能力由配置明确；9B 的真实分类与选择质量单独评测。

官方 Jev 原生 API

通过同一个官方 @typesafe-ai/sdk 的 TypeSafeClient.systemOne() 接入官方服务。官方模型供给、响应事实与 usage 单独记录，复用同一 DSH 候选、取消、采用与回放机制。官方 SDK 的单次真实鉴权与三类问题 smoke 已通过；不是路由质量或整体验收。

                 ├→ 官方 TypeSafe SDK → 一个 ctx.jev Registry → 有界决策节点 → DSH 所属服务采用
官方原生 Jev API ─┘
System2：Fidoo / 其他生成 Provider → 原生 ctx.llm → 推理、生成与工具执行

已有 ctx.jev.register / resolve / decide 支持 provider 注册与请求绑定；两种供给共用 Host 侧 SDK provider，以显式 baseURL/model/凭据配置区分，不分别维护自定义 HTTP 客户端；不重复注册第二个 Jev 总服务。现有 provider 仍是直接 Fetch，实现阶段须替换并更新消费者和测试。每次请求先固定 provider 与请求模型引用，再按该供给的数据执行域做准入；响应回执记录实际返回模型。不得把自有模型配置标签当作实际供给，或静默向官方云回退。

官方文档已核对：原生请求要求 state/model/questions；问题须有 instructions；Score 接受 2—10 级。自有服务的 effort 等扩展参数不能未经验证发送给官方。适配器按各供给能力校验和序列化，输出仍规范化为 typed answer，不伪造缺失分数、分布或 usage。参见官方 API 参考。

TypeSafe SDK 接入约束

核对官方 JavaScript/TypeScript SDK 与 v0.6.0 源码。首期固定 SDK 0.6.0 并记录 lockfile；DSH Core、Host、Client、System3 和桌面 runtime 统一正式 0.1.7-rc.2，不能混装 rc.1，外部 SDK 使用自己的版本体系。

  • 显式配置。baseURL 是 API 根地址，SDK 会追加 /v1/systemone；不可重复写 /v1。两种供给各自传入 baseURL、model、apiKey、日志和重试配置，不依赖全局 TYPESAFE_* 回退串用供给。SDK 强制 Bearer；无鉴权自有 gateway 也必须验证其对显式非秘密占位 key 的兼容，官方密钥只发往官方供给。
  • 输入与响应校验。显式构建 SDK 请求，只发送 state/model/questions 及获准扩展，不能展开整个 JevSpec。SDK 会透传额外字段，自有 effort 仅在确认支持后发送。state 顶层限字符串、对象、数组或 null；如需规范化必须记录实际模型可见输入。保留 DSH 候选、概率、Score/legend、模型与 usage 校验；SDK JSON 解析后的静态类型不替代运行时检查。
  • 取消和总预算。SDK 单次 timeout 不含总重试预算；DSH 传入覆盖整个调用的 AbortSignal 与总截止。入口首期明确 maxRetries=0，其他节点只能配置一个重试所有者并受同一预算限制；过期响应不能采用。
  • Host 所属。SDK 只进入 Host provider，不启用浏览器调用。显式控制 SDK logger/logLevel，禁用通用请求/响应正文日志；受控 Session 日志承担重建。客户端仅接收经过过滤的来源、健康与采用投影。

真实预检：官方 SDK 0.6.0 用公开合成状态调用一次，jev-latest 返回 jev-1.13.0；Choice/Score/Noul、概率分布及 usage 检查通过，耗时1369ms（单样本，不代表 p50/p95）。自有 gateway 经独立凭据和临时 SSH 通道，使用同一 SDK 返回 APUS-OpenJev-v1-9B-5949；三类问题和 usage 检查通过，耗时563ms。两种响应均通过现有 DSH 运行时解析器；临时通道已关闭。两次单样本不能用于供给优劣或总体速度结论。结果见不含凭据的预检记录。

配置与回执包含 providerId、requestedModel、实际返回 model、协议/候选版本、执行域、耗时与真实 usage。jev-latest 是别名，不能视为永久冻结模型。自有 9B 与官方的分数阈值、校准及延迟各自评测；切换供给不自动复用另一供给的质量结论。

前端可在设置中选择决策供给、查看健康与降级状态，决策卡默认简洁并在展开时显示实际来源。凭据保存在 Host 管理的 credential store，不发送给客户端。额外远程供给只有在相应数据类别获准时才能进入候选；无获准供给时保留原生 baseline。

3. Jev 在哪些环节值得接入

节点准入标准：输入足够小，候选足够明确，错误容易回退，选择能改变真实行为，并能与规则基线比较。初期建议候选上限 4、每个输入批次每类最多一次判断；它们作为可配置试验参数，不视作模型已验证的能力上限。

环节Jev 的有限职责原生所有者 / 实际动作弃权与限制
入口模型路由
首要交付		在实际可用 Flash / Pro / baseline 中选一个；分类只用于解释处理类型。SessionController 保证输入一次准入；原生 ModelSelection 安装本回合选择。指代不明、输入超限或候选不合法则保留已准入 baseline；人工固定优先。不能把分类标签当任务成功。
Skill / 场景选择
首个过程节点		从少量真实 skill 摘要中选一个或 none；用户显式 skill 直接优先。ctx.skills.snapshot/get；复用加载语义，在 pre-step 形成带来源、可回放的上下文。遵守 modelInvocable、Scope 和版本；自动来源不得伪造成用户手势。目录不完整不宣称穷尽最优；不因此启用不存在的工具。
记忆相关性
后续核心切片		在规则检索出的少量记忆摘要中选择相关项；不要求它生成永久事实。已有 SessionQuery / SessionReferenceResolver 取得来源；System3 上下文消费者限定范围并注入。限定 Workspace / Session 可读范围；用户排除和过期记录由 Host 管理。全文检索不等同于语义长期记忆。
上下文压缩
重要能力节点		对有来源的小块内容分类为保留原文 / 可摘要 / 按需查回，评估局部相关性与遗漏风险。ctx.compaction 的 provider/consumer 处理压缩事务与原生替换；System2 或已验证的摘要器生成正文，规则保护明确事实与工具配对。Jev 不生成全量摘要，不独立证明语义无损。必需事实、来源或版本检查失败就不提交替换；原生 fallback 也必须通过同一检查。保留现有 surface，必要时升级或请求补充，受取消和预算控制。
失败后诊断
后续过程切片		在「读错误详情 / 检查相关文件 / 查看已有测试结果 / 无建议」中选择下一份证据。读取已结算 tool/result；下一 pre-step 注入建议，System2 通过已有工具取得证据。不自动重放未知幂等性的写操作；不抢 overflow compaction、image offload 和 adapter retry。先 shadow 再采用。
专业 Agent 路由
基础委派切片		在声明能力满足条件的少量实际 provider 中选择；一开始只验证一个任务族。ctx.subagents；父子 runId、上下文交接、取消、结果回传和最终答复仍由原生生命周期维护。未安装的 Codex/Claude provider 不进入候选。模型别名不能代替专业委派；不能让同一输入在父子两处重复执行。
Goal 跟进
完整目标维护		依据 Goal revision 与有限真实证据，建议继续、等待用户补充或报告当前进展。ctx.goals + goal-round-driver；CAS 更新、暂停、恢复、实际续轮与预算由 Host 控制。Jev 不认定完成、不自写目标。已完成由独立验收证据或用户确认决定；turn/end 仅表示回合收尾。
主动沟通
会话内先行		在已有重要变化、重复失败或等待输入时，分类为需要报告 / 可合并 / 暂不报告。现有 live Session follow-up 与 Schedule；Host 负责去重、频率限制和取消。排队不等于用户已读。cold 会话后台唤醒、外部通知与跨会话 Goal 单独设计；不宣称已有。
明确由规则或 System2 负责的部分

权限、隐私准入、候选服务是否存在、取消、幂等性、价格计算、预算限制和独立验收使用确定规则；复杂规划、代码修复、深层推理、最终答案生成由 System2 或经验证的本地 Lead 负责。Jev 分数尚未校准，不能显示成成功率。

控制复杂度的方法

  1. 先保留固定基线；没有多个可比较候选时不调用 Jev。
  2. 入口只读必要输入；指代任务可以增加有限、带来源的上下文，超限时弃权，不能悄悄截断关键内容。
  3. 只在新输入、新结果或 Goal revision 变化时触发；不对每个 token 或每个事件调用。
  4. 同一批次去重，超时、取消、无效返回和旧版本建议不能迟到采用；成本、输入大小和调用次数由显式配置限制。
  5. 每个节点独立证明收益后再默认启用；无收益节点可以保留 opt-in 或直接删除。

速度与记忆：用户可感知的原生融合

当前 Jev provider 真实支持 choice（合法候选选择）、score（有序语义等级）与 noul（二值命题分数），以及有界问题、分布与 usage。它不是现成的长文生成压缩器。三种接口按节点需要使用，不为覆盖所有协议而增加请求；相关判断可在同一有界 state 中合并，批量是否节省延迟需实测。

让 Agent 使用起来更快

入口与能力

选适合的模型，明确 Skill 与专家候选，减少错误路径和返工。已有有效选择不在每一步重复评估；模式固定时入口不增加 Jev 请求。

上下文与记忆

小候选相关性判断，减少无关历史装载；关键事实保留原文，按需恢复来源。沿用 DSH 的稳定前缀与压缩机制，避免无谓改变请求前缀；不凭架构推断已命中缓存。

反馈与跟进

及时显示实际阶段与可撤销状态，避免用户重复提交；有限诊断减少盲目重试，Goal 基于真实变化跟进，停止无进展空转。

以首次有效响应、端到端完成耗时、返工次数和成功率为主要指标；同时记录 Jev 额外耗时、超时、弃权、上下文 tokens 与费用。视觉反馈更及时不等于任务执行更快；压缩省下的 tokens 要扣除判断、摘要与查回的总开销。Jev 仍走串行关键路径的部分必须计入延迟。

「无损」的分层实现与验收

层次可承诺的行为验证方式
原始记录保存压缩不删除已经持久化的原文与必要附件；保持来源、范围和内容校验信息。压缩前后逐项读取、核对内容与可访问性；原来未记录或已经过期的外部内容不冒充可恢复原文。
明确的关键事实用户约束、Goal revision、验收条件、精确标识、路径和关键数值作为受保护内容或带来源的原文引用保留。由明确声明与原文提取形成必需项；确定性对照确认存在与来源正确，缺少任一必需项不得采用该次摘要。不能仅靠 Jev 分数放行。
摘要与按需恢复摘要保留原始范围和 sourceRef；信息不足时取得原文或补充上下文。测试恢复与回放、来源拒绝/缺失、长程事实问答和任务续做；上下文容量不足时应显式升级或请求补充，不能偷偷丢弃必需事实。
语义任务质量以压缩后任务质量不退化为目标，持续评测遗漏、矛盾和用户重复解释。与完整上下文基线比较。摘要加可恢复来源不等于模型始终看见全部事实，不承诺任意语义的数学零损失。
已持久原文与来源
→ 规则保护明确事实、权限、工具配对与容量
→ Jev 对少量块做保留/摘要/查回选择，或弃权
→ 原生 compaction 摘要器生成候选
→ 检查必需事实、来源与版本；不通过则不采用
→ DSH 持久压缩事务和上下文替换
→ 续做任务与按需原文恢复；结果回到同一证据链

DSH 现有压缩保留被遮蔽的 Session 原文，已有基础。此次目标是沿原生 compaction 能力改善内容选择、必需事实保护与恢复体验。触发压力、错误恢复和事务所有权继续由原生机制维护；调用 Jev 的块大小、次数、超时和压缩收益阈值均可配置。是否能比现有压缩更快、更稳需要真实对照。

源码依据：Jev 当前 typed 协议、原生 Compaction与摘要调用与前缀复用实现。

4. 第二名桌面载体与 rc.2 对齐

选定 dataelement/dsh-desktop 的交互与桌面载体。它通过 Electron 子进程调用 DSH CLI 的 Web profile，复用原生 Conversation；并未实现另一套 AgentLoop。System3 决策保留在后端，Electron IPC 继续只处理目录选择、窗口、重启、更新等桌面操作。

对齐源码与产物，不能只改版本字符串

实际共同祖先核对确认我们基于 rc.1 追加了定制提交；rc.1→rc.2 有 346 个提交、3433 个文件变化，其中包含大量双语和生成文件。我们的定制变化与升级交叠 46 个文件，需要重点复核 SessionController、CLI、目录生成器、SDK 回放和 Python smoke。

桌面当前还带 25 个 rc.2 DSH 补丁，加上 Cordis loader 与 undici 补丁共 27 个。SessionController 的 handle 保留、删除、preset fallback 会影响恢复和销毁；Conversation 外框与模型搜索也有补丁。不能简单替换 package.json 后假定兼容。

  1. 先对齐核心。在独立工作分支合并正式 rc.2 源码，逐项保留 Jev router、取消、人工固定优先、单回合选择及持久事件；重跑相关行为与双 SDK 回放。
  2. 建立桌面补丁映射。逐个标记：上游已覆盖、需要合入 System3 源码、仅桌面层需要、暂不采用。对自有源码已经合入的改动不再次 patch-package。
  3. 由桌面加载自有产物。先以显式 runtime 路径做开发联调；安装包使用固定的私有本地包集合或已有生产运行时打包机制，确保加载路径、Client Modules 和 Host 均来自同一构建。具体复用打包脚本在 rc.2 核心合并后验证。
  4. 安全模式保留可信基础。禁用第三方插件；保留原生会话与模型、System3 状态读取和自动模式控制。Jev provider 不可用时使用获准 baseline 并显示降级，不能把安全模式悄悄当完整 System3。
  5. 更新原子匹配。桌面、Host、Client、Session schema 和 System3 特性版本共同记录在 build manifest。检测到错误运行时或混装依赖时启动失败并给恢复方式；开发联调与安装包分别验收。

只在隔离数据目录验证。历史 Session 世代保留，持久格式升级遵循原生相邻迁移；共享 CLI/桌面数据前核实实际 profile 和凭据兼容。PPT、市场和远程访问是桌面配套功能，按需组合，不替代 Jev 核心验收。

可信安全 profile 独立保留 System3 持久事件解码、回放与投影消费者；禁用 Jev provider 不得导致既有 Session 无法读取。provider 不可用时，新输入使用获准 baseline 并显示降级，正常模式的自动意图不被覆写。验收覆盖「已有 System3 日志 → 安全模式打开 → 正确回放 → 降级输入」，不能通过忽略旧事件或换回 stock DSH 恢复。

6. 原生接口草案与状态模型

本节是新增接口设计草案，名称与字段须在 rc.2 源码合并后定型；不是已经存在的公开 API。现有 session/prompt、SessionPromptRouter 与原生事件继续复用。

建议接口 / 状态输入与返回行为约束
session/setRoutingModesessionId、expectedRevision、mode(auto/fixed)、fixedSelection；返回 revision、effectiveFrom。Session 级 CAS，和 prompt admission 序列化。当前执行不被悄悄重路由；变更明确影响下一准入。恢复自动不改全局默认。

Jev 供给配置 / 投影providerId、模型引用、协议能力、实际执行域、健康与降级状态；凭据只用 Host 引用。复用单一 ctx.jev registry。provider 变更在下一决策生效，已开始请求与已采用动作保持绑定；旧响应不能跨供给版本采用。
统一决策回执decisionId、sessionId、input/turn/stepRefs、nodeKind、goalRevision、candidateVersion、outcome、selectedId、elapsed/usage。输出只能引用合法候选或弃权；原始请求由受控日志保存用于重建。过期、取消、无候选和无效返回分别记录。

Goal 维护使用现有 Goal id/revision 与 phase API；补预算和检查引用。原生续轮所有权不变；重启与 fork 的 disarmed 保留，用户明确恢复后继续。Jev 建议不得直接变成 done。

8. 多层评审与实现可行性

架构可行性

入口 router 已在本仓库真实工作；Skill/来源上下文、Goal 与 Subagent 有原生机制。接入路径可实现，但每种行为需要自己的消费者与验收。不能由现有 shadow 库推断已具备全流程监督。

模型能力限制

少候选分类与选择是合理试验方向，尚未证明这个 Jev 9B 在每类任务上的可靠性。难例弃权，由 System2 接管；不依赖未校准分数授予控制权。

产品与工程成本

rc.2 和桌面补丁是当前主要风险；先统一产物再加节点。用户只需理解当前模式、实际采用、待办与恢复，默认不展示大量内部协议。

需要纠正的现有缺口

  • 现有人工选择没有恢复自动操作；当前 wire modelSelection 只有 lastUsed/next。需要后端模式状态，不能仅补按钮。
  • 现有 entry-decision 与 shadow 投影不是完整 Client-safe 决策链；必须补真实采用、结果与缺档处理。
  • 现有 supervisor 信任外部 checks，不能代替 verifier。空必需检查、过期或不存在的证据不能放行完成。
  • DSH Goal 默认没有费用/Token/时间预算；Schedule 只处理 live 根 Agent。长程可靠性要明确补预算与运行条件。
  • 连接远程 GPU 的 Jev 9B 仍是远程执行；未来设备上本地 Lead 必须另行实测资源与工具能力。

以“规则没必要覆盖、System2 完整判断成本高、Jev 可以在小范围内可靠选择”为取舍标准。若某个节点规则已经足够、输入太长或错误成本高，就省掉该次 Jev 调用。设计深度来自真实的原生采用与结果闭环。
