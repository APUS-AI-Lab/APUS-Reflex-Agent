# README 与架构图发布设计

[English](readme-loop-working-design.md) | 中文

## 目标

依据当前代码与限定范围的证据解释 Personal Agent 和 Loop Working。保持两仓独立，区分运行时合并与已验证的桌面发布。

## 架构

输入事实写入持久 Session。可选 Reflex 决策指导允许的动作。Continuum 恢复带来源的记录，形成有界模型投影；生成模型推理，Harness 执行，结果回到 Session。架构图沿用现有浅底橙色样式，使用支持离线查看的系统字体。

## 文件与 API 影响

更新根 README 双语对、架构 SVG／HTML 和贡献者任务清单。审阅受跟踪文档、原始证据和二进制附件，将不适合公开的原件归档到仓库外并修复引用。本轮不修改运行时 API 或持久化格式。

## 验收

- 准确说明同 Session 恢复、成功 flush、显式准入和 Reflex 专属启用条件。
- 区分保留源文本与可能不完整的检索、摘录和摘要。
- 链接测试，不把模拟 provider 检查描述成真实 provider 效果证明。
- 验证双语文档、引用、SVG 无障碍、渲染布局与受跟踪文件秘密扫描。
- 仓库可见性或所有权变更前单独审阅历史；仅当前文件树干净不足以判断可发布。

## 重启证据修正

共享请求日志和重复召回短语可能让首进程或新准入的查询文本满足当前重启断言。仅修改正式 profile 记忆测试：分开进程日志，查询不包含已存的唯一标记，在恢复进程请求中断言完整原始事实与记录归因，并增加新 Session 负控。针对源码和构建产物启动路径运行定向无密钥测试。不修改生产 API 或格式。

## Loop Working 叙事重设计

用户已批准的重设计先呈现 Personal Agent 价值，再解释目标约束的持续工作、模型决策、受控执行和证据反馈。八节点总览展示默认生成路径和可选 Reflex／Continuum 增强；六节点记忆细图区分持久源事件、准入、来源关联记录、派生检索、可选选择与有限请求投影。两图沿用现有视觉皮肤，采用离线 SVG／HTML，并链接到实现归属。英中 README 与 Frontend 入口叙事采用相同职责划分。

源记录是事实依据；自动文本准入会 trim，图片存储可能归一化，持久性需要成功 flush。Goal 状态可以恢复，但续轮激活在重启后解除，需恢复授权。不宣称无限物理存储或万能召回。验证覆盖 SVG 可访问性、视觉检查、双语配对、本地链接、正式 profile 记忆场景及配置回归；新文案不把剩余发布验收变成已通过。
