# Continuum × Reflex 集成验收

[English](integration-plan.md) | 中文

## 集成状态

记忆和控制面两个源分支都已进入 `main`。后续验收修复由独立集成 worktree 承接，发布状态和实际运行证据统一记录在[发布就绪审计](release-readiness.zh.md)。源码已包含不等于功能已验收。

## 共享实现职责

- `deploy/system3/runtime.patch.yml` 组合控制插件、Continuum 及可选 Jev 选择器。记忆保持默认关闭；缺少 Session 分类时关闭 System3，通用模型执行仍可用。
- Session 事件声明与持久化保留所有模型可见输入及来源引用；已发布的历史格式世代保持不可变。
- 依赖元数据、生成目录和回放预期描述合并后的实现。
- 修复归属相应功能包；共享配置和两个 SDK 的投影分别验证。

## 验收矩阵

| 场景 | 所需证据 |
| --- | --- |
| 原版 profile | 无 Continuum 或未配置 Jev 服务时通用模型仍可执行。 |
| 开关生命周期 | 配置变化、off/shadow/active 模式及 reload 保持文档规定的投影行为。 |
| 进程重启 | 持久化 Session 事实、record ID 和来源引用在真实进程替换后恢复。 |
| 更正与冲突 | 被取代的事实不再充当当前记录；拒绝的修订不产生部分提交。 |
| 权限与范围 | 未授权 scope 和记录不进入 recall 或模型请求。 |
| 预算与长历史 | 配置的摘录预算生效，请求拼接开销单独计量，长历史可重建。 |
| 停用与卸载竞态 | 关闭、释放或卸载后，在途读取与迟到 Jev 答案不能注入。 |
| Jev 故障 | timeout、cancel、abstain 及文档规定的 fallback 可观察、可恢复。 |
| 派生索引 | 索引与直接检索保持一致匹配语义，持久化 Session 记录为准。 |
| 并发持久化 | 重复 flush 不重复记录，写入失败不能静默丢失已接受的数据。 |
| 控制面联动 | Goal、上下文、监督及运行时配置不相互覆盖状态。 |
| SDK 回放 | TypeScript 与 Python 保留各自模型可见投影，记忆具备录制 Session 判据。 |
| 真实产品链路 | 明确配置的 Jev 和生成服务执行真实请求，浏览器状态与磁盘证据一致。 |

## 发布条件

发布要求已解决的冲突有解释和测试，适用场景有证据，并在固定源码和构建产物上完成最终仓库检查。任何失败、跳过或未执行平台都在就绪报告中明确保留。本矩阵通过不承诺无限存储、跨 Session 召回或所有任务的质量。
