Your models. Your Personal Agent.
Work that can keep moving.

Loop Working connects planning, action, inspection and adjustment around a goal. Memory brings relevant facts back, decisions guide the next step, and the Harness executes actions while recording evidence.

THE USER VALUE

Turn a single answer into an ongoing project.

For example, build a personal portfolio over multiple work periods in one Session: retain design constraints, create content and pages, run checks, and revise using feedback. After an interruption, recover facts and state from the same Session, then explicitly resume. This explains the intended workflow; it does not claim every scenario has passed end-to-end acceptance.

Your models, with distinct responsibilities

A general model plans, generates content and requests tools. Reflex / Jev handles bounded choices, scores and supervision advice. The Harness manages configuration, permissions and lifecycle. General models can run independently; an arbitrary chat endpoint cannot automatically replace every Jev decision protocol.

01 / PRODUCT & TECHNICAL ARCHITECTURE

One Personal Agent: decide, execute and remember.

This diagram combines product capabilities and technical responsibilities. User requests enter the Harness; general models plan and generate, while Codex is an optional delegated executor. Reflex is an optional decision layer, with Goal supervision focused on Codex execution. Enable capabilities separately; validate advice before adoption. Basic Session recovery works without Jev. Continuum is an explicitly enabled memory enhancement.

02 / MEMORY AND CONTEXT

Finite windows. Work that can continue across them.

A model sees a bounded input in each request. Persistent history retains the source evidence; retrieval and projection assemble relevant context for the next request. Continuity comes from recoverable state and evidence, rather than placing all history in a single prompt.

Define what “lossless” means

Successfully committed and flushed source events remain the factual record; summaries do not replace them. Automatic memory admission applies trim() to text. Images may be normalized or resized, and attachments and tool output can use separate references. Source retention does not guarantee preservation of every uploaded byte, unflushed crash-time data, or complete recall in each request.

Two distinct cache concerns

Continuum can rebuild its retrieval index from Session records. System3 context projection protects submitted prefixes and can append recovered content. Derived retrieval data and request-content management do not imply unlimited KV cache, provider cache hits or lower costs.

04 / WHAT MAKES IT RELIABLE

Control continuation, stopping and acceptance.

Goals and control

Goal revisions and continuation limits constrain ongoing work. Cancellation, competing input and lifecycle checks reject late actions. State survives a restart; automatic continuation requires explicit resume. There is no unified hard dollar or token budget covering every execution path.

Permissions and data policy

Reflex grants no tool permissions; the Harness owns tool approval. System3 classification and routing, and Continuum scope filtering, govern their respective requests. They are not a global operating-system network firewall.

Results and acceptance

Proposing corrective advice, adopting it and improving a task are different facts. Completion requires actual deliverables and relevant checks, rather than a model claiming success. Supervision and recovery do not guarantee every task will succeed.

Failure and fallback

The general path remains available without explicit optional configuration. Enabled but invalid configuration fails clearly. If decisions are unavailable, use only permitted baseline behavior; do not silently choose a new external service.

Evidence and current limits

Five deterministic cases have run through the shipped headless profile: source and built cross-process recovery, no Reflex, disabled memory, and a new Session in the same workspace. Recovery checks persisted source records and sourceRefs; only the old fact in the second process’s separate request log can satisfy the assertion.

These cases establish storage, recovery and model-request injection. Live-model quality, large-scale retrieval, long-running goal outcomes, full regression and signed native packages require separate acceptance. This is a developer preview; an architecture diagram is not a release certificate.
