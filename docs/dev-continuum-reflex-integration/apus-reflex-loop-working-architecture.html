让工作形成可以继续的循环。

Loop Working 的价值，是让一个目标经历计划、行动、检查和调整，持续走向可验收的结果。记忆让重要事实可以回来；决策判断下一步；Harness 负责把动作可靠地执行并留下证据。

THE USER VALUE

把一次回答，延伸为一个持续推进的项目。

例如，逐步完成自己的作品集：留下设计约束，生成内容和页面，运行检查，依据反馈修订。中断后恢复同一 Session 的事实和工作状态，再明确授权继续。这个例子解释产品工作方式，不是全部场景已经端到端验收的声明。

自己的模型，意味着可选择职责与提供方

通用模型负责开放式规划、生成与工具请求；Reflex / Jev 提供有界选择、评分和监督建议。两类能力都通过 Harness 的配置、权限和生命周期管理接入。通用模型可以独立运行；当前没有“任意聊天模型替换所有 Jev 决策协议”的实现保证。

01 / WORKING LOOP

目标决定为何继续，证据决定如何继续。

这是职责与信息流图，不是逐事件时序图。Reflex 的路由、记忆选择、上下文恢复和监督分别启用；System3 未配置数据分类时默认关闭，仍可使用通用模型。Goal 的持久状态和恢复后的执行授权分别管理。

02 / MEMORY AND CONTEXT

“无限上下文”的工程方向：窗口有限，工作可以跨窗口延续。

模型本轮只看到有限输入。持久层保留事实依据，检索和投影为下一轮构造需要的上下文。连续性来自可恢复的状态与证据，而非把所有历史一次性塞入提示词。

“无损”需要说清楚保存的对象

成功提交并 flush 的源事件作为事实依据，摘要不替换它们。自动记忆会 trim() 文本；图片可能归一化或降采样，附件与工具输出还可能通过引用存储。因此“无损输入 / 无损记忆”应限定为来源记录的保留原则，不能扩大到所有原始字节、崩溃前未落盘内容或每次召回。

两种不同的缓存问题

Continuum 检索索引可以从 Session 记录重建。System3 上下文投影保护已经提交的前缀，并支持追加恢复内容。前者是派生检索数据，后者是请求内容管理；两者都不等于无限 KV cache，也不证明供应商缓存命中或费用下降。

03 / SIX RESPONSIBILITIES

六层共同支撑循环，不让模型建议直接变成执行权。

层真实职责实现入口
输入事实层接收消息和执行事件，保留可追溯来源；持久化以成功 flush 为准。Session
Reflex 决策层对有界候选提出建议，校验隐私、作用域、有效 revision、取消和置信度后采纳。决策 / 监督
Harness 执行层调度工具、技能和子 Agent，管理权限、审批、生命周期与退出。工具执行
持久记忆层记忆内容和 sourceRefs 以 Session 事件保存，派生索引可以重建。Continuum
上下文投影层将有界片段送入模型请求，提供归因；可选保护冻结前缀和恢复内容。召回投影 / 前缀保护
结果反馈层区分已建议、已采纳、已执行和效果，向下一轮提供可检查依据。续轮驱动 / 反馈证据
04 / WHAT MAKES IT RELIABLE

记忆之外，还需要可控地继续、停止和验收。

目标与控制

Goal revision 与续轮上限约束持续工作；取消、竞争输入和生命周期限制迟到动作。重启后保留状态，但恢复续轮需显式授权。当前没有覆盖全部执行路径的统一美元或 token 硬预算。

权限与数据策略

Reflex 不授予工具权限，工具审批仍属于 Harness。System3 数据分类与路由策略、Continuum 的 scope 过滤分别管理各自请求；它们不是操作系统级全局网络防火墙。

结果与验收

“发出纠偏建议”“采纳建议”和“任务改善”是不同事实。任务完成依赖实际产物及对应检查，不能只凭模型一句完成。监督与恢复有各自限制，不能保证任意任务自动成功。

失败与回退

缺少显式配置时保留通用路径；启用但配置错误应明确失败。决策不可用时只使用允许的基线，不悄悄选择新的外部服务。

当前证据与产品边界

正式 headless profile 的五个确定性记忆场景已经实际运行通过：源码 / 构建产物跨进程恢复、无 Reflex、关闭记忆、同工作区新 Session 隔离。恢复测试核对持久源记录与 sourceRefs，且只有第二进程独立日志中的旧事实能满足断言。

这些证明存储、恢复与模型请求注入；真实模型质量、大规模检索、长时目标效果、完整回归、签名原生包仍须分别验收。项目处于 developer preview，架构图不是完整发布验收证书。
