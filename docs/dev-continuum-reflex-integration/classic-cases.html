最容易被记住的三个瞬间

适合短视频开场、发布会演示和 GitHub README 首屏。先让人看到结果，再解释架构。

已验证 · shipped src/lib

“我昨天说过的话，今天不用再说一遍。”

真实双进程测试已验证：事实写入、Session 重启恢复，并在第二进程 provider request 出现原文和来源。标题可用：AI 终于记得上下文之外的事。

已验证 · real Jev

“上下文满了，但 Decimal 没被压掉。”

真实 Jev 场景已验证：旅行内容可整理，Decimal 和原始文件保护仍出现在模型请求里。标题可用：AI 会忘记闲聊，但不会忘记不能犯的错。

部分验证 · 需补权限负向 E2E

“记忆可以回来，指令权限不会跟着回来。”

历史数据标记和来源引用已有测试；“恢复内容不能触发执行权限”还需要独立工具调用负向 E2E。标题可用：记住信息，不继承风险。

待补 · provider 切换 E2E

“换模型了，项目记忆没有丢。”

Session 作为事实源的设计已存在，但当前没有完成模型 provider 切换后的完整黑盒验收，暂不能当作已通过案例传播。标题可用：模型可以换，记忆不用迁移。

已验证 · negative controls

“关掉开关，AI 立刻回到原版。”

shipped profile 已验证 no-reflex 和 disabled：不产生 memory record，也不注入 recall。标题可用：无限记忆是能力，不是绑定。

部分验证 · matrix evidence

“Jev 先旁观，再接管。”

Shadow/Active 的组件和决策矩阵已有覆盖；仍需在同一 shipped profile 中补齐完整 shadow receipt 与 active provider request 对照。标题可用：AI 决策也可以先灰度。

部分验证 · bounded retrieval

“长对话不再等于长账单。”

有界 working set 和字节预算已有单测，但尚未完成 provider 计费或 token 曲线的产品级基准，因此只能传播为设计能力。标题可用：无限记忆，不等于无限 token。

已验证 · restore attribution

“恢复一个历史决定，并核对出处。”

真实恢复场景已检查历史事实、event/block reference 和 reflex-memory 来源。标题可用：召回事实，可以核对出处。

已验证 · real Jev

“无关内容会退场，关键内容会留下。”

严格真实 Jev 场景已验证旅行内容可移除，同时财务约束保留。标题可用：不是把所有东西都记住，而是知道什么不能忘。

已验证 · provider request

“测试不是看日志，是看模型真的收到了什么。”

shipped profile 测试直接捕获第二进程 provider request，检查 continuum-memory、record id 和召回文本。标题可用：无限记忆，必须在模型请求里证明。

传播公式：一个人 + 一个具体事实 + 一次进程重启 + 一条 provider request。不要先讲“无限上下文”，先让观众看到“第二天它真的还记得”。

五个值得记住的故事

这些案例覆盖能力、边界和失败时的原版兼容路径。

PASS · safety

财务 CSV：精度不能被压缩掉

用户要求金额必须使用 Decimal，原始 CSV 不可修改。上下文整理可以移除无关旅行内容，但 precision 和 file-integrity constraint 仍保留；真实 Jev 测试还验证新 Host 能恢复旅行事实。

PASS · compatibility

没有 Jev：系统照旧工作

未接入 Jev 时，Continuum 的 Reflex 专属开关不生效。任务继续走原 provider 路径，不写 memory record，也不注入 recall。

PASS · control

开关关闭：记忆不会偷偷工作

即使插件配置存在，disabled 场景也不产生记忆召回。这个负向测试证明“无限记忆”是显式能力，而不是隐式改变原版行为。

部分验证 · 来源标记

历史内容以数据身份恢复

Reflex 恢复内容通过 reflex-memory 标记为历史数据，带 event/block 引用。这证明来源归因；阻止历史文本诱导工具执行仍需独立负向 E2E。

MATRIX · decision

Shadow 与 Active：同一候选，两种职责

Shadow 让 Jev 观察并记录 decision receipt，但保留 baseline；Active 才应用 selected ids。路由失败或隐私拒绝时回退到确定性 baseline。

必须诚实记录

全仓绿，不等于核心链路通过

组件测试不能代替真实进程；无密钥回放不能代替真实 Jev；跳过和未执行都不能计为通过。发布页必须同时展示证据和剩余基线问题。

三种运行方式的差异

同一套产品可以从原版兼容开始，再按需打开 Reflex 专属能力。

原版

没有 Jev 或开关关闭。无自动准入、无 recall 注入，保持既有 provider 行为。

Continuum Active

记录事实、重启恢复、检索有界 working set，并把 attribution 完整带入模型请求。

Continuum Shadow

让 Jev 参与观察和评估，不改变 baseline，适合灰度、对比和风险审计。

发布判断：只有“用户输入 → Session 事件 → 真实重启 → provider request → 归因检查”全部可见，才能把案例写成已验收能力。
