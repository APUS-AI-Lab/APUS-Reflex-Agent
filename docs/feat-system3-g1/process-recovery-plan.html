遇到输入问题时，
让 Jev 选择下一种处理方法

先验证一个完整、可解释、可回放的过程决策：公开 CSV 或文档读取失败后，选择定位文件、请求明确输入或弃权，由原生 Harness 采用，大脑继续执行。

本方案的目标是证明过程决策能实际改变执行方法，并测量它是否带来收益。完整专家编排、本地 9B/27B Lead 与任务自动完成判定沿用各自后续里程碑。

1. 为什么选择这个场景

当前原生 llm-retry 已处理模型请求的重试与 backoff，repeat-tool-reminder 已提示重复工具调用。新增恢复消费者只处理原生只读文件操作的明确缺失错误，选择下一种方法；原生重试和重复提醒继续拥有原来的职责。

文件可能存在

用户提供了过时路径，公开工作区内有明确目标。先定位真实文件，再读取和生成成果。

必要输入缺失

工作区没有足够线索，或用户尚未提供资料。请求具体位置或补充输入，避免反复猜路径。

证据不足

Jev 弃权、超时或返回无效结果时，由现有大脑与原生工具流程继续处理。

3. 准入与动作约束

项目拟定行为
失败事实只识别可核验为原生 read 的 FS_NOT_FOUND；从已提交 tool/call 与关联 tool/result 取事实。未知同名工具、任意错误文本和复合工具不参与。
时机agent/pre-step 先委派 next()；拒绝、取消、新输入改变任务、工具能力变化或失败已处理时不采用恢复。并行工具批次完成后再读取一致事实。
locate_input注入固定指令：先用当前允许的只读定位能力核实输入位置，再决定是否继续。具体调用由大脑生成，仍走原生工具检查。
request_input注入固定指令：说明缺失的输入并请求明确位置或材料；交互使用现有原生能力。
abstain / 不可用保持原生流程。Jev 超时、失联、低置信、无效候选和过期响应均不得产生迟到指令。
副作用第一版不接管写操作、权限拒绝、外部服务或任意 shell 失败；恢复消费者不直接执行工具、不重放失败动作、不批准权限。
配置恢复默认关闭，明确 profile 启用。输入字节上限、deadline、置信阈值、每回合次数和允许的数据分类均为有效 Config；实际 profile 显式 high。取消、deadline 和插件生命周期共同约束请求。

4. 数据与前端契约草案

新增 system3/recovery-decision 持久事件和专用消息来源 system3-recovery。精确字段在实现中沿现有 branded ID 与 Session 类型定义，不把自由生成的计划作为执行命令。

记录字段与关联要求
决策事实decision ID、Session 内 turn/step、失败 call/result seq、当前输入消息 ID、候选动作、完整获准 Jev 请求和响应、outcome、elapsedMs、状态版本、精确 injectionMessageId。
去重与时效通过持久事件投影记录失败是否消费及回合次数；重复 pre-step、刷新和 resume 保持一致。返回时重新核对当前任务与能力，过期即弃用。
采用事实只由原生 user/message 提交且精确 injection ID 匹配确认。决策返回、拟注入和实际进入模型上下文分别记录。
Client 投影system3Runtime 增加恢复摘要并升级缓存版本；只投影必要状态与动作，不传完整 prompt、原始错误或工作区路径。
用户可见“遇到输入问题”→“已选择：先定位文件 / 请求补充输入”→“策略已采用”。后续执行仍由实际工具卡片显示；没有目标文件关联证据时不显示“恢复成功”。
兼容新增 SessionEventMap / MessageSourceMap 需要持久化类型确认、两 SDK 同步及记录回放。先核对旧读者接受规则，再定义升级与回滚范围；不推定旧版可读新增事件。

6. 验收与三组对照

  1. 错路径但工作区存在目标 CSV：选择定位方法、实际读入正确文件、生成成果，外部 oracle 核验文件内容。
  2. 必要输入确实缺失：提出具体输入请求；不循环猜测路径。
  3. 取消、超时、失联、低置信、非法候选、过期状态：无迟到注入；保持原生可继续状态。
  4. 同一失败重复 pre-step 和 resume：最多一次采用；取消后晚到响应不改变状态。
  5. 权限拒绝、写入失败和未知工具：不进入恢复消费者。
  6. 只有建议、只有拟注入、真正采用三类投影负例；刷新、回放及两 SDK 对应事实一致。

对照组必须包含：原生大脑自行恢复、确定性“先定位”规则、Jev 三动作策略。固定任务、资料和质量门槛，保留失败，统计端到端耗时、无效工具调用、总 Token / 成本及成功率。单个文件错误很可能用规则即可解决；只有实测净收益才能支持扩大 Jev 控制范围。
