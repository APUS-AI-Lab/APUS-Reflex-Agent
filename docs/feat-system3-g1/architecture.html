02

三层智能，表达为同一个任务体验

默认界面让用户能说出四件事：现在做什么、已经得到什么、还有什么未验证、我能怎样接管。技术细节放进展开层，重要方法变化留下可追溯记录。

入口智能

希望感受到：我一提交就得到回应；系统选择合适方法，缺关键资料时只问影响执行的问题。

当前落地：本地提交反馈、合格文本入口的自动选模、人工固定与恢复自动。澄清、附件及更多入口策略仍需接入。

过程智能

希望感受到：系统沿进展换方法，记住约束，遇错会先查证据，需要时让专家接力。

当前落地：自动选择并注入一个专业 Skill。取证、约束保护、压缩和专家策略还未形成 System3 闭环。

体感智能

希望感受到：等待中有清楚变化，成果逐步出现；离开再回来，状态可信、操作可达。

当前落地：已收到 / 决策 / 运行反馈，展开查看建议、采用、响应及 Skill 注入。完整任务、上下文与验收工作台仍是目标。

目标工作台：一条主线，按需展开

主区 · 工作与成果输入、原生 Conversation、工具结果、产物与下一步；任务回执就地更新。
上下文 · 实际使用已注入的方法、保留约束、来源原文、排除范围与数据去向。
目标 · 缺项与恢复阶段、检查结果、预算、等待原因；普通任务不强加长期 Goal。
记录 · 建议到结果默认简洁；展开核对建议、采用、请求、响应、证据和控制结算。

体感速度由真实变化支撑

  • 输入提交立即回显，Host 接收与准入分开报告；首次确认、首个有效成果和总完成时间分别测量。
  • 普通路由保持一条紧凑状态；Skill 加入、失败取证、专家交接、产物通过检查时才留下有意义的变化记录。
  • 成果显示草稿 / 待检查 / 已验证；未知进度不显示百分比。流式输出保持稳定布局，遵循减少动态效果偏好。
  • 停止请求已接纳与所有工作已收尾分别显示；恢复后先读记录，不用旧状态制造“正在运行”。

03

Jev × Harness：当前融合与完整目标分别看

每个原生 Agent 的回合由自己的执行 owner 管理；Host 复用同一执行机制，多实例各有 Session。Jev 是其中的有界判断服务，System2 负责生成与工具请求；UI 消费事实，原生服务负责采用与结算。

融合要验证什么：Jev 的选择实际改变下一步方法；推理模型与工具结果反馈到后续判断；权限、取消和验收始终由原生 Harness 执行。只更换模型名或显示决策状态，不足以证明这一闭环。
当前发布 · 两套实例，各自运行原生闭环
目标设计 · 事件触发、原生采用、结果与恢复贯通
原生采用的位置：入口模型由 SessionController 采用；Skill 指令由 AgentLoop 实际提交；压缩由 Compaction owner 提交 replacement；专家由 Subagent 管交接；Goal 由自己的服务管理状态和续轮。新增判断不替代这些 owner。
接入节点触发与有限选择实际采用要求状态
入口选模合格新文本；Flash / Pro / 弃权合法候选与准备完成；同 requestId 采用，按对应 turn 的模型内容确认响应已发布实测
专业 Skill存活输入、作用域目录；至多一项 / 弃权重查目录与可调用性；精确 injection message id 成为原生 user/message已发布实测
失败取证已结算失败；错误附近片段、头尾、来源读回等策略复用 spill / read；记录实际取回及下一请求使用；不自动重放写动作目标接入
约束与记忆有来源的小候选材料；保留 / 查回 / 排除来源版本、范围与排除有效；实际请求中的注入可追溯目标接入

切换场景查看调用者、实际 owner、日志事实与用户体感。前三条说明当前能力，后三条说明目标设计；此演示不连接后端、不调用模型、不执行工具。

05

接口与事件：建议、采用和实际使用各有事实

使用原生 Session Remote、follow 流和 projection；不新增前端直调 Jev 的接口，不把设计字段写成已发布 API。

当前 API / 投影职责必须保留的语义
session.prompt / selectModel / resetModelSelection准入新输入，人工固定，后续恢复自动固定模型只跳过入口 Jev；自动 Skill 仍可独立触发。实际调用名称来自原生 Remote namespace。
session.cancel / updateQueue / follow 与历史读取停止当前回合、管理队列、订阅与恢复普通 cancel 保留 pending inbox；不能代表所有未来任务、专家和提醒均已停止。
modelSelectionmode / next / lastUsed表述原生选型配置；lastUsed 或 request/header 不能独自证明模型响应。
system3Runtimeentry.suggested / adopted / used；skill.selected / injectedClient-safe 事实，stateVersion=3；响应关联该 entry.requestId 对应输入的 turn 与模型内容。entry / skill 为最新历史事实，当前运行状态来自原生 Session。
ctx.system3.shadowDecision / evidence / supervise显式影子判断与纯函数辅助不构成生产全过程控制器；挂载库不等于启用取证或完成监督。
事实层实际记录 / 来源能说明什么
入口判断system3/entry-start、system3/entry-decision开始与结构化建议；可记录弃权、低置信度、超时或不可用。
原生采用model/automatic-selection；同 requestId可采用 Jev 的合法建议，也可采用合法 baseline；adopted 不必然是 Jev 选择成功。
Skill 与模型输入system3/skill-decision → 精确 id 的 user/message，来源 skill-invocationSkill 被选择与指令真正进入请求分别确认；不新增工具权限。
实际输出与执行assistant/message、含内容的 assistant/attempt、tool/result纯 usage、placeholder、合成 finish:error / aborted 不能证明收到模型内容。
成果验收原生工作区产物 + 独立 verifier 结果已生成不等于已通过；验收须关联具体产物、检查、来源与版本。
实时生命周期原生运行状态、agent/* / subagent/start/end 等 live 事件实时事件并非同名持久 Session 事件；持久日志与 live 状态分开使用。

06

记住什么、在哪里保存、回来怎样接着做

执行和模型可见输入以所属 Session 日志为依据；文件和原生业务存储由各自服务保存。Desktop 与服务器的 Session、工作区、凭据相互独立，当前没有已验收的自动同步。

数据 / 状态实际 owner当前与目标
对话、请求、工具和 System3 决策所属 Host 的原生 Session / 持久后端当前可记录和回放；投影是可重建视图，不是另一套执行真源。
材料、spill 与交付物实际工作区 / 文件与 spill 服务原生按需读回已有；来源保留受其策略和期限约束，不能承诺永久原文恢复。
Goal原生 Goal 服务：durable phase + process-local activation恢复 / fork 后 active Goal 为 disarmed；需要明确恢复才继续，完整 System3 验收尚待接入。
提醒原生 Schedule / storage-domain 持久任务表Host 运行时可恢复 cold Session 并投递；只有原 Session，非 exactly-once；不是外部通知服务。
本任务持续约束 目标接入原话、来源消息、scope、revision、替代 / 排除关系把关键约束标为持续有效；实际请求注入可追溯，修改后旧约束不回流，排除影响后续。
受保护摘要 目标接入Compaction provider + 必需事实检查与原文引用摘要由生成模型完成；摘要日志不等于 replacement 生效，检查失败不提交替换。

下一最小切片：同会话不用重讲，回来知道接着哪里做

约束卡 · 原话可查

保留“只处理已支付订单”“不改输入文件”等要求及来源。可修改或排除；界面显示这次是否真正进入请求。先做同会话保护，再扩展跨会话自动记忆。

恢复卡 · 记录与执行分开

已保留约束、已有产物、待完成检查、下一可用动作。默认“记录已恢复，等待继续”；不自动重放未知写操作，不把上次运行状态继承为当前。

压缩不是把所有内容改写成一段摘要

  1. 规则先选择合法范围、配对和版本；必要事实保留原文及可解析来源。
  2. Jev 只选择有限保留或查回策略；生成模型负责摘要，原生 provider 管事务与提交。
  3. 取消、来源变化、摘要未缩小或必需事实缺失时不提交 replacement。
  4. 用户能检查当前实际使用材料，缺信息时按权限查回原文。原文保存、可恢复和语义无损分别验收。

依据：原生压缩 · 工作区指令 · Goal · Schedule。

07

Jev、执行模型、本机 Lead 和专家各司其职

9B 参数规模不决定模型角色。当前 A100 Jev 9B 是结构化决策供给；未来设备端 9B/27B Lead 是通用生成与编排供给，需要独立能力与资源验证。

角色执行位置与接口负责什么不承担什么 / 状态
Jev / System1 已发布实测A100 网络服务；/v1/systemone；当前显式 high在合法有限候选中建议或弃权；当前入口与 Skill不生成完整计划、不执行工具、不授予权限、不独立判定完成。当前 9B 尚非用户设备本地推理。
System2 已发布实测proxy.fidoo.ai/v1；Flash / Pro；经原生 ctx.llm生成答案、代码、摘要和工具 / 委派请求真实工具动作由 Harness 或所属子 runtime 执行。Jev high 与生成模型 reasoning effort 是独立配置。
本机 9B / 27B Lead 后续演进设备 / 内网供给；原生 LLM adapter + 能力清单常用问答、文件与本地数据处理、计划、专业 Agent 编排、结果整合模型适配、工具正确率、上下文、硬件、冷启动和恢复均需实测；容量不足不擅自外发。
专业 Agent 目标接入原生 subagent registry / provider；可接 Codex、Claude Code 等 runtime接收限定任务包、材料与输出要求，返回结果和证据，由父任务整合不是另一模型别名；内部工具由专家 runtime 管，父 Harness 管交接、归属与控制能力。
官方 Jev 供给 原生基础相同 TypeSafe SDK 的官方协议配置替代决策供给，保留相同准入与采用语义合成 smoke 与当前自有9B的完整任务验收分开；非本次默认部署供给。

未来本地优先的实际调用关系

用户任务→Host 规则 / Jev 有界判断→本机 Lead 生成与组织→原生工具 / 限定专家委派→父任务整合与独立验收

常用能力留在本地

按设备能力和数据策略处理常见事务、文件分析与本地材料。模型不直接取得额外权限；依然使用原生工具与工作区规则。

专业工作形成明确交接

只发送获准的任务包与必要材料，追踪 parent / child / run、输出证据与取消结算。未经外发授权，不因本机模型不足切换远端。

Model-as-a-Harness（MAAH）· 后续研究命题

让小脑模型学习 Harness 的自适应控制策略：何时选方法、补证据、交接专家、继续或弃权。大脑模型负责生成与复杂规划；原生 Harness 保留准入、采用、执行、权限、持久化、取消和验收责任。模型控制建议进入原生执行，不替代这些确定性机制。

分三个阶段验收：设计时用模型帮助优化 Harness 代码与规则；运行时从有限合法策略中控制方法与下一步；执行后用任务轨迹和独立成果评分改进策略。代码优化、在线采用与轨迹学习分别交付，当前不声称已完成自动训练。

这是本项目拟研究的产品定位，不声明术语首创或已证新颖性，尚未完成全过程训练或效果验证。近期聚焦执行时有限结构动作与原生采用。当前真实闭环仅为入口与 Skill；扩展节点应与规则基线及无 Jev 路径对照，比较成果通过率、重复失败、总耗时与全部调用成本。

供给替换不改变职责

当前 provider 使用 TypeSafe SDK 0.6.0，自有 OpenJev 请求保留 effort，关闭 SDK 自动重试与日志；整体截止包含准备与凭据。普通 vLLM /v1 生成接口不能替代 /v1/systemone 决策协议。Loopback 隧道连远端 GPU，实际执行域仍是 network。

不要承诺尚未证明的能力：Choice 分数不是校准后的成功率；接入小模型不自动降低总成本；相同参数规模也不证明代码、摘要或工具参数能力。每类节点与供给分别做任务对照。

Frontend 是桌面载体，包含自己的 Harness；服务器 Web 是另一个独立实例。两端 UI 扩展共享原生接口和投影，文件执行与 Session 存储属于实际连接的 Host。
