Text input persistence receipts

This bounded slice follows the sole Continuum architecture entry. It reuses native inbox events and never changes the agent loop.

Text prompt response keeps accepted:true and adds optional storage metadata: state saved/unavailable/failed, stable message identity, and source Session/event position when recorded. Accepted means queued, saved means the original inbox source event passed the native Session flush barrier and exact backend readback. Saved does not mean processed or still scheduled.

All text admission checks use the original source rpcId in historical inbox insertions or user messages, including claimed/canceled input. Reuse with changed text rejects a conflict. Concurrent requests recheck after asynchronous admission before enqueue. Retrying a failed flush saves the existing source rather than enqueuing it again. No persistence provider or missing readback can produce saved.

Attachments retain their existing accepted receipt in this slice: raw upload identities differ from stored normalized references. SDK enqueue receipts stay compatible and their documentation stops promising durability. Composer emptiness checks may trim; transmitted text preserves whitespace.

Files: session-controller commands/types/new local receipt helper and tests; shared composer facade plus focused regression; SDK enqueue JSDoc; package docs and generated type catalogs. Verification covers real JSONL storage, before-model admission, failed flush retries, historical cancellation, concurrent duplicate/conflicting IDs, unavailable backend, exact whitespace, and process restart.

The saved source normally names an agent/inbox/spliced event. Exact recovery uses session_event_read event-json pages; its text-block view cannot read an inbox event directly. This response confirms original content retention, not automatic resumption of claimed or canceled work.
