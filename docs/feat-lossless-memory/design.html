1. 三项目标如何严格落地

目标产品与工程定义必须给出的证据不得替代为
无限上下文逻辑历史和任务状态不因模型窗口固定而被淘汰。跨压缩、换模型、跨会话、重启后，仍能在授权范围持续检索、精读、处理与续做；容量按存储资源扩展。超过实际有效窗口的历史；授权跨会话连续任务；分页游标/处理账本恢复；实际产物正确。单次请求塞入无限token，或只让对话不断报成功。
无损输入已确认保存的原始文本、附件字节与完整捕获的工具产物可精确还原；所有输入分区有待处理/完成/失败状态，无法处理时显式停止或续处理。长度和内容摘要一致、区间完整、崩溃后可恢复、重复提交幂等；超窗输入真实分阶段处理。只保存开头摘要；文件落盘即宣称已经读完或理解。
无损记忆原始证据、版本和纠正链不被摘要覆盖；有效约束不因最近N条或模型评分消失；任一采用内容能定位到具体版本的来源。索引可重建；旧版本/越权来源不被新请求采用；精确引文与原文一致；覆盖缺口明确。任意语义问题100%答对、所有历史永远全量注入。

“无限”约束的是逻辑可访问范围，不取消磁盘容量、保留政策、单次读取预算或用户删除权。“无损”的确定性要求与语义理解质量分开报告，不能用语义分数抵消原文丢失或越权。

必须一直成立的八条约束

  1. 先保存，再确认。客户端收到完整保存确认之前，源数据及引用必须完成持久化；接收中、已保存、待处理、已处理、已注入、已验证是不同状态。
  2. 原文唯一且可验证。Session与附件/产物存储拥有原始事实；摘要、索引、任务视图是可重建派生物。文本按应用接收的精确字符串保存，附件按字节保存；OCR、解码、规范化另存为派生版本。
  3. 所有省略都有定位。候选摘录标记源ID、版本、位置和省略；record.content的偏移不得冒充原始附件或Session block的偏移。
  4. 要求不会静默退休。明确撤销/纠正须引用目标及适用范围；含糊指令保留待解析，不能靠关键词把旧要求删除。
  5. 读取权不等于外发权。检索、Jev、摘要模型、主模型、子Agent分别检查宿主授权与目标路由。
  6. 索引不代表全部事实。无匹配、扫描未完成、索引滞后、来源缺失、拒绝读取必须区分。
  7. 最终请求在实际路由确定后验预算。包括工具schema、图片、当前输入、任务要求、召回、输出预留和安全余量。
  8. 事实按提交点可见。重放使用当时实际采用的文本；取消、卸载、换任务、修订与停用使旧异步结果失效。

2. 一条信息主线，六个职责模块

复用原生Session、存储、工具、AgentLoop与token-meter。保留Jev作为有界决策服务，生成模型处理复杂理解；Harness承担可确定执行的存储、权限、版本、预算和提交规则。不新建平行的AgentLoop，也不让Jev决定是否保存原文。

3. 四条必须闭合的运行流程

3.1 超长输入：完整接收不等于一次塞进模型

  1. 接收端先创建稳定输入ID与来源清单；流式保存原始内容，校验长度/摘要，再确认“已保存”。失败、取消或上游已截断须报告明确状态，不能补造完整性。
  2. 仅在任务需要处理全文时，分块建立处理账本。记录区间、重叠、源ID/源revision、操作类型/实现版本/参数摘要、分区计划版本、任务ID及generation、输出产物引用、待处理/完成/失败。只有这些键一致才复用完成记录；源修订、规则或任务改变使受影响条目失效。重启续处理，重叠片段去重，不遗漏区间。
  3. 精确提取、计数、代码/表格分析优先使用确定性工具，生成模型进行需要语义理解的部分；每块输出引用来源，汇总也可追溯。
  4. “已处理”只表示对应操作完成，不证明模型理解每个事实。询问单一事实时可按需读取，不宣称已扫描全文；任务要求全量比对/统计时，未覆盖区间阻断完成。
  5. 跨块依赖需要再次读原文或专门聚合；若同一步必须同时使用的不可拆分材料超过获准模型容量，返回capacity-blocked，提供获准路由或明确任务分解，不能静默缩写。

3.2 任务续做：记住当前有效要求，而非最近几句话

任务工作集保存目标、明确要求、未解析输入、当前决定、未完成动作、来源和验证状态。新会话通过授权任务ID恢复；主体、记忆域和精确工作区共同约束访问。用户更正只有在目标明确时建立supersedes；含糊冲突保持待核查，旧约束不被自动移除。已撤销条目仍可审计，但不能作为当前有效要求注入。多个任务的要求不混为全局偏好。

3.3 检索与回源：覆盖相关信息，由主模型判断

召回优先覆盖，不要求候选都精准相关。Reflex/Jev 快速判断相关性并分配读取优先级，允许带入适量噪声；主模型判断证据是否适用、是否矛盾、是否足以回答。高精度过滤和默认只选一条不作为目标。原文读取仍须准确保持内容、来源和版本，权限与预算由宿主严格执行。

当前问题 + 有效任务状态 + 近期上下文 → 授权快照
        → 多路候选召回 / 去重 / 覆盖缺口
        → Reflex/Jev：相关性排序 / 多候选保留 / 展开 / 补查
        → 同一原文读取服务 → 原文页 → 版本与权限再检查
        → 当前路由预算 → Session实际采用记录 → 主模型判断、回答或继续检索
无匹配 + 尚未覆盖 → 继续补查或报告不足；不能回答“历史不存在”。

候选既可能包含数据，也可能包含恶意指令。宿主只把它们作为带来源的数据，不能提升为system消息或工具授权。子Agent继承显式委派的范围，不继承整个宿主可读集合。

查询线索从哪里来

当前实现：上下文消费者从当前待处理消息末尾向前找到第一条含非空文本的用户消息，将其文本块换行拼接并去除首尾空白；仅有图片或空白文本的消息会被跳过；memorySearchTerms转小写，按字母、数字、下划线、连字符以外的字符切分，去重并排除长度不大于 1 的词项。retrieval按这些词项在记忆类型、scope 和正文中的子串命中数计分。这里没有模型生成关键词、中文分词、同义扩展或任务指代解析。例如“之前那个方案怎么配置？”会留下“之前那个方案怎么配置”整个词项，难以命中表述不同的历史。

目标设计：查询保留用户原句，同时读取授权范围内的当前任务、近期对话、明确实体与已知来源引用；分别从词法、任务、时间及按效果评估引入的语义入口取得候选并合并去重。“继续”从已恢复任务定位未完成动作，不能仅搜索“继续”。主模型可以根据任务提出补查或改写查询，但改写只是附加线索，不能替换用户原句或成为唯一入口。相关性判断交给 Reflex；不假设现有 Jev 决策接口能够自由生成关键词，也不要求每轮先增加一次生成模型调用。

Reflex 对多个候选的相关性可以同时给出高分，不用互斥单选的置信度冒充每条独立相关概率；具体分数以提供方支持的返回字段为准，未校准分数只用于排序。软相关阈值由覆盖与成本评测确定，低置信候选可以保留或触发扩检，不能仅因分数低就丢弃潜在证据。候选未能全部进入本轮预算时，保留可续查位置和未读状态，由主模型按需继续读取；同一问题的互补证据及相邻上下文需有覆盖，重复材料去重。

3.4 纠正、停用与撤销：让旧数据停止影响下一次请求

每次变更更新记忆域revision或授权epoch；索引、摘要、任务视图、候选缓存、已准备未发送请求均检查依赖版本。只删除索引不足以停用记忆，未来模型请求中的旧注入也须屏蔽/重建；必要时建立新的请求序列以避免缓存旧内容。已经发往远端的数据不能撤回，取消只阻止后续采用。停用不等于物理擦除，删除策略另行处理来源、索引、摘要、缓存、备份及共享引用。

来源和区间规则

source manifest至少记录sourceId、owner/domain、kind、版本、媒体类型、长度、内容摘要、完整性、原生Session/附件/产物引用。字节位置用于原始blob；文本视图另声明编码和字符位置映射，派生文本必须有映射或声明无法逐字节对应。原始blob页按字节读取并可精确拼接；解码文本页不能切断UTF-8字符，必要时明确续行/续记录标记并保留原始字节范围。优先对齐结构化单元，但单个单元超过预算时返回oversized-unit及可用的安全子页能力，不能为保持边界越过硬预算或无限重试；内容哈希只用于完整性和去重，不授予访问相同内容的其他用户权限。

最终模型请求的准入点

当前pre-step早于prepareCall实际路由，不能仅在pre-step估算召回预算。扩展AgentLoop原生请求准备阶段：准备实际provider/model能力 → 对含新输入/召回的候选请求计量 → 处理超限并重新准备 → 最后核对任务/授权revision → 单次提交消息与request/context → 发送。授权撤销、记忆停用与最终dispatch进入同一宿主有序提交点；撤销先发生则拒绝旧请求，dispatch先发生则记录内容可能已经离开宿主并取消后续采用，不能声称撤回。最后检查与开始dispatch之间不得插入可改变授权的异步等待。保留取消、重试、系统prompt更新和一次用户消息提交语义；修改时同步架构说明及两个SDK快照。只在stream前拒绝发送，不能冒称输入提交前自动压缩。

可用输入 = 模型窗口 − 输出预留 − 安全余量
完整请求 = system + tools + 当前有效约束 + 当前输入 + 近期历史 + 召回 + 多模态开销
完整请求必须满足准入预算；估算精度、provider超窗重试与实际usage分别记录。

超限时先减少可选召回，再压缩可恢复旧视图，再按有证据的任务分解续处理；有效要求和原始输入保持可读。仍不可满足则显式阻断或选择获准路由。硬字节上限在最终渲染后检查，标签、来源、标题、游标和省略标记全部计入。

5. 优化以任务可靠性和总成本为依据

  1. 修正确凿缺陷。全文命中后围绕命中位置生成原样摘录，避免尾部答案被开头截断；统一最终正文渲染与预算。
  2. 直接引用优先。已知来源直接分页读取；检索和Jev只用于未知位置或有取舍的情况。多个独立事实允许多选，不把互斥概率当独立相关度。
  3. 复用底座。先复用现有Session-query/存储提供者，补自定义记忆事件索引；使用分页结果而非每轮复制所有记录。
  4. 增量派生。按提交水位维护索引和摘要，后台低优先级、可取消可恢复；尾部不足通过受控扫描补齐，而非等待全库重建。
  5. 摘要只导航。节点覆盖范围、来源版本和摘要模型可追踪；数字、路径、约定等精确问题必须回源。坏摘要不影响全文入口或原文保存。
  6. 稳定上下文。缓存键包含主体/权限epoch、任务/域revision、路由、源版本和查询；纠正及撤销优先于缓存收益。
  7. 按实测增加语义检索。先测同义改写和无关键词续做的缺口，再决定向量检索/重排；不默认增加数据库和服务成本。

性能报告涵盖用户输入到可验证产物的总成本：Jev、主模型、后台摘要、检索、重读、失败重试和存储。分别报告P50/P95/P99、峰值内存、索引积压、每查询扫描量；provider cache命中只采用provider实际回执，本地前缀相同不冒充费用节约。

固定指标与不能混淆的分母

  • 源完整率 = 可校验恢复的已确认源 / 全部已确认源。硬要求100%，故障模型和备份范围须声明。
  • 处理覆盖率 = 该操作已成功处理的源区间并集 / 任务要求处理的源区间。重叠不重复计数；失败块不算完成；区间读取不证明语义理解。
  • 索引/扫描覆盖 = 截至固定revision可查询或已扫描的范围；它只说明搜索过哪里，不证明检索算法找到了所有语义相关事实。
  • 在独立 oracle 标注的题集上，分别报告候选证据召回率（候选覆盖的相关证据 / 全部标注相关证据）、预算内证据注入率、完整任务证据集覆盖率（必需证据全部进入可用上下文的任务 / 全部任务）、答案正确率和最终任务成功率。覆盖率为主指标，精确率仅作噪声诊断，不单设高精确率门槛。比较时固定 token/时延预算，同时记录续查后的累计覆盖、噪声对主模型的影响和总成本；相关证据进入候选不等于已注入或已被模型使用。
  • 过期事实误用、越权外发、明确约束丢弃、已确认源丢失均是发布阻断项，不能用平均质量分抵消。
  • 候选截断、Jev超时、无匹配、来源缺失、未扫完、容量阻断单独计数；不能把unknown填0或算成功。

对照组与防止题库污染

A0关闭新能力；A1当前发布实现；B完整架构确定性选择；C与B相同候选/读取预算的Jev主动管理。评估摘要树/向量检索时单独消融，只改一个因素。B用于内部测量和有限故障兜底，不定义新的无Reflex产品模式。计入所有后台成本，失败与重试留痕；固定可用模型、参数、预算、缓存冷热条件和输入顺序。

工程题库用于开发，可反复运行；另生成密封held-out数据（新名字、数字、路径、顺序和干扰项），答案保存在独立oracle，不能进入模型prompt、测试fixture provider答案或查询未来历史。先pilot估计方差，冻结成功率/非劣界/成本上限后再正式比较，报告置信区间和逐题失败。不得测完挑阈值或只发表通过的重试。

规模阶梯

源规模与模型窗口两条轴分别测量：记录数量1千/1万/10万；完整历史达到实际模型可用输入预算的2倍/10倍/100倍。固定硬件、数据分布和并发1/4/16，分别测试冷热索引和有积压场景；峰值内存不得靠全库复制随每个并发查询放大。1千条样例或人为缩小窗口只能证明机制触发，不能代替实际模型超窗口验收。性能门槛在硬件pilot后冻结，不把设计目标写成已实测SLO。

发布结论

只有确定性保护全通过、必测真实链路无缺项、受影响回放一致、已冻结质量与资源门槛满足，才宣布对应批次验收。完整三目标必须等B1–B5全部完成；B0通过仅能宣布修复召回正文。API key缺失、runner不可用或实验成本未获准时记为未验收，不伪造结果。

9. 本轮明确的取舍与后续决策

  • 目标保留完整三项，不把“检索更准”包装成全部完成；先修复已证实缺口，同时按D/I/R/C/J/U完成产品闭环。
  • 不以摘要替代唯一事实，不默认新上向量数据库，不让每一次存储或展开都调用Jev。
  • 单Host单写者为首版一致性边界；多Host共享写、跨租户聚合、物理擦除与备份合规单独设计，不混入首版无限上下文承诺。
  • 无损输入的边界是宿主实际收到且已确认保存的数据；上游未提供的字节、OCR遗漏的语义、远端已经截断的输出必须显示缺口。
  • 充分原文证据不保证任意模型必定推理正确；对精确字段与产物采用确定性校验，对开放语义任务用冻结评测及诚实的不确定性。
  • Jev不能覆盖权限、版本和有效要求。产品“已启用”要求完整依赖与配置生效；“已纳入请求”来自原生committed记录；“已发送”来自transport dispatch记录；provider确认或响应单独记账；连接中断等发送结果不明时保留unknown，不推断已收到或未收到。任何状态都不证明模型内部理解或答案正确。
