# 原生已安装包再验收

[English](requalification.md) | 中文

## 范围

现有 `product-release.yml` 手动工作流通过 `qualification_run_id` 和 `qualification_source`，配合单个原生目标（`windows`、`mac`、`mac-intel` 或 `linux`）验收已有安装器，不重新构建产品字节。两项验收输入均留空时执行正常构建。输入指定已有构建任务及预期的 40 位源码 SHA。工作流只接受本仓库的 product-release 工作流及其精确命名的 `apus-preview-<native-target>-<run-id>` 产物。它验证任务源码 SHA，下载该产物，并要求安装器哈希、构建信息和已安装运行时身份均与所选源码一致。验收辅助脚本另有检出 SHA，与产品源码分开记录。

## 过程和诊断

Windows smoke 跟踪安装器 PID 及采样到的后代进程，再跟踪已安装应用及其 profile。完整原生负载的安装等待上限为 600 秒。报告保留耗时、数字退出码、终止及信号信息、有界的安装目录摘要，以及独立的清理错误。关闭时等待所属进程消失；失败不能被报告为验收成功。凭据和认证 URL 均脱敏。脚本使用全新临时安装目录和 profile，验证首次启动、产品版本、重启、卸载及进程退出，应用 PATH 中不含外部 Node。

工作流仅需 contents/actions 读取权限，安装辅助脚本锁定的根依赖，执行定向测试和真实安装验收，并上传小型报告与截图。它不上传或重新发布产品二进制。通过的报告仅验收指定源码 SHA 及安装器哈希，不代表辅助脚本提交对应的产品源码。失败的构建任务可以提供已完成的安装包用于诊断；再验收通过不能豁免其他构建或平台检查。

## 验证

定向测试拒绝任务、源码和产物不一致，保留主失败及清理诊断，并验证后代进程归属及清理完成。各原生 runner 分别负责安装和浏览器证据。本地源码测试不能替代该结果。
