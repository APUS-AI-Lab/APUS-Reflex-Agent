APUS Continuum · 连续记忆

Reflex 专属的“无限记忆”开关：由即时决策模型管理长期记忆，让每次推理只携带当前所需的信息。关闭开关或不接 Reflex 时，保持原版 Harness 行为。

状态：已授权在同名 worktree 分模块实施；完整产品尚未实现或验收。 当前 main 已有自动摘要压缩、原始 Session 日志和可选历史查询；默认全文检索关闭。按“整体 → 模块 → 可独立验收切片”推进，工程检查、真实模型链路与效果验收分别记账。命名为候选，尚未做重名核验。

目标与命名架构UniiChat 横向对比专属开关与兼容记忆组织运行与决策原生接入模块与小批次摘要树与缓存取舍真实验收门禁取舍

1. 目标与命名

“无限”指在存储与保留策略允许时，不因模型窗口固定而被迫放弃历史；它不承诺无限存储、零成本、任意问题全量召回或语义无损。产品目标是：长任务可续做、旧要求可找回、纠正后不沿用过期结论，单次请求的上下文和召回开销受控。

候选名含义与取舍
APUS Continuum（连续记忆）推荐作为子系统名称；产品开关明确叫“无限记忆”，属于 Reflex 管理能力。
APUS Recall（记忆召回）简洁，但偏重读取，不能充分表达任务状态、纠正和记忆维护。
Reflex Memory可作为能力副标题，直接表达 Reflex 专属定位；原版仍有自己的会话历史和压缩。

推荐对外关系：APUS Reflex Harness 是产品，Continuum 是记忆子系统，“无限记忆”是 Reflex 专属能力开关，Jev 是结构化决策接口。 默认使用自有 Reflex；生成模型负责摘要与复杂理解。保留其他 Jev 供给的技术适配能力，但不能把协议兼容误写成原版拥有同等无限记忆产品模式。

2. Reflex 管理与 Harness 原生执行

Harness：可用与可追溯

持久化、索引、授权、版本、预算、原文回读、实际输入记录和故障恢复。

Reflex：有界策略判断

在检索到的合法候选中选择相关信息、建议展开或扩大检索。不能写入事实、授予权限或增加预算。

生成模型：理解与生成

提炼有来源的摘要，理解跨片段关系，处理无法确定的冲突，并完成用户任务。

3. “无限记忆”是 Reflex 专属开关

产品状态记忆行为决策与界面
关闭，或未接入 Reflex原版 Harness：原有压缩、持久化及用户原配置不开启 Continuum 自动整理与召回；不能显示无限记忆正在运行
开启且 Reflex 可用Continuum 长期记忆、任务要求、检索回读与有界上下文Reflex 管理候选与读取动作；Harness 校验并实际执行
开启后 Reflex 临时不可用已保存记忆不丢失；当次在既定权限与预算内确定性兜底显示降级及原因；恢复后重新核验，不伪装成模型仍在管理

拟议 memory.enabled 是产品开关；开启要求有效的 Reflex 决策供给，默认采用自有模型。无 Reflex 的正常配置保持原版，不额外提供“无模型无限记忆”产品模式。界面可显示功能说明，但不可启用的原因必须明确。开关管理记忆能力，不要求把普通任务的生成模型切成 Reflex。

关闭停止新记忆决策、自动整理和召回注入，不删除已存记忆。切换在原生安全步骤边界提交；之后的请求移除本功能的活动记忆投影，必要时开始新请求序列。已发送内容不能撤回。重新开启后按最新权限、停用状态和版本恢复，不能直接重用旧缓存。

Jev 的 shadow 是研发/灰度验证模式；测试专用的确定性 Baseline 用于度量 Reflex 增益和运行期兜底，不对外作为原版的同等无限记忆能力。其他 Jev 的协议适配保留独立验证入口，不自动赋予原版该产品开关。

显式开启却缺少必需 provider/model、或预算冲突属于配置错误，须在最早可解析处报错。有效配置运行时超时、弃权、低置信或隐私不允许发送时，记录原因并有限兜底；持续不可用须显式标记，不能静默长期运行并声称由 Reflex 管理。用户取消直接传播。摘要模型失败时保留原文与索引，后台稍后重试。

4. 三类记忆，多个检索入口

类别内容使用方式
任务工作集目标、有效要求、最新纠正、未完成事项、关键证据引用每轮保留适用约束；不按最近 N 条静默淘汰
长期事实与决策已确认的用户偏好、项目约定、历史决定、可验证结论按主体、项目、任务和有效时间检索；区分用户确认与模型推断
历史证据用户消息、工具结果、产物、子 Agent 报告、操作与失败记录保留精确来源；按需读取原文或分页展开

摘要树只承担时间概览与逐层展开。全文索引保留摘要可能遗漏的路径、数字、名字和错误；任务与实体字段连接跨会话的相关记录。先复用全文检索和显式标签，再按评测增加摘要层级；不要求首版部署向量数据库或知识图谱。

Markdown 作为用户可读、可编辑的记忆视图和导入格式。稳定 ID、版本、权限和引用由记忆服务管理。修改 Markdown 经明确导入生成新记忆事件，不允许文件变化直接提升为系统指令，也不自动修改 AGENTS.md。

数据约定：证据和推导必须能区分

拟议 MemoryRecord 包括：品牌化的记忆 ID、revision、kind、scope、subject、content、sourceRefs、有效时间、记录时间、状态、supersedes 和确认来源。sourceRefs 至少包含 Session ID 与事件序号；跨会话引用不能复用仅表示同 Session 的 sourceEventSeqs。

原始证据继续归原生 Session 与附件/产物存储。新增记忆事实、纠正和停用以持久 Session 事件为权威；跨会话查询维护可重建投影。单个记忆域由一个 Host 写入者持锁、按 revision 串行提交并等待持久化完成；并发旧版本写入返回冲突，不由 Jev 选择覆盖。多 Host 并发写同一记忆域不纳入首版。

全文索引、摘要树和工作集投影都是派生数据，重建不得丢失唯一的记忆记录。后台任务维护索引 watermark；读取固定版本，在独立读取预算内检索和分页读取尚未索引的授权尾部，返回已覆盖区间与未覆盖范围。最新未解析的用户要求进入任务工作集；其余未扫描历史不能被当作无命中。队列积压时保留原文读取路径，不无限等待全部摘要完成。

明确关联的用户更正建立 supersedes，旧证据仍可解释；“最新一条”不自动等于真相。模型提炼默认保存为推断候选，只有明确用户来源或独立验证依据才能进入已确认记忆；用户说过某事也只证明该陈述的来源，不证明所有外部事实为真。推断的关联或冲突只标为待核查，不能自动停用既有要求。普通导航摘要无需逐条向用户确认；适用环境不同的两条记录可同时成立。子 Agent 报告可贡献候选和证据，不能静默覆盖用户约束。

5. 在线召回与离线整理

  1. 先记录。 原生机制保存已接收消息与工具结果。大输出保留可回读产物引用；已有截断且未保存的内容标为缺口，不能宣称可恢复。是否保存证据不经过 Reflex。
  2. 维护当前任务。 显式记忆操作和带目标引用的更正确定性提交；自由文本中的疑似要求立即保留为未解析输入，再由模型分类，不凭关键词猜测更正对象。当前约束不能因模型低分消失。
  3. 按需检索。 新任务、跨会话续做、明确历史引用或执行中信息不足触发检索；已有精确引用直接读，不每个工具调用都问 Reflex。Harness 先限制权限、有效版本和候选量，再执行全文、任务或时间检索。
  4. Reflex 管理。 Harness 先按精确匹配、任务关联、有效性和检索分数形成候选；Reflex 批量判断相关性，选择原文展开、扩大检索或弃权。精确引用可以按规则直接读取；Reflex 不得取消强制保留的任务约束。
  5. 读原文再装配。 对精确数字、路径、承诺和待验证结论读来源片段；Harness 再检查版本、授权、取消与预算，记录实际注入文本。摘要仅作导航或带标签的概览。
  6. 使用后整理。 生成模型按需写有来源的摘要与候选事实；原生执行记录用于核对任务成果。后台维护索引和摘要，不把“模型引用过”直接当作记忆正确或用于自动训练的标签。

多条记忆可以同时相关，不能把一次互斥 choice 的概率当作多条独立相关概率。Reflex 的 score 或 noul 需要任务评测校准；分数不是事实正确率。首版以一次批量候选选择为主要增强点，不在摘要树每一层强制插入一次模型往返。

预算、缓存与不会静默遗忘的约束 
可用输入预算 = 当前路由模型窗口 − 输出预留 − 安全余量
系统与工具 + 当前有效约束 + 近期历史 + 召回内容 + 新输入 ≤ 可用输入预算
召回另外受候选数、展开次数、总字节、总 Token、截止时间与费用限制。

以当前路由的 token meter 和图片计价为依据，字节数只作传输上限。现有文字计量使用字符密度估算，并非精确 tokenizer；通过估算门禁不能证明提供方永不报超窗。预算字段由配置验证，不把 64–128KB 写死为所有模型通用窗口。模型切换须重新校验预算；不可拆分的新输入或强制约束本身超限时，显式报告并要求缩小任务或选择有容量的获准路由，不偷偷丢弃要求。需要精确上限时，须补充对应提供方可验证的计量能力及超窗处理。

稳定系统/工具前缀、稳定任务片段与动态召回分别组织；只在内容变化时产生新注入，按压力批量压缩，避免每次请求重排全部历史。复用原生 AgentLoop 与 Session，不为模仿 gist 强制每回合新建会话。缓存收益让位于纠正、授权变化与数据停用。

测试 Baseline、临时兜底和 Reflex 路径使用相同候选池、原文读取、预算、版本校验和最终装配代码，避免重复实现；这不构成无 Reflex 产品模式。候选召回遗漏不能靠重排弥补；无命中只能表示本次检索未找到，允许在预算内扩大关键词、任务或时间范围，仍不足则明确说明缺少证据。

权限、隐私、停用与回放

首版跨会话沿用当前工具的精确 cwd 授权规则，接口中保留主体与记忆域；不能将相同 cwd 外推为多租户用户授权。跨工作区的个人偏好需单独显式授权。每次读取和实际注入前重新授权；子 Agent 不因父代理可读就自动获得权限。

检索内容作为有来源的数据使用；网页、工具输出、摘要与子 Agent 报告不能伪装为用户指令。摘要模型、最终生成模型与 Reflex/Jev 都通过同一个不依赖模型判断的宿主数据准入接口；若复用的策略当前属于 System3，则抽取共同依赖或由宿主显式注入。故障兜底同样执行授权；本地隧道不等于本地计算。

首版“停用记忆”阻止未来检索和使用，并使相关摘要与当前工作集失效。它不等于物理删除。真正擦除需独立的保留/擦除设计，覆盖源事件、派生索引、已注入的 Session、缓存与备份，不在本方案冒充已支持的操作。

停用提交使记忆域 revision 更新；尚未发送的已准备请求、后台摘要提交和索引发布必须重新核验，旧结果不得重新激活停用记忆。已发送的远端请求不能撤回内容，应取消后续采用并准确记录。提交与最后发送检查的顺序由宿主串行化，而不是仅在检索开始时检查一次。

重放使用当时日志中的记忆版本、引用和完整注入文本，不重新搜索当前索引或重新调用 Jev。恢复后新一轮才重新授权和检索。停用后的新请求必须移除相关历史投影并开始合适的新请求序列；不能只删除 FTS 条目而继续发送旧上下文。历史审计记录和曾经发送到模型服务的内容不能被声称已撤回。

6. 原生接入与拟议接口

新增一个 packages/context/continuum/ 包，包含 Service Definition、本地 Provider、自动召回消费者、确定性兜底和模型读取工具。再增加 packages/experimental/continuum-jev/ 适配包，将管理决策接到现有 ctx.jev。底层存储与授权保持模块化；产品装配层要求开启无限记忆时同时具备 Reflex 控制器。原版关闭该功能时不加载这条管理链，不能把可单测的底层模块解释成另一种对外产品模式。

拟议接口输入与结果约定
resolve(request) → spec从宿主身份解析授权范围、模型容量、查询及预算。调用者不能用请求字段提升身份。
record / supersede / deactivate来源引用、期望 revision 和明确动作；持久化成功后返回版本，否则报告冲突或失败。模型只能提议，写入由宿主校验。
retrieve(spec) → candidates已授权候选、记忆/索引版本、来源、覆盖范围和未索引尾部信息。
read(refs, budget) → evidence指定版本的原文片段或分页、缺失/停用状态和实际预算。工具与自动召回使用同一服务。
decide(candidates, actions, budget)Reflex 返回允许动作和候选 ID；确定性策略仅用于测试和有限兜底。不返回可执行任意代码或可覆盖权限的指令。
prepareContext(spec, evidence)返回待准入的记忆消息、引用、预算和采用回执；只有原生 Session 实际提交后才标记为 injected。

配置须区分记忆启停、provider、增强模式、作用域、候选/读取/摘要预算、期限和保留策略；用户配置未知字段或不可满足预算时报错。所有跨包 ID 使用项目品牌类型，外部数据、模型响应和持久数据在对应入口验证。

已核实的接入限制
  • 当前 runtime-context 在 agent/pre-step 之前已生成。同步召回不能只更新 context 回调并声称本步生效；参考 Skill 注入，保留原 enter 决定的字段，并追加带专属 source 的 accepted message，由 loop 记录。稳定任务快照可继续使用 runtime-context。
  • 现有 compaction 测量最近已持久化请求，新输入和召回尚不在其中。实现须提供包含待准入消息的计量/预留，并在路由与 prepared call 确认后验证完整请求容量；不能以现有压缩成功代替硬预算证明。优先沿 token-meter、compaction 与 request 扩展点补齐，若需改 loop，另行更新架构设计。
  • 当前任务卡只保存有限最近要求且分类异步。Continuum 接管完整的有效要求记录，System3 从同一投影读任务状态，避免两个任务卡竞争或重复注入；不可解析的输入保留出处与待处理状态。
  • 现有 Session FTS 不自动提取自定义事件，SQLite 查询库可重建。新记忆事件必须提供明确的索引提取器或本包派生索引，不能将唯一记忆存在该缓存库。
  • 共享记忆的异步返回须重核 task revision、索引/记录 revision 和权限。晚到结果不能注入已取消或已换任务的步骤；插件卸载先停止订阅，再等待工作收敛。
  • 新增 Session 事件须更新已知类型、持久 schema 和变更确认。是否 ignorable 由重放语义决定，不为绕过旧 reader 拒绝而标记可忽略；TypeScript 与 Python SDK 的预期输出同步更新。

7. 分期与可证伪的验收

三级拆分：整体目标 → 六个模块 → 小批次闭环

整体目标是长任务在有限窗口内可续做、可纠正、可解释。模块按责任划分，提交按完整行为划分；一个行为可以跨模块，但不能以“文件已写完”代替验收。所有批次保留在 feat-continuum-memory 工作树与同名分支，不为每个小模块创建分支或 npm 包。模块只有在供给与消费者独立演进时才拆包。

模块职责与拟议接口拥有的事实 / 验证
D · 证据与记录record / supersede / deactivate；Session 来源、revision、串行持久提交原始事件是权威；断电重启、旧 revision 冲突、来源可回读

摘要树与缓存：吸纳机制，分别证明必要性

机制采用判断采用与验收条件
不可变摘要节点、来源范围、zoom吸纳；作为大历史导航的辅助索引，P5 实现候选先验证概览、时间回溯、无关键词问题的缺口；全文与原文回读仍保留。树节点必须可追溯，纠正后不能把过期摘要当有效要求
固定相邻二叉树 / 512 字节节点不直接照搬相邻时间未必同任务；比较时间树与任务分组。中文、代码、数字按内容与实际模型预算评估，不沿用固定字符/字节作为 token 保证
稳定前缀、追加视图、不重复注入优先保留；已有压缩前缀复用应复用源版本、权限和停用一旦改变，立即失效。字符串前缀稳定仅为本地证据，提供方返回缓存用量才算服务端命中

每轮重建会话、仅允许 zoom、入库前截断工具原文不采用为系统约束保留原生 Session 与多入口检索；完整产物或缺失声明可回读，不能让摘要遗漏变成永久丢失

摘要树与缓存优化不是“拥有记忆”的必要条件；来源、持久化、纠正、授权和有限上下文才是前置条件。树提供检索导航价值，cache 提供成本价值，Reflex 提供策略价值，三者要分别消融。若 P5 实测没有净收益，记录结果并明确调整范围，不以“尚未必要”冒充已经实现。

当前可复现实验：本 worktree 已生成 continuum-ablation.json。固定 3 条样本的本地 2×2 结果为：无树检索命中率 2/3，有树 3/3；稳定布局的估算可复用字节为 79/118 与 165/204。这里的缓存数字只是布局复用估计，不是 provider 返回的命中或计费数据；真实长历史与服务端用量仍待可达模型端点后验收。

完整真实验收：三层门禁，任何必测项缺失均未完成

  1. 确定性正确性：真实持久文件/SQLite、真实进程退出与重启、索引破坏后重建；权限、旧 revision、停用、取消、预算拒绝和回放一致性。竞态通过 barrier 控制确实重叠，不靠 sleep；故障替身用于精确造错，不能替代实际存储/进程证据。
  2. 真实产品链路：经支持的 dsh profile 启动，实际 Reflex 与生成模型共同执行；核对最终文件/目录/数据库和未触碰文件，而不只检查模型声称“记住了”。至少一条真实追加 → 压缩/摘要 → 纠正 → 退出 → 重启 → 续做演化链。缺 key、端点不可用或 self-skip 的必测场景标为未验收。
  3. 效果与经济性：冻结样本、期望事实/来源、模型版本、路由、预算和阈值后再测试；报告每个样本和失败，不挑最优结果。固定候选测 Reflex 策略，开放检索测系统；树开/关 × 稳定缓存布局开/关做 2×2 对照。测 cache 时保持注入内容相同，否则标为整体策略实验。

验收数据覆盖中文/英文、精确数字与路径、多任务交错、旧事实诱导、摘要遗漏、用户连续纠正、无命中、跨作用域拒绝与长工具输出。受控规模语料与实际多轮任务分开报告；人工缩小窗口只证明机制触发，另需实际历史超过所选模型有效窗口的规模测试。所有检索只能访问查询发生前已写入的历史，避免未来信息泄漏。

每次运行保存可复现 manifest：commit、配置摘要、样本版本/顺序、随机种子、模型/provider 标识、时间、冷暖状态、Session/请求 ID、检索来源、Reflex 建议、实际采用、原始用量、耗时、错误/重试/skip 和外部产物校验。测试密钥不进入报告；原始敏感日志留受控位置，分享证据脱敏。报告包含样本数、重复次数、配对差异与不确定性，pilot 只定阈值，不参与 held-out 发布结论。

当前评测清单：continuum-evaluation-manifest.json 已冻结 A0/A1/B/C/U 变体、四类代表性任务和必须保存的证据字段。当前 Jev live adapter 已通过并保存 continuum-live-e2e.json；DeepSeek 主模型验收因官方 endpoint 对提供的 key 返回 HTTP 401，仍保持未完成。

成本包含原版/新增生成调用、后台摘要、Reflex、扩大读取、失败重试、缓存写入与读取，以及索引/存储资源；本地模型另列硬件与摊销假设。提供方未返回缓存或费用字段时标为未知，不填零；估算费用与账单/实际用量分开。P50/P95 同时记录首次可见结果与任务完成，样本不足时明确尾延迟证据不足。

发布阻断：观察到越权、停用后再次注入、强制要求静默丢失、错误版本采用、重复提交或回放漂移均阻断。真实链路必测缺失同样阻断。效果门槛在 pilot 后、正式对照前预注册；未证明质量/费用收益，不宣称 Reflex 或摘要树更优。单元覆盖率遵循本仓 per-file 100% 规则，但覆盖率不能替代上述验收。

对照与消融

A0：原版默认压缩；A1：原版压缩加已有历史工具并启用检索；B：测试专用 Continuum 确定性策略；C：同一 Continuum + Reflex；U：按已冻结 gist 规则复现的 UniiChat 参考实现。C 与 B 固定候选和生成模型测 Reflex 净增益；U 与 C 用相同历史、查询、生成模型和输入预算比较完整系统，再在相同总费用下比较。若拿不到作者实际程序，明确标为参考复现，不能冒充对原产品的实测。B 不是对外开关选项；摘要树另做有/无消融。

必须覆盖的行为

  • 跨多轮与多会话找回精确数字、路径和历史承诺；高层摘要遗漏关键词时仍能读到原文。
  • 用户连续纠正、任务交错与重启后继续遵循适用版本；原版不启用功能的行为保持不变。
  • 索引落后、摘要失败、索引重建、并发旧版本提交和原文缺失时，输出准确状态。
  • 无 Reflex 的原版兼容、开关依赖校验、正常 Reflex、shadow、运行故障、隐私不允许、低置信和取消均走真实装配；单独测试替代 Jev 的协议适配。
  • 停用记忆后既不再召回，也不从现存模型历史重新带入；跨 scope 请求拒绝，外部文本不能升级权限或用户要求。
  • 新用户输入、图片、工具 schemas、召回内容及路由改变共同计量，拒绝不可满足的预算；候选数、字节、展开次数等硬限制用规则验收，token 估算与提供方超窗处理分别验证。
  • Session 回放不访问外部记忆服务或重新请求 Jev；两个 SDK 与默认产品 profile 的关键场景快照匹配。

指标为最终任务成功率、要求遵循率、有效事实召回、过期记忆误用、引用正确率，以及包含后台摘要、检索展开和 Reflex 的总费用、P50/P95 延迟。权限与版本拒绝用确定性测试作发布阻断；质量目标在冻结代表性任务集和 Baseline 后预注册，不在测后挑选有利阈值。检索到、已注入、模型引用和任务验收分别记录，不推断不可观察的内部“记住”。

实施验证包括单元负例、原生 profile 集成、keyless recorded-session 快照、两个 SDK 投影和真实模型对照。只运行受影响面的测试与要求的构建/检查；不把 mock 通过称作模型质量证明。

成熟度与证据作者描述自用方案并给出较细算法和缓存模拟；这份 gist 未提供完整程序或长期任务质量对照。底座已有实现；“无限记忆”开关和 Continuum 仍未实现。分期实现后，用公开定义的任务与消融验证。当前无法判定整体谁更强，更不能写成我们已超过对方。

我们应借鉴什么，可能做出什么差异

直接借鉴

不可变来源引用、多分辨率概览、需要时读原文、持久视图和批量压缩。先复现缓存曲线，再判断是否值得移植。

拟议差异

任务要求独立维护、带时间和版本的记忆、权限内多入口检索、Reflex 有界决策与实际采用记录。这是待验证的系统组合，不是已证明的独创算法。

必须付出的代价

更多状态与异常、更复杂测试、一次额外模型往返，可能反而更慢更贵。不能只展示省下的主模型 Token。

公平实验及负面结果

先比较“功能关/开”对长期任务的整体收益，再用测试专用 Baseline 与 Reflex 比较控制器净增益，最后与忠实 UniiChat 参考复现比较。冻结模型、历史与任务；同时报告相同上下文预算和相同总费用两种结果，冷热缓存分开，计入全部摘要、重试、展开和 Reflex 成本。

若 Reflex 只负责给已有候选重排，它就是一种 reranker，不能仅据此宣称架构突破。还需与同预算通用模型策略比较；固定候选实验测重排价值，另做允许扩大检索的端到端实验，验证“何时补查、查什么、读多深”的管理价值。权限、日志和版本治理属于工程能力，不等于算法原创。

必测：摘要遗漏精确数字、连续纠正后恢复、多个交错任务、历史越权、缓存过期、摘要积压、Reflex 故障与长尾延迟。若 Reflex 相对同一记忆系统的确定性策略没有稳定收益，就缩小它的调用范围或推迟启用，不用“专属开关”包装未证实的效果；若纯时间回溯场景 UniiChat 更便宜，应直接承认并采用其合适机制。

9. 审慎取舍

创新应落在模型参与的记忆管理及其可验证收益。 日志、摘要树或 Markdown 本身不能证明“不会忘”。Continuum 承载记忆，Reflex 管理同一任务下选什么、读多深、何时补查。模块职责分开便于测试和兜底；产品能力仍属于 Reflex 专属开关，原版兼容不意味着对外提供相同功能。

不复制 gist 的“只能沿树 zoom”限制；保留原文全文与任务索引，避免摘要遗漏变成不可发现。不把每次存储和每一层展开都变成 Reflex 网络调用。首版不训练新的记忆模型；先收集经任务验收的候选、选择和采用结果，再单独设计受授权的数据与训练流程。

用户体验示例：上周已将交付目录从 A 改为 B，今天在新会话说“继续上次任务”。开启无限记忆后，Continuum 恢复当前任务和 B 的有效更正，Reflex 在需要判断时选择相关任务与证据，Harness 读回原文并记录采用，UI 显示出处。输出应写入 B，并由实际文件结果验收。关闭功能的原版不承诺这套自动续做能力，但仍保留原有历史与压缩。
