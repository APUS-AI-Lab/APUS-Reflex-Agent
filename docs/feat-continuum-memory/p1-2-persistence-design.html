APUS Continuum P1.2：Session 持久化与重启恢复

实现前设计门；目标是让记忆事件进入既有 Session event log，并证明 flush、磁盘重启和失败语义。此批不接入 Jev，不实现检索、摘要树或 UI 开关。

目标与边界

  • 复用 Session.append、ctx.sessions.flush 和现有 JSONL persistence，禁止创建第二个事实源。
  • 为 Continuum 记录声明一个可版本化的 Session 事件，事件可独立折叠回 MemoryRecordStore。
  • 验证写入、flush、reader 重启回读、未知/损坏事件拒绝和 flush 失败传播。
  • 本批不宣称产品级无限记忆；事件持久化完成后仍需 P1.2 精确回读与 P2 索引。

架构

事件与 API 草案

continuum/memory-record 的 payload 只包含 JSON 可序列化的完整记录和操作：

{ operation: 'create' | 'supersede' | 'deactivate', record: MemoryRecord }
  • create 要求 revision=1、status=active；supersede 同时携带旧记录引用和新 active 记录；deactivate 携带递增 revision。
  • 写入前由 MemoryRecordStore 验证 revision、scope、ID 和来源引用；append 成功后才视为 Session log 已接收。
  • 恢复只折叠日志，不调用模型、不重新检索、不重写原事件；坏事件由 Session 的持久化验证拒绝。

文件与测试计划

  • packages/context/continuum/src/index.ts：声明 SessionEventMap 扩展和记录事件类型。
  • packages/context/continuum/src/persistence.ts：追加和从事件日志折叠的最小消费者；不新增存储后端。
  • packages/context/continuum/tests/persistence.spec.ts：临时目录 JSONL 写入、显式 flush、销毁 Context、重新挂载并回读；覆盖 supersede/deactivate 顺序。
  • 失败测试：flush 拒绝向上冒泡；写入失败后内存 Session 与磁盘可观察状态的差异被明确记录；未知事件/损坏事件不能静默恢复。
  • 运行 gen-persistence-catalog、persistence acknowledgement、双语文档门禁、包级 lint/build/test；若事件影响模型可见面，再补两个 SDK 与 snapshot。

验收条件

  1. 同一 Session 的事件 seq 连续，显式 flush 返回后 reader 能在新 Context 中完整回读。
  2. 回读折叠出的记录与写入前后的 revision/status/sourceRefs 完全一致，旧快照不被修改。
  3. 关闭或未接入 Reflex 时没有自动创建这些事件；本批不会改变原版 Harness 行为。
  4. 证据明确区分“日志可恢复”与“真实模型产生收益”；无模型凭据时不把 keyless 测试写成真实 Jev 验收。
