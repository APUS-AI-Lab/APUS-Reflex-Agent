# 服务商地址与凭据变更

[English](credential-switch-design.md) | 中文

Models 编辑器原先先保存服务商配置，再替换凭据。使用真实渲染编辑器与 PiAiAdapter 的本地复现已确认：凭据写入被拒绝后，新地址仍生效并引用旧凭据，后续 HTTP 请求会把旧密钥发送到新地址。

## 修改

现有服务商编辑器同时修改地址或协议并输入新密钥时，分配新的随机凭据引用。先将新密钥存入新引用，再以一次带 revision 检查的设置变更提交连接配置与新引用，不覆盖旧引用。同一密钥草稿重试复用新引用，修改密钥后另分配引用。

仅修改凭据的操作及环境持有的只读密钥保持现有行为。密钥留空继续保留已配置凭据，不修改凭据 API 或持久化格式。

## 失败

凭据写入被拒绝时不改变设置；设置变更被拒绝时保留旧配置和旧凭据，新引用可能未被使用。传输失败后不自动删除新引用，因为未确认的设置写入可能已经引用它。保存结果不明时保留草稿并显示相应提示。

## 文件与检查

`ProviderEditor.tsx` 管理暂存引用和保存顺序，本地化字典管理保存结果未确认的文案。现有服务商表单测试覆盖凭据拒绝、设置冲突、不覆盖旧密钥的成功切换、重试与回执不明。使用修复后的编辑器重复本地 HTTP 复现，所属 Models README 说明这些保存与失败语义。
