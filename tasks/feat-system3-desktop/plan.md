# System3 rc.2 桌面与原生决策工作计划

当前工作区：`feat-system3-desktop`。完整设计入口：`docs/feat-system3-desktop/system3-native-v1.html`。本计划承接入口第一目标、过程智能第二目标，以及能力、记忆、长期目标和未来本地 Lead 的历史方向。

## 已记录的产品目标（2026-10-01）

交付面向外部用户的 System3 Harness + Agent 桌面工作台，使同一任务从提交、合法选路、实际执行、人工干预到有证据的交付贯通入口智能、过程智能与体感智能。桌面优先，Web/API/TypeScript/Python SDK 共享执行事实与控制语义；产品 UI 复用原生 Conversation 与侧栏扩展，Harness 是唯一执行和持久状态所有者。

- **入口智能**：规则形成合法候选，Jev 9B 判断，Fidoo LiteLLM 承担生成；保留固定模式、弃权与失败基线，逐项说明附件、排队和其他入口的支持范围。完整体验必须区分本地回显、Host 收到、准入、实际请求与输出。
- **过程智能**：至少一个 Jev 过程节点真实改变任务行为，首选 Skill 有界选择与实际注入；随后完成有来源记忆、压缩保护与查回、失败取证、专业 Agent 委派、持续 Goal 的预算和独立验收。首条切片不替代完整 G1—G6。
- **体感智能**：默认呈现当前动作、可用成果、缺项和用户可执行操作。反馈节奏跟随事实；暂停、停止、来源排除、续做与重连具有明确范围、回执和失败路径。技术记录渐进展开，不能要求用户阅读协议日志才能判断任务是否成功。
- **前端接入**：xDAN-System3-Frontend 加载固定来源的自有 runtime 与共享 Client Module，开发模式和安装包分别验收；模式、材料、批准、控制与成果都来自原生接口，不迁入 v3 的内存演示状态机作为产品事实库。
- **模型供给**：自有 Jev 9B 与官方 Jev 经统一 SDK/provider 机制分别验收；生成使用配置的 proxy.fidoo.ai 路由。既有入口实网结果、独立 SDK smoke、服务健康与桌面真实调用是四类不同证据。
- **未来演进**：本机通用 9B/27B 用于常用任务、本地数据处理及提出专业 Agent 编排指令；与 Jev 9B 分工独立。先验证工具能力、资源和质量，再启用；不以本地模型未落地否定已有入口链路，也不提前承诺已支持。

## 明确的前端接入目标与文件范围

用户已再次明确前端仓库为 `/Users/gumpm5/Documents/Code/xDAN-System3-Frontend`。该仓库承担 System3 产品前端，不停留在 HTML 演示；已存在的 `chore-bootstrap` 工作区保留初始化交付，实际产品修改另建 feature worktree。当前记录和设计复核不自动视作产品代码实施批准。

- Harness 仓库：原生 SessionController、System3/Jev provider、Client-safe 事件与投影、接口及双 SDK。
- Frontend `src/main/index.ts`、`src/main/runtime/harness-runtime.ts`：自有 runtime 入口及启动/安全 profile 装配；保留唯一 dsh 启动路径。
- Frontend `build/dsh-desktop.patch.yml`：现有 Host 插件与桌面 Client Module 注册；配置来源和版本显式固定。
- Frontend `packages/dsh-desktop-client-ui/`：现有模块已依赖 Conversation/API 并使用原生 slots。优先评估在此扩展与共享模块拆分的必要性，复用 locale/theme，不先建第二套前端。
- 接入顺序：自有 runtime → 显式 Jev/System3 配置 → Client-safe 实际采用投影 → Conversation/侧栏 → 真实控制接口 → 安全恢复与安装包验收。

独立 `ops-jev9b-api` 工作区记录 2026-09-30 已完成 Jev 9B 公网 HTTPS 26 项验证，日常无需 SSH；本轮未重新探活，也未修改 endpoint、凭据或默认 effort。接入时复核新端点/密钥引用、SDK 请求和 high/low 实际配置；公网三问题样本与入口延迟分别评测，不能混用。

## 完成定义与首条纵向交付

建议第一条验收任务为隔离工作区的接口升级核对：真实材料与只读约束 → Jev 合法选模 → Fidoo 执行 → Skill 实际注入 → 阶段报告与变更/核验证据 → 用户干预与恢复 → 独立验收；在 G5 扩展为已安装代码专家接力。任务族为实施建议，尚未被用户单独确认。

- [ ] 双仓固定兼容组合，桌面开发启动与安装包实际加载自有 runtime，版本不匹配明确拒绝。
- [ ] 一个 UI 输入关联同一原生请求、采用、模型请求/结果与成果；双击、超时、取消和重连不重复执行。
- [ ] 入口实际调用 Jev 9B，Fidoo 使用被采用模型；固定模式跳过 Jev；失败只走合法基线。
- [ ] 至少一个过程节点的正文或结果进入真实后续请求，有原生日志、keyless snapshot 和规则对照。
- [ ] 原型中的主要操作逐项映射真实 API；没有实现的操作隐藏或明确标为不可用，不能虚构成功。
- [ ] 真实文件准入、运行中补充/排队、控制部分失败、流中断、日志缺档、重启恢复和专家生命周期有端到端用例。
- [ ] 屏幕阅读器、键盘、IME、明暗、缩放、桌面窗口、长对话/多任务与真实延迟下可用；消息更新不抢焦点或滚动位置。
- [ ] 目标用户能独立指出当前动作、实际材料/数据去向、可用成果、验收缺项与控制范围；失败或误解项必须闭环。
- [ ] 桌面/Web/API/双 SDK 对同一记录给出一致状态；真实任务质量、首次有效成果、总耗时和成本有基线对照。

完成度分为设计覆盖、交互定稿、产品实现、真实接入、用户验收五项分别报告；不填缺乏依据的百分比。当前复核及分工见 [交付目标与 UI/UX 完成度审查](../../docs/feat-system3-desktop/delivery-objectives-and-ux-audit.html)。

- [ ] 落码前收敛运行中补充/另起任务、逐对象材料批准、部分停止失败后的恢复三项生产交互，并以目标用户操作验证。
